1工具簡介

用瀏覽器把測試畫面推到整個螢幕上，一個像素對一個像素、不縮放。也可以自己編一個 4×4 的 sub-pixel 圖樣平鋪滿版，或把結果存成 PNG／BMP 給機台用。

它能做什麼

  • 測試畫面 — 內建一整套常用畫面（灰階條、Skip Dot、Line、Checker、Cross Talk、SMPTE…），選單結構與原程式一致。
  • 手動 4×4 — 自己指定 4 列 × 4 pixel × RGB 共 48 個 sub-pixel 的灰階，全畫面平鋪。
  • 遮罩 — 只露出畫面的某幾等份，其餘蓋掉（這是本站加的，原程式沒有）。
  • 另存圖片 — 指定解析度輸出 PNG／BMP，可選 8 或 10 bit，存完自動驗證像素是否完全一致。
  • 放大鏡 — 就地放大看 sub-pixel 排列與每一格的數值。

三個要先知道的事

  • 首頁的預覽不是 1:1——它是把 pattern 放大成 3×3 平鋪讓你看清楚結構。要看真實比例請進全畫面，或用輸出區的「1:1 實際像素」。
  • 開啟時的預設畫面是 Horizontal 256（左到右的白／紅／綠／藍灰階條），不是空白的手動模式。
  • 螢幕縮放會騙人——系統若不是 100% 縮放，CSS 像素與實際裝置像素不一致。第 11 章的螢幕資訊卡會直接告訴你目前的比例。

2快速開始

選一張測試畫面

按「▾ Test Pattern Menu」，從選單挑（例如 Skip 1 Dot ▸ 1V 1H）。上方預覽立刻更新。

調顏色與灰階

「畫面參數」卡的顏色鈕 1–8 與 Level 滑桿。這兩項就是原程式數字鍵與上下鍵在做的事。

推到整個螢幕

按「⛶ 進入全畫面顯示」。全畫面中一樣可以用鍵盤換畫面、調灰階；控制面板可切左右，按 F 或 Esc 離開。

看 sub-pixel 排列

任何有 pattern 的地方點右上角的 🔍，開放大鏡；方向鍵移動準星，可切 3×3 / 5×5 / 9×9 / 13×13。

需要檔案就另存

展開「輸出與另存」，填解析度（或按「用螢幕」）、選 PNG／BMP 與位元深度，按「💾 另存圖片」。存完會自動驗證輸出的像素與畫面完全一致。

5手動 4×4 編輯區

切到「🎛️ 手動 4×4」後使用。編輯的是一個 4 列 × 4 pixel 的重複單元，每個 pixel 有 R／G／B 三個 sub-pixel，總共 48 格；全畫面時這個單元會 1:1 平鋪滿整個螢幕。

操作方式

操作效果
點一個格子把目前的灰階值套用到該 sub-pixel。所以順序是：先設灰階，再點格子。
按住拖曳連續塗刷多格。
點 L1–L4 標題選取整列。
點 px1–px4 標題選取整個 pixel 欄。
點 R／G／B 標題選取該顏色的所有 sub-pixel。
選取亮組／暗組依目前的值自動分成兩組並選取其中一組——調整「亮的那些」時不必一格一格點。
亮暗反轉兩組的值互換。
全選／取消選取字面意思。
沒有選取任何格子時，灰階操作會套用到全部 48 格 優先序是：有選取 → 只作用於選取的格子；沒有選取但有亮組 → 作用於亮組；兩者都沒有 → 作用於全部 48 格。這是刻意的設計（要整片改灰階時不必先全選），但如果你以為只會改一格，結果整片變色，原因就在這裡。

灰階輸入區

控制項說明
數值＋滑桿0–255。這是「接下來要套用的值」。
L0 / L32 / L64 / L128 / L192 / L255常用值的快捷鈕。
−16 / −1 / +1 / +16微調。注意它是對每一個目標格各自加減，不是把所有格子設成同一個值——原本有高低差的格子會保持相對關係。
起始樣式（選單捷徑）一排等同選單的按鈕，按下去把該測試畫面的實際輸出載進編輯格。按完仍停在手動模式，可以繼續改。
捷徑的值來自實際輸出，不是另一份硬編的表 按捷徑等於「選那張測試畫面 → 反推它的 4×4 重複單元 → 填進編輯格」，所以不會出現「捷徑跟選單畫出來不一樣」的情況。

6全畫面顯示與鍵盤操作

真正要看畫面的地方。進入後 pattern 以 1:1 填滿整個螢幕。

控制面板

  • 面板可設定靠左或靠右（主頁的「全畫面時控制面板位置」，或面板上的「⇄ 切換面板左右」）。
  • 面板內有：測試畫面選單、切換左右、離開全畫面、鍵盤說明與目前畫面資訊。
  • 畫面左右邊緣是感應熱區，滑鼠移過去面板才出現，平常不擋畫面。
  • 在全畫面上按右鍵也會開測試畫面選單。

離開的三種方式

  • 按 F —— 明確的「離開全畫面」，會一併關掉放大鏡。
  • 按 Esc —— 逐層關閉：先關選單 → 再關放大鏡 → 再關 1:1 預覽 → 最後才離開全畫面。
  • 面板上的「✕ 離開全畫面」。

7放大鏡

用來確認「螢幕上這一格到底是哪個 sub-pixel、值是多少」。可以在首頁預覽、輸出預覽、全畫面三個地方開啟。

控制項說明
🔍 入口預覽區右上角的圓形徽章，或輸出區的「🔍 開啟放大鏡」按鈕。
範圍 3×3 / 5×5 / 9×9 / 13×13一次看幾個像素。3×3 只在下方資訊列顯示中心格的值；切到 5×5 以上每一格都會標上數值。
方向鍵移動準星。放大鏡開啟時，方向鍵歸放大鏡使用，不會動到 pattern 的灰階或變體（XY Coordinate 的準星也一樣暫停）。
工具列可用左邊的 ⠿ 把整條工具列拖到別的位置，避免擋住要看的區域。
關閉按 Esc、點工具列的 ✕、或再點一次進入時用的那個入口。

8遮罩（只露出指定等份）

把畫面切成 N 等份、只露出你勾的那幾份，其餘蓋掉。這是本站設計的功能，原程式沒有。卡片預設收合。

控制項型別範圍／預設說明
啟用遮罩核取方塊預設關閉關閉時整張卡沒有任何作用，標籤顯示「未啟用」。
水平等份數數值＋滑桿數值 1–64、滑桿 1–24，預設 6把畫面左右平分成幾份。
露出哪幾等份多選標籤—可複選，勾起來的才會顯示 pattern。
同時使用垂直等份核取方塊預設關閉開啟後多一組垂直的等份數與選擇。
組合方式單選鈕交集（預設）／聯集交集 ＝ 露出矩形（水平與垂直都被勾到的區域）；聯集 ＝ 露出十字（任一方向被勾到即露出）。
露出區外緣調整數值＋滑桿±200 px，預設 0正值外擴、負值內縮。作用在整段連續露出區的外緣，所以露出相鄰的兩份（例如 2、3）時中間不會出現接縫。
遮罩內容單選鈕單色（預設）／另一個畫面被蓋住的區域要填什麼。選「另一個畫面」可以做出「左半 Skip Dot、右半 Gray」這種對照畫面。
遮罩顏色／灰階下拉＋數值—單色模式下的填色。
把顏色與灰階也套到這張畫面核取方塊預設不勾選「另一個畫面」時才有。預設不套用，讓那張畫面維持它原本該有的樣子。
典型用法 量某一區的亮度或串擾時，只露出要量的那一份、其餘蓋成黑色，可以排除周邊亮度的干擾；或用「另一個畫面」做左右對照，一次拍一張照就能比較兩種 pattern。

9匯入圖片

有現成的測試圖檔時，直接丟進來用整個螢幕 1:1 顯示。卡片預設收合。

控制項說明
📂 選擇圖片檔PNG／BMP／JPG／GIF／WebP 等瀏覽器能解的格式都可以。
圖片資訊匯入後顯示尺寸等資訊，卡片標籤也會從「未匯入」變成已匯入狀態。
失真格式提醒匯入 JPG 這類有損壓縮的檔案時會出現警告——像素值已經被壓縮改過，不適合拿來做嚴謹的像素級驗證。
✕ 清除匯入的圖回到測試畫面。
匯入的圖不會被縮放 它以原始尺寸 1:1 顯示。圖比螢幕小就只佔一部分、比螢幕大就會超出——這是刻意的，任何縮放都會改變像素值，使測試失去意義。

把目前畫面存成圖檔。卡片預設收合。

解析度與預覽

控制項型別範圍／預設說明
輸出解析度數值 ×21–16384，預設 1920 × 1080以裝置像素為單位。
用螢幕按鈕—一鍵帶入目前螢幕推算出的裝置像素。
常用尺寸標籤鈕11 組，640×480 – 3840×2160滑鼠停留會顯示長寬比與百萬像素數。

⛶ 用整個螢幕 1:1 檢視按鈕—用整個螢幕以 1:1 檢視輸出結果（基準是真正的螢幕）。

格式與位元深度

控制項選項／預設說明
檔案格式PNG（預設）／BMP兩種都是無損、像素值完全相同。PNG 有壓縮、檔案小；BMP 不壓縮、體積大很多。對方的機台只吃 BMP 時才選 BMP。
色彩深度8 bit（預設）／10 bit10 bit 是給只吃 10-bit 圖的機台用的。畫面本身仍以 8 bit 產生，存檔時每個通道用 MSB replication 放大到 10 bit（0 → 0、255 → 1023，兩端精準）。它不會憑空生出 8 bit 做不到的階。
檔名可編輯，副檔名自動—

存檔、批次與驗證

控制項說明
💾 另存圖片依目前設定產生檔案並下載。
📤 分享圖片給其他 App只有在裝置支援檔案分享時才會出現（多半是手機）。分享與下載用的是同一份位元組，不會為了分享而重新編碼。使用者取消分享時不會強制退回下載。
一次匯出多個尺寸勾選多個尺寸後批次匯出。每個尺寸都以該解析度原生重畫並各自驗證，不是把同一張圖縮放成好幾份。
驗證結果存檔後自動把檔案重新解碼回來逐像素比對，顯示格式、像素總數、差異數與檔案大小。差異數必須是 0，且解碼出的寬高與設定相同，才算通過。
為什麼要自動驗證 測試畫面最怕的就是「存出來的檔跟看到的不一樣」——瀏覽器編碼、色彩管理、縮放都可能悄悄改掉像素值。這裡每存一次就實際解回來比一次，差異不是 0 就直接標紅，不必靠人肉眼檢查。

11螢幕資訊與縮放偵測

唯讀資訊，卡片預設收合。用來回答「我現在看到的到底是不是 1:1」。

欄位意義
CSS 邏輯解析度瀏覽器認知的螢幕尺寸。
devicePixelRatio每個 CSS 像素對應幾個實體像素。不是 1 就代表有縮放。
推算裝置像素CSS 解析度 × dPR，也就是真正的面板像素數。輸出區的「用螢幕」帶入的就是它。
視窗內部尺寸／可用區域目前視窗與扣掉系統列後的可用範圍。
色彩深度瀏覽器回報的色彩位元數。
螢幕方向橫向／直向。
多螢幕 (isExtended)是否有延伸螢幕。
🔎 取得每台螢幕詳細資訊需要授權，取得後可列出每一台螢幕各自的解析度與縮放。
dPR 不是 1 的時候，「全畫面 1:1」也不會是真的 1:1 瀏覽器畫的是 CSS 像素，系統再依縮放比放大到實體像素——這中間一定有內插，sub-pixel 圖樣就失真了。要做像素級測試，請先把系統顯示縮放設為 100%，或改用「另存圖片」輸出檔案給機台顯示。

12常見問題

點問題展開答案。

我只想改一格，結果整片都變了？▼

因為當下沒有選取任何格子。灰階操作的作用範圍是：有選取 → 只作用選取；沒有選取但有亮組 → 作用亮組；兩者都沒有 → 全部 48 格。要精準改一格，先點那一格（點格子本身就是套用），或先用標題列選取想要的那一組。

「以此為起點手動編輯」按鈕是灰的？▼

代表這張畫面不是 4×4 週期性圖樣——像灰階條、SMPTE、Cross Talk 這種整張畫面各處都不同的圖，沒有可以搬進 4×4 編輯格的重複單元。按鈕旁邊會直接寫出原因。

預覽看起來跟實際顯示不一樣？▼

首頁的預覽是放大後的 3×3 平鋪，目的是讓你看清楚圖樣結構，本來就不是 1:1。要看真實比例：進「⛶ 全畫面顯示」，或在輸出區切到「1:1 實際像素」／「用整個螢幕 1:1 檢視」。

全畫面時方向鍵沒作用？▼

兩個可能：放大鏡開著——此時方向鍵歸放大鏡移動準星使用，pattern 的方向鍵功能整個暫停，關掉放大鏡即可；或是焦點停在某個輸入框，點畫面空白處再試。另外不同類型的畫面，方向鍵的意義不同（見第 6 章對照表）。

選 10 bit 輸出，畫質會變好嗎？▼

不會。畫面本身仍是 8 bit 產生的，10 bit 只是存檔時把每個通道用 MSB replication 放大（0→0、255→1023），供只接受 10-bit 圖的機台使用。它不會憑空生出 8 bit 做不到的中間階。

存檔後的驗證顯示紅色，怎麼辦？▼

紅色代表重新解碼回來的像素與畫面不完全一致（差異數不是 0，或寬高不符）。這份檔案不適合拿去做像素級測試。可以先改用另一種格式（PNG ↔ BMP）再存一次；若仍失敗，請把顯示的訊息回報，那代表瀏覽器的編碼行為有問題。

手機上看不到「分享圖片」按鈕？▼

分享鈕只在瀏覽器確實支援檔案分享時才顯示，不支援就完全隱藏，避免按了才失敗。此時直接用「💾 另存圖片」下載即可，內容完全相同。
