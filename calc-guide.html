1工具簡介

一個 Port 上串了好幾顆 Source Driver 時，每顆離 TCON 的距離不同，資料到達時間也就不同。這個工具算兩件事：去示波器上要怎麼觸發才看得到每一顆，以及 TCON 端的 cof_cnt 分界值要填多少。

它解決什麼問題

  • 示波器 A Event B 設定 — 要看第 3 顆 Driver 的波形，B event 要數到第幾個 CLK？手算很容易錯一位，這裡一次列出每一顆。
  • UI cof_cnt 分界值 — 分時（分顆）驅動時，TCON 要知道在哪個 pixel 位置切換到下一顆。分界值填錯，畫面上會出現直向的分區色差。
  • Skew 檔位對照 — 粗調（cksk）與微調（fine）的檔位表，調 skew 時直接查。

使用前提

  • 這個工具有「開始計算」按鈕——與工具箱其他頁不同。原因是要先選 Driver 顆數、動態產生 X1…Xn 輸入欄，欄位齊全後才有得算。
  • 改任何輸入都會把結果收起來，提醒你重新按一次計算，避免看到舊結果誤以為是新的。
  • 「X1 最靠近 TCON」——編號方向弄反的話，整組 event 值會完全對不上。

2快速開始

填基本參數

用 Hres. 下拉帶入 Hactive，再確認 Driver bits、Driver pairs 與 Single／Dual Gate 三項與實際板子一致。

選 Driver 顆數

點「單 Port Driver 顆數」的數字鈕（1–8）。點下去才會出現 X1…Xn 的輸入欄，這也是為什麼這頁需要一顆計算按鈕。

填示波器 Event 數

用示波器量出 XSTB(TP) 正緣到 mLVDS RST 負緣之間的 CLK event 數，填進去。示意圖點一下可以放大看觸發定義。

填每顆 Driver 的 channel 數

X1 填好之後，其餘 Xn 會自動跟著同步（除非你手動改過某一顆）。每顆不同時就個別填，或按 Copy to All 統一覆蓋。

按「▶ 開始計算」

得到兩張表：左邊是每一顆的 B event 值（拿去示波器設），右邊是 cof_cnt 分界值（拿去 TCON 設）。TCON 型號可在右上角切 EM01／EM02。

結果消失了不是壞掉 只要動到任何輸入欄，結果區就會自動收起來——因為那些數字已經對應不到目前的輸入了。改完再按一次計算即可。

4示波器觸發設定

這一格是整個計算的「起算點」。→ 直接開啟工具的這張卡

要量的是什麼

欄位全名是「XSTB(TP) rising → mLVDS RST falling 之 CLK EVENT 數」，也就是：

A：XSTB(TP) 正緣
→
數 mLVDS CLK 邊緣
→
B：RST 負緣
  • 示波器觸發設成 A event B 模式
  • A ＝ XSTB(TP) 正緣
  • B ＝ mLVDS CLK 正負緣（雙邊緣都算，因為 mLVDS 是 DDR）

量到的數字填進去，後面每一顆 Driver 的 B event 值都是從這個數字往上加。

控制項

控制項型別範圍／預設說明
CLK EVENT 數數值輸入≥ 0 的整數，預設 510允許填 0。這個值只影響 B event 結果，不影響 cof_cnt 分界值。
觸發示意圖可點擊圖—點圖任一處會放大成全螢幕燈箱。
示意圖放大後可以操作 滑鼠滾輪縮放、按住拖曳平移；手機用雙指捏合縮放、單指拖曳、連點兩下還原。關閉方式：右上角 ×、點圖以外的暗色區域，或按 Esc。

5Xn Channel 輸入

每一顆 Driver 負責幾個 channel。欄位數量由「單 Port Driver 顆數」決定，選了幾顆就出現幾格。

控制項型別預設說明
X1 Channel數值輸入864X1 是最靠近 TCON 的那一顆，也是整串的起點。改 X1 時，還沒被你手動改過的 X2…Xn 會自動跟著變成同一個值。
Copy to All按鈕—把 X1 的值強制覆蓋到所有 Xn，包含你手動改過的那些，並解除它們的「已手動編輯」標記。X1 空白時會跳提示。
X2 … X8數值輸入864各顆的 channel 數。一旦手動改過某一格，它就不再跟著 X1 連動——這是刻意的，避免你細心調完又被 X1 洗掉。
大多數情況每顆都一樣 同一 Port 上的 Driver 通常是同型號、同 channel 數，所以直接填 X1 讓它同步就好。只有在最後一顆吃剩下的 channel 數不同（面板寬度除不盡）時，才需要單獨改那一格。

6結果一：示波器 A Event B 設定

拿去示波器上照設就能逐顆看到波形。→ 直接開啟工具的這張卡

公式

對象B event 值說明
X1（第一顆）floor( floor(X1 × bits ÷ pairs ÷ gate) ÷ 2 ) + Event 數先算出一顆 Driver 的資料所佔的 CLK 數，取一半（落在該顆資料的中間，比較好觸發），再加上你量到的起始 Event 數。
X2 … Xnfloor(Xn × bits ÷ pairs ÷ gate) + 前一顆的值逐顆累加。每往後一顆，就多等一整顆 Driver 的資料時間。

所有除法都是無條件捨去（floor），與硬體計數器的行為一致。

設定示波器時別忘了另外兩件事 表格下方的紅字提醒：A Trigger ＝ TP（正緣）、B Trigger ＝ mLVDS CLK（正負緣）。B 只設單一邊緣的話，數出來會差一倍。

7結果二：UI cof_cnt 分界值設定

拿去 TCON 暫存器設定的數字。→ 直接開啟工具的這張卡

分界值怎麼來的

第 i 個分界（i 從 1 數到 顆數−1）：

分界值 = floor( Hactive ÷ 2 ÷ 顆數 ÷ gate × i − 1 )

  • ÷ 顆數：把整行平均切給每一顆
  • ÷ 2：以 UI 為單位計數（一個 UI 對應兩個 pixel 位置）
  • ÷ gate：Dual Gate 時每組只處理一半
  • − 1：計數器從 0 起算

最後一列的 2047

最後一顆（Xn, End）以及超出顆數的列，分界值固定顯示 2047。這不是算出來的，而是「一直到底」的結束標記——告訴 TCON 這一段沒有下一個交界。

2047 不會被 EM02 除以二 它是 sentinel 而非公式結果，切到 EM02 時仍然是 2047。看到它保持不變是正確行為。

表格與控制項

控制項／欄位型別選項說明
TCON下拉EM01（預設）／EM02切換 TCON 型號。EM01 提供 cof1–cof3、EM02 提供 cof1–cof7，而且 EM02 的分界值 ＝ EM01 分界值 ÷ 2（無條件捨去）。切換是即時的，不必重按計算。
cof_cnt 項目下拉- 或 cof1…（依 TCON 型號）指定該列要用哪一個 cof 暫存器。可自行調整對應關係。
交界位置唯讀顯示—顯示這一列是哪兩顆之間的交界，例如 X1, X2；最後一列為 Xn, End；超出顆數的列顯示 -。
cof_cnt 分界值唯讀顯示—綠底高亮的數字，就是要填進暫存器的值。
改一個 cof 項目，後面會自動接續 把某一列改成 cof2 時，工具會自動把它後面的列依序排成 cof3、cof4…，並把其他列上重複的名稱清成 -。這樣就不會出現兩列都指到同一個暫存器的設定。若只是想清掉某列，選 - 即可，不會觸發連動。

表格列數取「Driver 顆數」與「該型號的 cof 數量」兩者較大者，所以 EM02 在顆數少時仍會列滿 7 列（多出來的列交界位置顯示 -、值為 2047）。

9常見問題

點問題展開答案。

按了計算沒反應，或畫面跳到某個欄位？▼

代表有欄位沒通過驗證。畫面會自動捲到第一個紅框欄位。Hactive 與 X1…Xn 必須是正整數，Event 數必須是 0 或正整數；另外沒有先點「單 Port Driver 顆數」也會被擋下並跳出提示。

改了輸入之後結果整塊不見了？▼

刻意的。輸入一改，先前算出來的數字就對不上了，留著只會害人抄錯。重按「▶ 開始計算」即可。例外：在結果區內操作（切 TCON 型號、改 cof 項目下拉）不會清除結果，因為那些是結果的呈現方式而非輸入條件。

切到 EM02，分界值全部變成一半？▼

正確。EM02 的分界值 ＝ EM01 的分界值 ÷ 2（無條件捨去），例如 15 → 7、32 → 16。切回 EM01 會回到原值，不會重複套用。唯一不變的是結束標記 2047。

算出來的 B event 值到示波器上對不到？▼

依可能性排查：

  1. B Trigger 沒設成正負緣——只算單邊緣會差一倍。
  2. Single／Dual Gate 選錯——同樣會整組差一倍。
  3. 起始 Event 數量錯——A 必須是 XSTB(TP) 的正緣，量到 RST 的負緣為止。
  4. X1 方向反了——X1 必須是最靠近 TCON 的那一顆。
  5. Driver bits／pairs 與實際板子不符。
改 X1 的時候，某幾格 Xn 沒有跟著變？▼

那幾格被你手動改過，工具就不再用 X1 覆蓋它們，避免辛苦調好的值被洗掉。要強制統一請按 Copy to All，它會連手動改過的一起覆蓋，並解除標記。重新點選顆數也會重置全部。

cof 項目下拉改一個，其他列自己跟著動？▼

這是順序連動：cof 暫存器必須依序對應到由近到遠的交界，所以指定某列為 cof2 之後，後面的列會自動排成 cof3、cof4…，同時把其他列上重複的名稱清成 -。選 - 則不會觸發連動。
