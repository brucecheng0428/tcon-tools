1工具简介

三件事合成一页：把 AUX 封包解成人看得懂的内容、查 DPCD 寄存器的定义与每个 bit 的意义、以及比对不同 eDP／DP 版本之间的差异。内置 289 个 DPCD 寄存器定义与 326 条版本标注，不必再翻规格书 PDF。

三个分页

  • AUX 解码 — 用菜单组出一笔 Request／Reply，解出它在做什么，并画出对应的 Manchester II 波形。
  • DPCD 查询 — 输入地址（可加上值），列出寄存器名称、读写属性、每个 bit 的意义与该值的解读。也能反过来用关键字搜索。
  • 版本差异 — 一张总表列出跨版本才新增／变更的寄存器与 bit。

两个好用的小地方

  • 分页会被记住 — 刷新后回到你上次看的那一页；也可以用网址参数直接打开，例如 aux.html?auxTab=dpcd（其他工具链接过来时就是这样指定的）。
  • 解码结果里的地址可以点 — Native 交易解出来的目标地址是链接，点一下直接跳到 DPCD 查询分页并带入该地址。

2快速开始

两个最常见的场景。

场景 A：手上有一笔 AUX 封包

选 Command

封包第一个 byte 的高 4 bits 就是 Command。9 是 DPCD 读、8 是 DPCD 写。

转出地址与长度

Address 用五个滚轮转；Length 菜单选的是字段值，实际 byte 数 ＝ Length ＋ 1。

（选填）填 Reply

有测到回复就选 Reply Status，Read 交易还可以填回传数据。

按「▶ 解码」

下方出现解码结果与波形。Native 交易的目标地址是链接，点一下就跳到 DPCD 查询。

场景 B：只想查某个 DPCD

切到「DPCD 查询」分页

不知道地址？直接用下面那张「反向搜索」卡输入关键字（例如 LANE_COUNT）。

转出地址

五个滚轮选 hex，停下约 1 秒会自动查询，不必按任何按钮。

填上测到的值

有值就填，结果会多出一栏「值」，把每个 bit 的数值直接翻成语义。

需要时再筛版本

上方选规格版本后，不存在于该版本的寄存器／bit 会被标示出来。

3AUX 解码：封包输入

不必自己拼 hex，用菜单组出来即可，右下方会即时显示组合后的封包。→ 直接打开工具的这张卡

AUX Request

控件类型选项／默认说明
Command下拉8 个选项，默认 9封包第一个 byte 的高 4 bits。详见下表。
Address滚轮20-bit，5 位 hex五个滚轮各代表一位 hex，用转的（鼠标滚轮或手指滑动）而不是打字，避免打错位数。
Length下拉数据长度字段🔴 实际 byte 数 ＝ Length ＋ 1。这是 AUX 规范的定义：字段填 0 代表 1 个 byte。解读别人的封包时最容易在这里差一。
Datahex 输入格每格 1 byte只有 Write 类指令才会出现，格数随 Length 自动增减。
组合封包预览只读显示—上面任何一项改动都会即时更新，可直接拿去和测到的 raw bytes 比对。

Command 八个选项

值名称说明
9DPCD 读取（Native Read）最常见。读面板的 DPCD 寄存器。
8DPCD 写入（Native Write）写 DPCD。解码结果会附上「哪个地址被写入什么值」的对照表。
1 / 5I2C Read（MOT=0 / MOT=1）透过 AUX 走 I2C，最典型的用途是读 EDID。
0 / 4I2C Write（MOT=0 / MOT=1）同上，方向相反。
2 / 6I2C Write Status（MOT=0 / MOT=1）查询前一笔 I2C 写入的状态。
MOT 是什么 Middle-of-Transaction。MOT=1 代表这笔之后还有后续（I2C 不送 STOP，继续同一个交易），MOT=0 代表这是最后一笔。读 EDID 时会看到一连串 MOT=1，最后一笔才是 MOT=0。

AUX Reply（选填）

控件类型选项说明
Reply Status下拉不填／AUX ACK／AUX NACK／AUX DEFER／I2C NACK／I2C DEFER／自定义输入选「自定义输入」可以直接填任意 hex byte（测到怪值时用），旁边的「↩ 列表」按钮可切回下拉。
Reply Datahex 输入格每格 1 byte只有 Read 类指令才会出现，用来填回传的数据。
Reply 封包预览只读显示—即时组合。
DEFER 不等于失败 DEFER 是「现在还不能回答，请稍后重试」，Source 应该重送。看到零星 DEFER 属正常；连续大量 DEFER 才代表面板端有问题。NACK 则是明确拒绝。

4Preamble 设定与规范检查

Preamble 是每一笔 AUX 交易开头的同步信号。数量不足，对方可能同步不上；这一区让你把测到的数量填进去，立刻知道合不合规。

两个输入

控件类型范围／默认说明
系统 Preamble滑块＋数值0–64，默认 32由信号源（Source）送出的 Preamble 总数。
TCON Reply滑块＋数值0–64，默认 32由面板端（Sink）回复时送出的 Preamble 总数。

两者各自即时检查，结果直接显示在该滑块下方。波形也会同步重画。

规范范围与三种提示

规范合规范围
DP / eDP 1.2 ~ 1.326 – 32
eDP 1.4 以上18 – 24
显示意义
✅ 绿色落在该规范范围内。
🚨 红色低于最小值——这是真的有风险，对方可能来不及同步。
ℹ️ 灰色超出建议最大值，但功能上仍兼容，只是比规范建议的多。
两组规范会同时显示，因为它们有冲突区间 默认值 32 刚好合 DP/eDP 1.2~1.3、却超出 eDP 1.4+ 的建议上限；反过来 20 合 eDP 1.4+、却不足 1.2~1.3。要看的是「你这块面板宣告的版本」那一行，不是两行都要绿。

元素说明
编码规则bit 1 ＝ 中点 H→L 跳变、bit 0 ＝ 中点 L→H 跳变，1 bit ＝ 1 μs。Start／Stop 是 HHLL 这种不含中点跳变的特殊样式，所以在波形上一眼就能认出来。
段落颜色Pre-charge（深紫）、SYNC（紫）、Start／Stop（蓝）、Command（橙）、Address（绿）、Length（黄）、Data（青）、Idle（灰）。
H-Zoom −／+／Fit水平缩放与还原，倍率显示在中间。
全屏放大查看，有独立的缩放与 Overview。
Overview整笔交易的缩略图，点一下跳到该位置。
Preamble 警告横幅当 Preamble 数量不合规时，会在波形上方出现一条警告，说明是哪一组规范不符。
异常值标示数据段中出现不合常理的 DPCD 值时会被标记出来，提醒你这一笔值得怀疑。

查询结果包含什么

区块内容
标题栏寄存器名称 ＋ 读写属性徽章（RO／RW／W1C）＋ 版本徽章。
版本不兼容提示选了特定版本、而该寄存器需要更新的版本时，会出现橙色警告：「在你选的版本中可能不存在或为 RESERVED」。

值合法性警告你填的值不在该寄存器的合法值清单里时，会列出所有合法值供对照。

7DPCD 版本差异总览

一张表看完「哪些功能是哪个版本才开始有的」。→ 直接打开工具的这张卡

表格内容

  • 共 14 个功能分区（Receiver Capability、DSC、PSR、FEC…）、108 条差异。
  • 每一行是：地址｜bit 或值｜名称｜起始版本徽章。
  • 徽章颜色依版本区分，eDP 1.4+ 代表「1.4 版开始才有」。
  • 此分页在第一次点开时才产生表格，所以初次切换会有极短暂的延迟。

数据来源版本顺序

依规格发布时间排列：

DP v1.2 → eDP v1.2 → eDP v1.3 → eDP v1.4 → DP v1.3 → eDP v1.4a → eDP v1.4b → DP v1.4a → DP v2.0 → eDP v1.5

eDP 与 DP 的版本号不能直接比大小 两条规格线是交错发布的：eDP 1.4 早于 DP 1.3、DP 1.4a 早于 eDP 1.5。判断「这个功能该不该有」时，要看的是面板宣告的那一条规格线，不是版本数字谁大。

8常见问题

点问题展开答案。

Length 到底要填几？▼

填的是「实际 byte 数 − 1」。要读 1 个 byte 就填 0、要读 16 个就填 15。这是 AUX 规范的定义，工具的字段提示也写了同一件事。解码结果那边显示的则是换算后的实际 byte 数，两边差 1 是正常的。

查了某个地址说「找不到」？▼

数据库收录 289 个常用寄存器，不是完整的地址空间——RESERVED 区段与极少用到的地址不在其中。先确认位数（要 5 位 hex，例如 00101 而不是 101），再用反向搜索确认名称是否正确。真的没有就代表这个地址目前不在收录范围。

Preamble 两行提示互相矛盾，到底合不合格？▼

工具是同时对两组规范检查：DP／eDP 1.2~1.3 要 26–32，eDP 1.4 以上要 18–24，两者本来就不重叠。请看你的面板宣告的版本那一行。另外注意：红色（低于最小值）才是真的有风险，灰色只是超出建议上限，功能仍兼容。

解码结果的地址点不动？▼

只有 Native（DPCD）交易的地址才是链接，因为只有它对应到 DPCD 地址空间。I2C 交易的地址是 I2C 设备地址，工具会改为比对常见设备（例如 EDID），不会跳转。

Reply 一定要填吗？▼

不用。Reply 区是选填，只想确认 Request 的内容时把它留在「不填」即可。填了才会多出回复的解读，以及波形中的回复段落。

刷新之后怎么回到我刚刚看的分页？▼

它已经帮你记住了——分页状态存在浏览器的会话里，刷新后自动回到原分页。要指定打开哪一页也可以直接用网址：aux.html?auxTab=dpcd、?auxTab=verdiff、?auxTab=decode。
