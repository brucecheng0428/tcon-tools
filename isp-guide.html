1工具簡介

把 iSP 介面上「應該長什麼樣」的差動波形畫出來，讓你拿示波器上量到的畫面直接比對。也可以反過來：把量到的 9 個 bit 敲進去，反推它是哪一個控制碼或哪一階灰階。

它在做什麼

  • 正推 — 設定模式與像素值，產生一整條 line 的位元序列：BK、BAC、POL、資料、EOL，一段一段標上顏色與名稱。
  • 反推 — 輸入 9-bit 波形，比對出 Command、DLL Data、PLL Data 三種可能的解釋。
  • 所有編碼都是 8B9B：8 個 bit 的資料編成 9 個 bit 送出，DLL 與 PLL 兩張對照表各一份。

先弄清楚三件事

  • 位元順序是 LSB-first：波形最左邊是 b0，最右邊是 b8。看規格書上的十六進位值時要記得反過來對。
  • DLL 與 PLL 只差在 BK：控制碼裡只有 BK 兩種編碼不同，其餘 BAC／POL／SET／EOL 完全相同；資料則是兩張完全不同的 LUT。
  • 沒有計算按鈕：任何設定一改，波形立刻重畫。

2快速開始

對齊模式

先把「模式設定」四項調成與實際 IC 一致：Source Driver Bits、Pair 數、Data Zone 編碼、BK Zone 編碼。編碼選錯，畫出來的位元序列會整條不同。

設定要送的像素

用「純色畫面」最單純：R/G/B 各給一個灰階，Pixel 數量先設 2–4，波形短一點好對照。

看波形與 Frame 資訊

波形上方會列出整條 line 的段落順序（BK BAC POL+ R1 G1 B1 … EOL）與總 bit 數。每一段都有顏色與名稱標示。

放大比對

用 H-Zoom 的 +／− 放大到看得見單一 bit，或按全螢幕。下方 Overview 點一下可跳到該位置。

反過來查

示波器上量到一段不認識的 9-bit？捲到最下方的「波形反推」，用搜尋框輸入名稱、或直接勾 b0–b8，三行結果立刻告訴你它是什麼。

3模式設定

六項設定決定「同樣的像素值會被編成什麼位元」。→ 直接開啟工具的這張卡

控制項型別選項／預設說明
Source Driver Bits單選鈕6 / 8（預設）bits決定資料段怎麼組。8-bit：每個 pixel 直接送 R、G、B 三個 byte。6-bit：每個 pixel 是 18 bits（R/G/B 各 6），串起來後每 8 bits 重新切成一個 byte 再編碼，所以段落標籤會出現 R1+G1 這種跨欄位的名稱。
Pair 數單選鈕1 pair（預設）/ 2 pair2 pair 時畫面會出現上下兩條波形（Pair 0／Pair 1），像素資料依 3 個 slot 為一循環分配到兩條上（見第 4 章的說明）。
Data Zone 編碼單選鈕DLL-based（預設）/ PLL-based資料段用哪一張 8B9B 對照表。兩張表是完全不同的映射，同一個灰階編出來的 9-bit 不一樣。
BK Zone 編碼單選鈕DLL-based（預設）/ PLL-based只影響 BK 這一個控制碼。PLL 版的 BK 是類似時脈的交替樣式（供 PLL 鎖相用），DLL 版則是另一種固定樣式。其餘控制碼兩者相同。
Scrambler單選鈕Off（預設）/ On開啟後資料在編碼前先與 LFSR 產生的 key 做 XOR（打散連續相同值，降低 EMI）。開啟時波形上的資料段會標記為已加擾。
初始 Key文字輸入16-bit 十六進位，預設 FFFF只有 Scrambler 選 On 時才出現。要和 IC 端的初始值一致，波形才對得起來。
BKPOL單選鈕ON（預設）/ OFF開啟後在 frame 末端加入 VBK 段：BK · BAC · BKPOL± · BK。這一段接在 EOL 之後、本身不帶 EOL。點波形上的 BKPOL 色塊可直接切換正／負。
Scrambler 的運作方式 16-bit LFSR（Galois form，多項式 x¹⁶+x⁵+x⁴+x³+1），每送完一個 pixel 推進一次；每個 byte 的第 i 個 bit 與 key 的對應 bit 做 XOR 之後才進 8B9B 編碼。所以 Scrambler 開與關，同一個灰階畫出來的波形完全不同——比對不上時先確認這一項。

控制碼一覽（9-bit，LSB-first）

下表的位元由左至右就是波形上由左至右的順序。

控制碼b0…b8用途
BK（DLL）1 0 0 0 0 1 1 1 1Blanking 填充碼，DLL 版本。
BK（PLL）0 0 1 0 1 0 1 0 1Blanking 填充碼，PLL 版本，樣式像時脈，方便 PLL 鎖相。
BAC0 1 1 1 1 0 0 0 0命令起始碼，後面接的才是真正的命令。
POL+0 1 1 0 0 1 1 1 1本行極性為正。
POL−1 0 0 1 1 0 0 0 0本行極性為負。
SET1 0 0 0 0 0 0 1 1Setting line 的識別碼，其後接 REG 資料。
EOL0 1 1 1 1 1 1 0 0一條 line 的結束。
BKPOL+0 1 1 1 0 1 1 1 1VBK 段的極性命令（正）。
BKPOL−1 0 0 0 1 0 0 0 0VBK 段的極性命令（負）。
正負碼互為反相 POL+ 與 POL−、BKPOL+ 與 BKPOL− 每個 bit 剛好相反。在示波器上分辨極性時，看第一個 bit 最快：0 開頭是正、1 開頭是負。

4像素設定

要送出去的畫面內容。→ 直接開啟工具的這張卡

三種像素模式

模式控制項範圍／預設用途
純色畫面R / G / B Gray Level（滑桿＋數值＋色塊）各 0–255；預設 R255 G128 B0預設模式。每個 pixel 都送同一組 RGB。要驗證某一個特定灰階的編碼時用這個最直接。
遞增起始灰階 / Step / 重複 sub-pixel 數起始 0–255（預設 0）；Step 1–255（滑桿到 64，預設 4）；重複 1–255（滑桿到 48，預設 3）灰階逐漸變大，達 255 後保持不變。用來一次看多個灰階的編碼差異，或做漸層測試圖。
遞減同上起始預設 255；其餘同上灰階逐漸變小，達 0 後保持不變。
Pixel 數量滑桿＋數值1–255，預設 4三種模式共用。數量越多波形越長，比對細節時建議先調小。
「重複 sub-pixel 數」是什麼 它決定連續幾個 sub-pixel 用同一個灰階之後才變化一次。設 3 時剛好是 R＝G＝B，也就是每個 pixel 換一次灰階（灰階漸層）；設 1 則是每個 sub-pixel 都不同（彩色漸層）。

2 pair 時資料怎麼分配

兩條 pair 各自是完整的一條 line（都有自己的 BK／BAC／POL／EOL），只有資料段被拆開。以每 2 個 pixel 為一個循環、共 3 個 slot：

SlotPair 0Pair 1
第 1 個R（第 1 個 pixel）G（第 1 個 pixel）
第 2 個B（第 1 個 pixel）R（第 2 個 pixel）
第 3 個G（第 2 個 pixel）B（第 2 個 pixel）

所以 Pair 1 不是「後半段像素」，而是與 Pair 0 交錯的 sub-pixel。量測時把兩條並排看才是完整資料。

控制項

控制項型別範圍／預設說明

↓

結果怎麼讀

欄位內容說明
9-bit 值例如 0x10F (100001111)括號內是 LSB-first 的顯示，與波形由左至右一致；括號外的十六進位則是一般的數值表示。
Command命中的控制碼名稱同時比對所有控制碼與 PLL 版的 BK。命中多個會用 / 並列。沒有命中顯示 —。
DLL Data例如 L128 (0x80)用 DLL 表反查，得到的是灰階值。
PLL Data例如 L64 (0x40)用 PLL 表反查。
三行同時有值是正常的 同一組 9-bit 可能既符合某個控制碼、又落在某張資料表裡。要判斷它到底是什麼，得看它在波形中的位置：BAC 後面的是命令，POL 之後到 EOL 之間的是資料。工具只負責告訴你「有哪些可能」。
為什麼標「8-bit」 反推是以 byte ↔ 9-bit 的映射為基礎，而這個映射與 6-bit／8-bit 模式無關（6-bit 的差別只在上游怎麼打包成 byte）。所以在 6-bit 模式下這個工具一樣能用，只是查出來的 Lx 是打包後的 byte 值而非某個顏色的灰階。

9常見問題

點問題展開答案。

畫出來的波形跟示波器上量到的對不起來？▼

依可能性排查：

  1. Data Zone 編碼選錯（DLL ↔ PLL）——資料段會整段不同，這是最常見的原因。
  2. Scrambler 狀態不符，或初始 Key 與 IC 端不一致。
  3. BK Zone 編碼選錯——只有 BK 段會不同，其餘正確。看到「只有 blanking 對不上」就是這一項。
  4. 位元順序看反了——本工具與示波器都是 LSB-first（b0 在最左），規格書上的十六進位要反過來對。
  5. Source Driver Bits 或 Pair 數與實際不符。
6-bit 模式下段落名稱怎麼變成 R1+G1 這種？▼

因為 6-bit 的資料不是以顏色為單位打包的。每個 pixel 是 18 bits（R/G/B 各 6），串接之後每 8 bits 切一個 byte 再做 8B9B——切點自然會落在顏色中間。所以一個 byte 可能同時裝著 R1 的後半與 G1 的前半，標籤就寫成 R1+G1。這是正確的封裝方式，不是顯示錯誤。

2 pair 模式下，Pair 1 的資料為什麼不是後半段？▼

iSP 的 2 pair 是交錯而非切半。以 2 個 pixel 為一循環：Pair 0 送 R1、B1、G2，Pair 1 送 G1、R2、B2。兩條要並排一起看才是完整畫面。詳見第 4 章的對照表。

波形太長看不清楚單一 bit？▼

三個做法：把 Pixel 數量調小（2–4 個就夠看編碼）、用 H-Zoom + 逐步放大（每次 1.4 倍，最大 12×），或按全螢幕再放大。要回到全貌按 Fit，要跳到特定位置點下方的 Overview。

REG 值填了，但波形上看不到我填的數字？▼

REG 資料一樣要經過 8B9B 編碼，波形上是編碼後的 9-bit，不是原本的 byte。要確認編出來對不對，把該段的 9 個 bit 敲進「波形反推」，看 DLL／PLL Data 是不是你填的值。

怎麼切換 POL 的正負？▼

不用去設定卡片找——直接點波形上的 POL 色塊就會正負互換，BKPOL 色塊同理，兩者各自獨立。切換後 Frame 資訊列與整段位元序列會立刻更新。
