1工具简介

一个 Port 上串了好几颗 Source Driver 时，每颗离 TCON 的距离不同，数据到达时间也就不同。这个工具算两件事：去示波器上要怎么触发才看得到每一颗，以及 TCON 端的 cof_cnt 分界值要填多少。

它解决什么问题

  • 示波器 A Event B 设定 — 要看第 3 颗 Driver 的波形，B event 要数到第几个 CLK？手算很容易错一位，这里一次列出每一颗。
  • UI cof_cnt 分界值 — 分时（分颗）驱动时，TCON 要知道在哪个 pixel 位置切换到下一颗。分界值填错，屏幕上会出现竖向的分区色差。
  • Skew 档位对照 — 粗调（cksk）与微调（fine）的档位表，调 skew 时直接查。

使用前提

  • 这个工具有「开始计算」按钮——与工具箱其他页不同。原因是要先选 Driver 颗数、动态产生 X1…Xn 输入框，字段齐全后才有得算。
  • 改任何输入都会把结果收起来，提醒你重新按一次计算，避免看到旧结果误以为是新的。
  • 「X1 最靠近 TCON」——编号方向弄反的话，整组 event 值会完全对不上。

2快速开始

填基本参数

用 Hres. 下拉带入 Hactive，再确认 Driver bits、Driver pairs 与 Single／Dual Gate 三项与实际板子一致。

选 Driver 颗数

点「单 Port Driver 颗数」的数字钮（1–8）。点下去才会出现 X1…Xn 的输入框，这也是为什么这页需要一颗计算按钮。

填示波器 Event 数

用示波器量出 XSTB(TP) 正缘到 mLVDS RST 负缘之间的 CLK event 数，填进去。示意图点一下可以放大看触发定义。

填每颗 Driver 的 channel 数

X1 填好之后，其余 Xn 会自动跟着同步（除非你手动改过某一颗）。每颗不同时就个别填，或按 Copy to All 统一覆盖。

按「▶ 开始计算」

得到两张表：左边是每一颗的 B event 值（拿去示波器设），右边是 cof_cnt 分界值（拿去 TCON 设）。TCON 型号可在右上角切 EM01／EM02。

结果消失了不是坏掉 只要动到任何输入框，结果区就会自动收起来——因为那些数字已经对应不到目前的输入了。改完再按一次计算即可。

4示波器触发设定

这一格是整个计算的「起算点」。→ 直接打开工具的这张卡

要量的是什么

字段全名是「XSTB(TP) rising → mLVDS RST falling 之 CLK EVENT 数」，也就是：

A：XSTB(TP) 正缘
→
数 mLVDS CLK 边缘
→
B：RST 负缘
  • 示波器触发设成 A event B 模式
  • A ＝ XSTB(TP) 正缘
  • B ＝ mLVDS CLK 正负缘（双边缘都算，因为 mLVDS 是 DDR）

量到的数字填进去，后面每一颗 Driver 的 B event 值都是从这个数字往上加。

控件

控件类型范围／默认说明
CLK EVENT 数数值输入≥ 0 的整数，默认 510允许填 0。这个值只影响 B event 结果，不影响 cof_cnt 分界值。
触发示意图可点击图—点图任一处会放大成全屏灯箱。
示意图放大后可以操作 鼠标滚轮缩放、按住拖动平移；手机用双指捏合缩放、单指拖动、连点两下还原。关闭方式：右上角 ×、点图以外的暗色区域，或按 Esc。

5Xn Channel 输入

每一颗 Driver 负责几个 channel。输入框数量由「单 Port Driver 颗数」决定，选了几颗就出现几格。

控件类型默认说明
X1 Channel数值输入864X1 是最靠近 TCON 的那一颗，也是整串的起点。改 X1 时，还没被你手动改过的 X2…Xn 会自动跟着变成同一个值。
Copy to All按钮—把 X1 的值强制覆盖到所有 Xn，包含你手动改过的那些，并解除它们的「已手动编辑」标记。X1 空白时会弹出提示。
X2 … X8数值输入864各颗的 channel 数。一旦手动改过某一格，它就不再跟着 X1 联动——这是刻意的，避免你细心调完又被 X1 洗掉。
大多数情况每颗都一样 同一 Port 上的 Driver 通常是同型号、同 channel 数，所以直接填 X1 让它同步就好。只有在最后一颗吃剩下的 channel 数不同（面板宽度除不尽）时，才需要单独改那一格。

6结果一：示波器 A Event B 设定

拿去示波器上照设就能逐颗看到波形。→ 直接打开工具的这张卡

公式

对象B event 值说明
X1（第一颗）floor( floor(X1 × bits ÷ pairs ÷ gate) ÷ 2 ) + Event 数先算出一颗 Driver 的数据所占的 CLK 数，取一半（落在该颗数据的中间，比较好触发），再加上你量到的起始 Event 数。
X2 … Xnfloor(Xn × bits ÷ pairs ÷ gate) + 前一颗的值逐颗累加。每往后一颗，就多等一整颗 Driver 的数据时间。

所有除法都是向下取整（floor），与硬件计数器的行为一致。

设定示波器时别忘了另外两件事 表格下方的红字提醒：A Trigger ＝ TP（正缘）、B Trigger ＝ mLVDS CLK（正负缘）。B 只设单一边缘的话，数出来会差一倍。

7结果二：UI cof_cnt 分界值设定

拿去 TCON 寄存器设定的数字。→ 直接打开工具的这张卡

分界值怎么来的

第 i 个分界（i 从 1 数到 颗数−1）：

分界值 = floor( Hactive ÷ 2 ÷ 颗数 ÷ gate × i − 1 )

  • ÷ 颗数：把整行平均切给每一颗
  • ÷ 2：以 UI 为单位计数（一个 UI 对应两个 pixel 位置）
  • ÷ gate：Dual Gate 时每组只处理一半
  • − 1：计数器从 0 起算

最后一行的 2047

最后一颗（Xn, End）以及超出颗数的行，分界值固定显示 2047。这不是算出来的，而是「一直到底」的结束标记——告诉 TCON 这一段没有下一个交界。

2047 不会被 EM02 除以二 它是 sentinel 而非公式结果，切到 EM02 时仍然是 2047。看到它保持不变是正确行为。

表格与控件

控件／字段类型选项说明
TCON下拉EM01（默认）／EM02切换 TCON 型号。EM01 提供 cof1–cof3、EM02 提供 cof1–cof7，而且 EM02 的分界值 ＝ EM01 分界值 ÷ 2（向下取整）。切换是即时的，不必重按计算。
cof_cnt 项目下拉- 或 cof1…（依 TCON 型号）指定该行要用哪一个 cof 寄存器。可自行调整对应关系。
交界位置只读显示—显示这一行是哪两颗之间的交界，例如 X1, X2；最后一行为 Xn, End；超出颗数的行显示 -。
cof_cnt 分界值只读显示—绿底高亮的数字，就是要填进寄存器的值。
改一个 cof 项目，后面会自动接续 把某一行改成 cof2 时，工具会自动把它后面的行依序排成 cof3、cof4…，并把其他行上重复的名称清成 -。这样就不会出现两行都指到同一个寄存器的设定。若只是想清掉某行，选 - 即可，不会触发联动。

表格行数取「Driver 颗数」与「该型号的 cof 数量」两者较大者，所以 EM02 在颗数少时仍会列满 7 行（多出来的行交界位置显示 -、值为 2047）。

9常见问题

点问题展开答案。

按了计算没反应，或画面跳到某个字段？▼

代表有字段没通过验证。画面会自动滚到第一个红框字段。Hactive 与 X1…Xn 必须是正整数，Event 数必须是 0 或正整数；另外没有先点「单 Port Driver 颗数」也会被挡下并弹出提示。

改了输入之后结果整块不见了？▼

刻意的。输入一改，先前算出来的数字就对不上了，留着只会害人抄错。重按「▶ 开始计算」即可。例外：在结果区内操作（切 TCON 型号、改 cof 项目下拉）不会清除结果，因为那些是结果的呈现方式而非输入条件。

切到 EM02，分界值全部变成一半？▼

正确。EM02 的分界值 ＝ EM01 的分界值 ÷ 2（向下取整），例如 15 → 7、32 → 16。切回 EM01 会回到原值，不会重复套用。唯一不变的是结束标记 2047。

算出来的 B event 值到示波器上对不到？▼

依可能性排查：

  1. B Trigger 没设成正负缘——只算单边缘会差一倍。
  2. Single／Dual Gate 选错——同样会整组差一倍。
  3. 起始 Event 数量错——A 必须是 XSTB(TP) 的正缘，量到 RST 的负缘为止。
  4. X1 方向反了——X1 必须是最靠近 TCON 的那一颗。
  5. Driver bits／pairs 与实际板子不符。
改 X1 的时候，某几格 Xn 没有跟着变？▼

那几格被你手动改过，工具就不再用 X1 覆盖它们，避免辛苦调好的值被洗掉。要强制统一请按 Copy to All，它会连手动改过的一起覆盖，并解除标记。重新点选颗数也会重置全部。

cof 项目下拉改一个，其他行自己跟着动？▼

这是顺序联动：cof 寄存器必须依序对应到由近到远的交界，所以指定某行为 cof2 之后，后面的行会自动排成 cof3、cof4…，同时把其他行上重复的名称清成 -。选 - 则不会触发联动。
