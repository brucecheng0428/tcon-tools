1工具簡介

一塊面板的時序規格丟過來，要立刻回答「這樣的解析度與更新率，介面跑得動嗎？」。這個工具把四種介面的頻率換算集中在同一頁，四張卡片共用同一組 Frame 參數，改一個數字四邊同時更新。

它在算什麼

  • TCON Rx（輸入端） — LVDS Rx 的各級時脈頻率、P2P（eDP）的每 Lane Bit Rate
  • TCON Tx（輸出端） — mLVDS 的 Tx 頻率、P2P（iSP／PHI）的 Tx Rate
  • 另外一併給出 1 UI（單一位元的時間長度）與 1/16 UI，這是評估 skew 預算與量測解析度時最常要的數字
  • eDP 還會直接告訴你至少要哪一檔 Link Rate（RBR／HBR／HBR2／HBR3）

三個使用前提

  • 沒有「計算」按鈕 — 每個欄位都是即時計算，打字的當下四張卡就全部重算。
  • 四張卡片共用 Frame 參數 — 最上面那張卡的 Hactive／Hblank／Vactive／Vblank 是所有公式的共同基礎。
  • Frame Rate 是雙向連動的 — LVDS Rx 與 P2P Rx 的 Frame Rate 會互相同步，Tx 兩張卡直接沿用同一個值。詳見第 9 章。
結果僅供估算 這裡算的是理論頻率，不含 PHY 的實際餘裕、板端損耗與 IC 規格上限。要判斷「這顆 IC 撐不撐得住」，仍以正式規格書為準；本工具的用途是快速比較不同配置與抓出量級錯誤。

為什麼 Blank 不能亂填

所有頻率都建立在 Htotal × Vtotal × Frame Rate 之上，而 Htotal／Vtotal 含 blank。只填 active 不填 blank，算出來的頻率會低估約 8–15%——那是實際跑不動卻以為有餘裕的典型來源。面板規格書上的 blank 值請照抄，不要憑印象。

Blank 也不是越大越安全 Blank 加大會同步推高 Pixel Rate 與所有下游頻率。做規格取捨時，這裡每加 100 個 pixel，四張卡的結果都會跟著漲。

控制項

控制項型別選項／預設說明
TCON Rx Port單選鈕1 / 2 / 4（預設）/ 8LVDS 輸入的 Port 數。Port 越多，每個 Port 分到的頻率越低——這正是高解析度面板要多 Port 的原因。
計算模式單選鈕給定 FPGA DCLK（預設）／給定 LVDS CLK／給定 TCON DCLK／給定 Frame Rate選哪個，下面就出現哪個輸入框，其餘三個由公式反推。手上有哪個數字就選哪個，不需要自己換算。
FPGA UI DCLK [MHz]數值輸入預設 210模式「給定 FPGA DCLK」時出現。此模式下 LVDS per Port = FPGA UI DCLK。
LVDS PER PORT [MHz]數值輸入預設 210模式「給定 LVDS CLK」時出現。量測儀器上直接讀到的就是這個值。
TCON UI DCLK [MHz]數值輸入預設 420模式「給定 TCON DCLK」時出現。FPGA UI DCLK = TCON UI DCLK ÷ 2。
Frame Rate [Hz]數值輸入預設 144模式「給定 Frame Rate」時出現。規格書上寫的更新率就填這裡。
切換模式不會遺失數字 算完之後，工具會把其他三個模式的輸入框也回填成算出來的值。所以你可以先用 Frame Rate 算，再切到 TCON DCLK 模式微調，數字是接得起來的。

輸出結果與公式

結果公式意義
Frame RatePixel Rate × 10⁶ ÷ (Htotal × Vtotal)實際更新率。反推模式下才是計算結果。
Pixel RateHtotal × Vtotal × Frame Rate ÷ 10⁶，或 FPGA DCLK × Port每秒送出的像素數（MHz），全頁最核心的中間量。
FPGA UI DCLKPixel Rate ÷ Port訊號源端每個 Port 的像素時脈。
TCON UI DCLKFPGA UI DCLK × 2TCON 內部像素時脈，固定為前者的兩倍。
LVDS per Port= FPGA UI DCLK每個 LVDS Port 的時脈頻率，量測時對得上的就是這個。
1 UI [ps]10⁶ ÷ (7 × LVDS per Port)單一位元的時間長度。係數 7 來自 LVDS 的 7:1 序列化：一個時脈週期內送 7 個 bit。
1 UI 拿來做什麼 它是 skew／jitter 預算的分母。例如 1 UI ＝ 680 ps 時，板端 100 ps 的走線差就吃掉了約 15% 的眼圖寬度。解析度往上拉時 1 UI 會快速變小，這也是為什麼同樣的板子在高更新率下才開始出問題。

5DCLK 頻率加乘（最大值估算）

位於 LVDS Rx 卡最下方。用途是回答「把所有會讓頻率變快的因素都算進去，最壞情況是多少」——設計餘裕要看的是這個數字，不是標稱值。

三個勾選項

項目型別百分比選項／預設什麼情況要勾
RX SSC 展頻核取＋下拉±0.5 / 1.0 / 1.5 / 2.0 / 2.5 / 3.0%，預設 ±3.0%訊號源端開了展頻（SSC）。展頻會讓瞬時頻率在標稱值上下擺動，最壞情況取上緣。
OSC 頻率製程偏移核取＋下拉±0.5 – 3.0%，預設 ±2.0%內部振盪器隨製程／溫度飄移。評估 IC 內部時脈餘裕時要算進來。
TX SSC 展頻核取＋下拉±0.5 – 3.0%，預設 ±3.0%輸出端也開展頻時勾選。

加乘怎麼算

勾選的項目是連乘而不是相加：

最大值 = 標稱值 × (1+a%) × (1+b%) × (1+c%)

三項全勾且都取 3%／2%／3% 時，倍率約為 1.0815，也就是比標稱高 8.15%。三項全不勾時，所有括號提示會消失。

哪些結果會被加乘

結果欄位套用哪些加乘
TCON UI DCLK三項全部（勾了就算）
LVDS per Port只有 RX SSC 展頻
LVDS 1 UI只有 RX SSC 展頻
mLVDS Tx Freq / 1 UI / 1/16 UI三項全部
P2P Tx Rate / BK Freq / 1 UI / 1/16 UI三項全部

加乘值以括號顯示在原數值旁邊，另外「加乘後最大 DCLK」會單獨列在加乘區塊下方。

LVDS per Port 為什麼不吃 OSC 與 TX SSC 這是輸入端的實際線上頻率，只受訊號源的展頻影響；OSC 偏移發生在 IC 內部、TX SSC 發生在輸出端，兩者都不會改變進來的 LVDS 頻率。這個區分是刻意的，不是漏算。

6P2P Rx Bit Rate 計算（eDP）

回答「這組時序需要幾條 Lane、跑到哪一檔 Link Rate」。→ 直接開啟工具的這張卡

控制項

控制項型別選項／預設說明
I/F下拉eDP（預設）／其他選 eDP 時 Encoding 鎖成 8b/10b 且顯示規格對照列；選其他時 Encoding 兩欄解鎖可自行填，規格對照列隱藏（因為那是 eDP 專屬的分檔）。
Color Depth單選鈕6 / 8（預設）/ 10 / 12 bits/channel每個色彩通道的位元數，公式中會再乘 3（RGB）。從 8 bit 改 10 bit，Bit Rate 直接漲 25%。
TCON Rx Lane單選鈕1 / 2（預設）/ 4Lane 數。Lane 加倍，每 Lane 的 Bit Rate 減半——當算出來超出最高檔規格時，第一個要調的就是它。
Frame Rate [Hz]數值輸入預設 144與 LVDS Rx 卡雙向連動，見第 9 章。
Encoding In [bits]數值輸入eDP 鎖定 8編碼前位元數。
Encoding Out [bits]數值輸入eDP 鎖定 10編碼後位元數。8b/10b 代表有 25% 的頻寬花在編碼上，這在估算時很容易被忘記。

公式

Rx Bit Rate / Lane [Gbps] = Htotal × Vtotal × Frame Rate × Color Depth × 3 × (Enc Out ÷ Enc In) ÷ (Lane × 10⁹)

  • × 3：RGB 三個通道
  • Enc Out ÷ Enc In：編碼額外開銷，eDP 為 10/8 ＝ 1.25
  • ÷ Lane：資料平均分配到各 Lane

10常見問題

點問題展開答案。

Tx 兩張卡顯示 —，什麼都沒算？▼

Tx 卡沒有自己的 Frame Rate，共用值必須先有效。請先在 LVDS Rx 或 P2P Rx 任一張卡把 Frame Rate 算出來（或直接在 P2P Rx 填一個），Tx 立刻就有數字。另外 Htotal 或 Vtotal 為 0 時整頁都不會計算。

Encoding 欄位灰灰的改不動？▼

那是刻意鎖定的：I/F 選 eDP（8/10）、iSP（8/9）、PHI（10/12）時，Encoding 由規格決定，不該被隨手改掉。要自訂請把 I/F 切到其他，兩欄就會解鎖。

算出來的頻率比實測低一截？▼

依可能性排查：

  1. Blank 沒填或填太小——這是最常見的原因，見第 3 章。
  2. 沒把 SSC／OSC 加乘算進去——實測拿到的是瞬時最大值，標稱值當然比較低。勾選第 5 章的加乘再比對。
  3. Encoding 開銷沒算——eDP 的 8b/10b 就是 25%。
  4. 量到的是不同節點的頻率（例如把 TCON DCLK 當成 LVDS per Port，兩者差兩倍）。
為什麼 LVDS 的 1 UI 用 ×7，mLVDS 卻用 ×2？▼

兩者的序列化方式不同：LVDS 是 7:1 序列化（一個時脈週期送 7 個 bit），mLVDS 是 DDR（時脈的上升與下降緣各送一個 bit，等於 2 倍）。係數反映的是實際的位元密度，不是換算單位。

需最低 eDP 規格顯示紅色的超出提示？▼

代表算出來的每 Lane Bit Rate 已經超過表中最高檔（10.0 Gbps）。可行的方向：增加 Lane 數（4 Lane 讓每 Lane 減半）、降低 Color Depth、縮小 blank，或降低更新率。四者都是規格取捨，改一個就回來看這張卡的數字。

可以拿這些數字直接寫進規格書嗎？▼

不建議。這裡算的是理論頻率，不含 IC 實際規格上限、PHY 餘裕與板端損耗。它適合用來快速比較配置與檢查量級，正式數字仍請以規格書與實測為準。
