1工具简介

一块面板的时序规格丢过来，要立刻回答「这样的分辨率与刷新率，接口跑得动吗？」。这个工具把四种接口的频率换算集中在同一页，四张卡片共用同一组 Frame 参数，改一个数字四边同时更新。

它在算什么

  • TCON Rx（输入端） — LVDS Rx 的各级时钟频率、P2P（eDP）的每 Lane Bit Rate
  • TCON Tx（输出端） — mLVDS 的 Tx 频率、P2P（iSP／PHI）的 Tx Rate
  • 另外一并给出 1 UI（单个位的时间长度）与 1/16 UI，这是评估 skew 预算与测量分辨率时最常要的数字
  • eDP 还会直接告诉你至少要哪一档 Link Rate（RBR／HBR／HBR2／HBR3）

三个使用前提

  • 没有「计算」按钮 — 每个字段都是实时计算，打字的当下四张卡就全部重算。
  • 四张卡片共用 Frame 参数 — 最上面那张卡的 Hactive／Hblank／Vactive／Vblank 是所有公式的共同基础。
  • Frame Rate 是双向联动的 — LVDS Rx 与 P2P Rx 的 Frame Rate 会互相同步，Tx 两张卡直接沿用同一个值。详见第 9 章。
结果仅供估算 这里算的是理论频率，不含 PHY 的实际余量、板端损耗与 IC 规格上限。要判断「这颗 IC 撑不撑得住」，仍以正式规格书为准；本工具的用途是快速比较不同配置与抓出量级错误。

为什么 Blank 不能乱填

所有频率都建立在 Htotal × Vtotal × Frame Rate 之上，而 Htotal／Vtotal 含 blank。只填 active 不填 blank，算出来的频率会低估约 8–15%——那是实际跑不动却以为有余量的典型来源。面板规格书上的 blank 值请照抄，不要凭印象。

Blank 也不是越大越安全 Blank 加大会同步推高 Pixel Rate 与所有下游频率。做规格取舍时，这里每加 100 个 pixel，四张卡的结果都会跟着涨。

输出结果与公式

结果公式含义
Frame RatePixel Rate × 10⁶ ÷ (Htotal × Vtotal)实际刷新率。反推模式下才是计算结果。
Pixel RateHtotal × Vtotal × Frame Rate ÷ 10⁶，或 FPGA DCLK × Port每秒送出的像素数（MHz），全页最核心的中间量。
FPGA UI DCLKPixel Rate ÷ Port信号源端每个 Port 的像素时钟。
TCON UI DCLKFPGA UI DCLK × 2TCON 内部像素时钟，固定为前者的两倍。
LVDS per Port= FPGA UI DCLK每个 LVDS Port 的时钟频率，测量时对得上的就是这个。
1 UI [ps]10⁶ ÷ (7 × LVDS per Port)单个位的时间长度。系数 7 来自 LVDS 的 7:1 串行化：一个时钟周期内送 7 个 bit。
1 UI 拿来做什么 它是 skew／jitter 预算的分母。例如 1 UI ＝ 680 ps 时，板端 100 ps 的走线差就吃掉了约 15% 的眼图宽度。分辨率往上拉时 1 UI 会快速变小，这也是为什么同样的板子在高刷新率下才开始出问题。

5DCLK 频率加乘（最大值估算）

位于 LVDS Rx 卡最下方。用途是回答「把所有会让频率变快的因素都算进去，最坏情况是多少」——设计余量要看的是这个数字，不是标称值。

三个勾选项

项目类型百分比选项／默认什么情况要勾
RX SSC 展频复选框＋下拉菜单±0.5 / 1.0 / 1.5 / 2.0 / 2.5 / 3.0%，默认 ±3.0%信号源端开了展频（SSC）。展频会让瞬时频率在标称值上下摆动，最坏情况取上缘。
OSC 频率制程偏移复选框＋下拉菜单±0.5 – 3.0%，默认 ±2.0%内部振荡器随制程／温度漂移。评估 IC 内部时钟余量时要算进来。
TX SSC 展频复选框＋下拉菜单±0.5 – 3.0%，默认 ±3.0%输出端也开展频时勾选。

加乘怎么算

勾选的项目是连乘而不是相加：

最大值 = 标称值 × (1+a%) × (1+b%) × (1+c%)

三项全勾且都取 3%／2%／3% 时，倍率约为 1.0815，也就是比标称高 8.15%。三项全不勾时，所有括号提示会消失。

哪些结果会被加乘

结果字段套用哪些加乘
TCON UI DCLK三项全部（勾了就算）
LVDS per Port只有 RX SSC 展频
LVDS 1 UI只有 RX SSC 展频
mLVDS Tx Freq / 1 UI / 1/16 UI三项全部
P2P Tx Rate / BK Freq / 1 UI / 1/16 UI三项全部

加乘值以括号显示在原数值旁边，另外「加乘后最大 DCLK」会单独列在加乘区块下方。

LVDS per Port 为什么不吃 OSC 与 TX SSC 这是输入端的实际线上频率，只受信号源的展频影响；OSC 偏移发生在 IC 内部、TX SSC 发生在输出端，两者都不会改变进来的 LVDS 频率。这个区分是刻意的，不是漏算。

6P2P Rx Bit Rate 计算（eDP）

回答「这组时序需要几条 Lane、跑到哪一档 Link Rate」。→ 直接打开工具的这张卡

控件

控件类型选项／默认说明
I/F下拉菜单eDP（默认）／其他选 eDP 时 Encoding 锁成 8b/10b 且显示规格对照行；选其他时 Encoding 两栏解锁可自行填，规格对照行隐藏（因为那是 eDP 专属的分档）。
Color Depth单选钮6 / 8（默认）/ 10 / 12 bits/channel每个色彩通道的位数，公式中会再乘 3（RGB）。从 8 bit 改 10 bit，Bit Rate 直接涨 25%。
TCON Rx Lane单选钮1 / 2（默认）/ 4Lane 数。Lane 加倍，每 Lane 的 Bit Rate 减半——当算出来超出最高档规格时，第一个要调的就是它。
Frame Rate [Hz]数值输入默认 144与 LVDS Rx 卡双向联动，见第 9 章。
Encoding In [bits]数值输入eDP 锁定 8编码前位数。
Encoding Out [bits]数值输入eDP 锁定 10编码后位数。8b/10b 代表有 25% 的带宽花在编码上，这在估算时很容易被忘记。

公式

Rx Bit Rate / Lane [Gbps] = Htotal × Vtotal × Frame Rate × Color Depth × 3 × (Enc Out ÷ Enc In) ÷ (Lane × 10⁹)

  • × 3：RGB 三个通道
  • Enc Out ÷ Enc In：编码额外开销，eDP 为 10/8 ＝ 1.25
  • ÷ Lane：数据平均分配到各 Lane

工具会把算出来的 Bit Rate 与下列档位比对，取第一个容得下的并显示为绿色；全部都不够时显示红色的超出规格提示。

显示名称每 Lane 上限

你改了哪里工具做了什么
改 P2P Rx 的 Frame Rate自动把 LVDS Rx 的计算模式切成「给定 Frame Rate」并填入同一个值，再重算 LVDS 全部结果。这是刻意的：两边的刷新率不可能不同。
改 LVDS Rx 的任何输入算出 Frame Rate 后写回 P2P Rx 的 Frame Rate 字段。
两张 Tx 卡没有自己的 Frame Rate 字段，直接沿用共用值（以 P2P Rx 的值优先）。
所以「改了 eDP 的 FPS，LVDS 那边的模式自己跳掉了」是正常的 不是误触。若你想固定用 FPGA DCLK 当输入，请不要再去动 P2P Rx 的 Frame Rate 字段——改它就会把模式切走。

10常见问题

点问题展开答案。

Tx 两张卡显示 —，什么都没算？▼

Tx 卡没有自己的 Frame Rate，共用值必须先有效。请先在 LVDS Rx 或 P2P Rx 任一张卡把 Frame Rate 算出来（或直接在 P2P Rx 填一个），Tx 立刻就有数字。另外 Htotal 或 Vtotal 为 0 时整页都不会计算。

Encoding 字段是灰的改不动？▼

那是刻意锁定的：I/F 选 eDP（8/10）、iSP（8/9）、PHI（10/12）时，Encoding 由规格决定，不该被随手改掉。要自定义请把 I/F 切到其他，两栏就会解锁。

算出来的频率比实测低一截？▼

按可能性排查：

  1. Blank 没填或填太小——这是最常见的原因，见第 3 章。
  2. 没把 SSC／OSC 加乘算进去——实测拿到的是瞬时最大值，标称值当然比较低。勾选第 5 章的加乘再比对。
  3. Encoding 开销没算——eDP 的 8b/10b 就是 25%。
  4. 量到的是不同节点的频率（例如把 TCON DCLK 当成 LVDS per Port，两者差两倍）。
为什么 LVDS 的 1 UI 用 ×7，mLVDS 却用 ×2？▼

两者的串行化方式不同：LVDS 是 7:1 串行化（一个时钟周期送 7 个 bit），mLVDS 是 DDR（时钟的上升沿与下降沿各送一个 bit，等于 2 倍）。系数反映的是实际的位密度，不是换算单位。

需最低 eDP 规格显示红色的超出提示？▼

代表算出来的每 Lane Bit Rate 已经超过表中最高档（10.0 Gbps）。可行的方向：增加 Lane 数（4 Lane 让每 Lane 减半）、降低 Color Depth、缩小 blank，或降低刷新率。四者都是规格取舍，改一个就回来看这张卡的数字。

可以拿这些数字直接写进规格书吗？▼

不建议。这里算的是理论频率，不含 IC 实际规格上限、PHY 余量与板端损耗。它适合用来快速比较配置与检查量级，正式数字仍请以规格书与实测为准。
