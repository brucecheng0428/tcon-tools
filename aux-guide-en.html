1Introduction

Three jobs on one page: turn AUX packets into something readable, look up DPCD register definitions and what each bit means, and compare differences between eDP / DP versions. It carries 289 DPCD register definitions and 326 version annotations, so you no longer have to page through the specification PDF.

The three tabs

  • AUX Decode - build a Request / Reply from the dropdowns, see what it does, and get the matching Manchester II waveform.
  • DPCD Lookup - enter an address (add a value if you have one) to list the register name, the read/write attribute, what each bit means and how that value reads. You can also work backwards and search by keyword.
  • Version Diff - one table listing the registers and bits that were added or changed between versions.

Two handy details

  • The tab is remembered - after a reload you land back on the tab you were reading. You can also open one directly through a URL parameter, for example aux.html?auxTab=dpcd (that is how the other tools link here).
  • Addresses in the decode result are clickable - the target address decoded from a Native transaction is a link. Click it to jump straight to the DPCD Lookup tab with that address filled in.

2Quick start

The two most common situations.

Case A: you have an AUX packet in hand

Pick the Command

The high 4 bits of the first byte are the Command. 9 is a DPCD read, 8 is a DPCD write.

Dial in the address and length

Dial the Address with the five wheels. The Length dropdown sets the field value - Actual bytes = Length + 1.

(Optional) fill in the Reply

If you captured a reply, pick the Reply Status. For a Read transaction you can also enter the returned data.

Press "▶ Decode"

The decode result and the waveform appear below. The target address of a Native transaction is a link. Click it to jump to the DPCD Lookup.

Case B: you only want to look up a DPCD

Switch to the "DPCD Lookup" tab

Do not know the address? Type a keyword into the "Reverse Search" card below (for example LANE_COUNT).

Dial in the address

Pick the hex digits with the five wheels. A lookup runs about 1 second after you stop, so there is no button to press.

Enter the value you captured

Enter a value if you have one. The result then gains a "Value" column that turns every bit into plain meaning.

Filter by version when you need to

Pick a specification version at the top, and any register or bit that does not exist in that version is flagged.

The eight Command options

ValueNameDescription
9DPCD read (Native Read)The most common one. Reads a DPCD register in the panel.
8DPCD write (Native Write)Writes DPCD. The decode result adds a table of which address received which value.
1 / 5I2C Read（MOT=0 / MOT=1）I2C carried over AUX. The classic use is reading EDID.
0 / 4I2C Write（MOT=0 / MOT=1）Same as above, in the other direction.
2 / 6I2C Write Status（MOT=0 / MOT=1）Checks the status of the previous I2C write.
What MOT means Middle-of-Transaction. MOT=1 means something follows this one (I2C does not send STOP and stays in the same transaction), and MOT=0 means this is the last one. Reading EDID gives a run of MOT=1 packets, with MOT=0 only on the last.

Reply StatusDropdownSkip / AUX ACK / AUX NACK / AUX DEFER / I2C NACK / I2C DEFER / Custom inputChoose "Custom input" to type any hex byte (useful when you captured something odd). The "↩ List" button beside it switches back to the dropdown.

DEFER is not a failure DEFER means "I cannot answer yet, please retry", and the Source should resend. The occasional DEFER is normal. A long run of DEFERs is what points to a problem on the panel side. NACK, by contrast, is an outright refusal.

4Preamble settings and compliance check

The Preamble is the sync signal at the start of every AUX transaction. With too few pulses the other side may fail to lock. Enter the count you captured here and you see immediately whether it is within spec.

Two inputs

ControlTypeRange / defaultDescription
System PreambleSlider + number0–64, default 32Total Preamble pulses sent by the signal source (Source).
TCON ReplySlider + number0–64, default 32Total Preamble pulses sent by the panel (Sink) in its reply.

Each one is checked live, and the verdict appears right under that slider. The waveform is redrawn to match.

Spec ranges and the three hints

SpecificationCompliant range
DP / eDP 1.2 ~ 1.326 – 32
eDP 1.4 and later18 – 24
DisplayMeaning
✅ GreenInside the range for that specification.
🚨 RedBelow the minimum - a real risk, because the other side may not lock in time.
ℹ️ GreyAbove the recommended maximum, but the function still works - there are simply more pulses than the specification suggests.
Both specifications are shown, because their ranges conflict The default of 32 fits DP/eDP 1.2~1.3 but exceeds the recommended ceiling of eDP 1.4+; the other way round, 20 fits eDP 1.4+ but falls short of 1.2~1.3. What counts is that you read the row for the version your panel declares - both rows do not have to be green.

7DPCD version difference overview

One table that answers "which version did this feature start in". → Open this card in the tool

What the table holds

  • 14 functional groups (Receiver Capability, DSC, PSR, FEC…) and 108 differences in total.
  • Each row is: address | bit or value | name | first-version badge.
  • Badge colours separate the versions; eDP 1.4+ means "only from 1.4 onwards".
  • On this tab the table is built the first time you open the tab, so the very first switch has a barely noticeable delay.

Version order of the data sources

Listed by specification release date:

DP v1.2 → eDP v1.2 → eDP v1.3 → eDP v1.4 → DP v1.3 → eDP v1.4a → eDP v1.4b → DP v1.4a → DP v2.0 → eDP v1.5

eDP and DP version numbers cannot be compared directly The two specification lines were released interleaved: eDP 1.4 came before DP 1.3, and DP 1.4a came before eDP 1.5. To judge whether a feature should be there, look at the specification line the panel declares, not at which version number is larger.

8FAQ

Click a question to open the answer.

What number goes into Length?▼

Enter "actual bytes − 1". To read 1 byte enter 0; to read 16, enter 15. That is how the AUX specification defines it, and the field hint in the tool says the same thing. The decode result, on the other hand, shows the actual byte count after conversion, so a difference of 1 between the two is normal.

A lookup says "not found" - why?▼

The database holds 289 commonly used registers, not the entire address space - RESERVED ranges and rarely used addresses are not included. First check the digit count (5 hex digits are required, for example 00101 rather than 101), then use the reverse search to confirm the name. If it is still missing, that address is simply outside the collection for now.

The two Preamble hints contradict each other - is it compliant or not?▼

The tool checks against both specifications at once: DP / eDP 1.2~1.3 wants 26–32 and eDP 1.4 and later wants 18–24, and the two never overlapped. Read the row for the version your panel declares. Note as well: Red (below the minimum) is the real risk, while grey only means you are above the recommended ceiling and the function still works.

The address in the decode result does not respond to clicks?▼

Only the addresses of Native (DPCD) transactions are links, because only they map onto the DPCD address space. An I2C transaction carries an I2C device address, which the tool matches against well-known devices (EDID, for example) instead of linking.

Do I have to fill in the Reply?▼

No. The Reply section is optional. Leave it on "Skip" if you only want to check the Request. Filling it in adds the reply interpretation and the reply segment in the waveform.

How do I get back to the tab I was reading after a reload?▼

It already remembers for you - the tab state lives in the browser session, so a reload returns you to the same tab. You can also pick the tab from the URL: aux.html?auxTab=dpcd, ?auxTab=verdiff, ?auxTab=decode.
