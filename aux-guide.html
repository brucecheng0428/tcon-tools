1工具簡介

三件事合成一頁：把 AUX 封包解成人看得懂的內容、查 DPCD 暫存器的定義與每個 bit 的意義、以及比對不同 eDP／DP 版本之間的差異。內建 289 個 DPCD 暫存器定義與 326 筆版本標註，不必再翻規格書 PDF。

三個分頁

  • AUX 解碼 — 用選單組出一筆 Request／Reply，解出它在做什麼，並畫出對應的 Manchester II 波形。
  • DPCD 查詢 — 輸入位址（可加上值），列出暫存器名稱、讀寫屬性、每個 bit 的意義與該值的解讀。也能反過來用關鍵字搜尋。
  • 版本差異 — 一張總表列出跨版本才新增／變更的暫存器與 bit。

兩個好用的小地方

  • 分頁會被記住 — 重整後回到你上次看的那一頁；也可以用網址參數直接開，例如 aux.html?auxTab=dpcd（其他工具連過來時就是這樣指定的）。
  • 解碼結果裡的位址可以點 — Native 交易解出來的目標位址是連結，點一下直接跳到 DPCD 查詢分頁並帶入該位址。

2快速開始

兩個最常見的情境。

情境 A：手上有一筆 AUX 封包

選 Command

封包第一個 byte 的高 4 bits 就是 Command。9 是 DPCD 讀、8 是 DPCD 寫。

轉出位址與長度

Address 用五個滾輪轉；Length 選單選的是欄位值，實際 byte 數 ＝ Length ＋ 1。

（選填）填 Reply

有量到回覆就選 Reply Status，Read 交易還可以填回傳資料。

按「▶ 解碼」

下方出現解碼結果與波形。Native 交易的目標位址是連結，點一下就跳到 DPCD 查詢。

情境 B：只想查某個 DPCD

切到「DPCD 查詢」分頁

不知道位址？直接用下面那張「反向搜尋」卡輸入關鍵字（例如 LANE_COUNT）。

轉出位址

五個滾輪選 hex，停下約 1 秒會自動查詢，不必按任何按鈕。

填上量到的值

有值就填，結果會多出一欄「值」，把每個 bit 的數值直接翻成語意。

需要時再篩版本

上方選規格版本後，不存在於該版本的暫存器／bit 會被標示出來。

3AUX 解碼：封包輸入

不必自己拼 hex，用選單組出來即可，右下方會即時顯示組合後的封包。→ 直接開啟工具的這張卡

AUX Request

控制項型別選項／預設說明
Command下拉8 個選項，預設 9封包第一個 byte 的高 4 bits。詳見下表。
Address滾輪20-bit，5 位 hex五個滾輪各代表一位 hex，用轉的（滑鼠滾輪或手指滑動）而不是打字，避免打錯位數。
Length下拉資料長度欄位🔴 實際 byte 數 ＝ Length ＋ 1。這是 AUX 規範的定義：欄位填 0 代表 1 個 byte。解讀別人的封包時最容易在這裡差一。
Datahex 輸入格每格 1 byte只有 Write 類指令才會出現，格數隨 Length 自動增減。
組合封包預覽唯讀顯示—上面任何一項改動都會即時更新，可直接拿去和量測到的 raw bytes 比對。

Command 八個選項

值名稱說明
9DPCD 讀取（Native Read）最常見。讀面板的 DPCD 暫存器。
8DPCD 寫入（Native Write）寫 DPCD。解碼結果會附上「哪個位址被寫入什麼值」的對照表。
1 / 5I2C Read（MOT=0 / MOT=1）透過 AUX 走 I2C，最典型的用途是讀 EDID。
0 / 4I2C Write（MOT=0 / MOT=1）同上，方向相反。
2 / 6I2C Write Status（MOT=0 / MOT=1）查詢前一筆 I2C 寫入的狀態。
MOT 是什麼 Middle-of-Transaction。MOT=1 代表這筆之後還有後續（I2C 不送 STOP，繼續同一個交易），MOT=0 代表這是最後一筆。讀 EDID 時會看到一連串 MOT=1，最後一筆才是 MOT=0。

AUX Reply（選填）

控制項型別選項說明
Reply Status下拉不填／AUX ACK／AUX NACK／AUX DEFER／I2C NACK／I2C DEFER／自訂輸入選「自訂輸入」可以直接填任意 hex byte（量到怪值時用），旁邊的「↩ 選單」按鈕可切回下拉。
Reply Datahex 輸入格每格 1 byte只有 Read 類指令才會出現，用來填回傳的資料。
Reply 封包預覽唯讀顯示—即時組合。
DEFER 不等於失敗 DEFER 是「現在還不能回答，請稍後重試」，Source 應該重送。看到零星 DEFER 屬正常；連續大量 DEFER 才代表面板端有問題。NACK 則是明確拒絕。

4Preamble 設定與規範檢查

Preamble 是每一筆 AUX 交易開頭的同步訊號。數量不足，對方可能同步不上；這一區讓你把量到的數量填進去，立刻知道合不合規。

兩個輸入

控制項型別範圍／預設說明
系統 Preamble滑桿＋數值0–64，預設 32由訊號源（Source）送出的 Preamble 總數。
TCON Reply滑桿＋數值0–64，預設 32由面板端（Sink）回覆時送出的 Preamble 總數。

兩者各自即時檢查，結果直接顯示在該滑桿下方。波形也會同步重畫。

規範範圍與三種提示

規範合規範圍
DP / eDP 1.2 ~ 1.326 – 32
eDP 1.4 以上18 – 24
顯示意義
✅ 綠色落在該規範範圍內。
🚨 紅色低於最小值——這是真的有風險，對方可能來不及同步。
ℹ️ 灰色超出建議最大值，但功能上仍相容，只是比規範建議的多。
兩組規範會同時顯示，因為它們有衝突區間 預設值 32 剛好合 DP/eDP 1.2~1.3、卻超出 eDP 1.4+ 的建議上限；反過來 20 合 eDP 1.4+、卻不足 1.2~1.3。要看的是「你這塊面板宣告的版本」那一行，不是兩行都要綠。

7DPCD 版本差異總覽

一張表看完「哪些功能是哪個版本才開始有的」。→ 直接開啟工具的這張卡

表格內容

  • 共 14 個功能分區（Receiver Capability、DSC、PSR、FEC…）、108 條差異。
  • 每一列是：位址｜bit 或值｜名稱｜起始版本徽章。
  • 徽章顏色依版本區分，eDP 1.4+ 代表「1.4 版開始才有」。
  • 此分頁在第一次點開時才產生表格，所以初次切換會有極短暫的延遲。

資料來源版本順序

依規格發佈時間排列：

DP v1.2 → eDP v1.2 → eDP v1.3 → eDP v1.4 → DP v1.3 → eDP v1.4a → eDP v1.4b → DP v1.4a → DP v2.0 → eDP v1.5

eDP 與 DP 的版本號不能直接比大小 兩條規格線是交錯發佈的：eDP 1.4 早於 DP 1.3、DP 1.4a 早於 eDP 1.5。判斷「這個功能該不該有」時，要看的是面板宣告的那一條規格線，不是版本數字誰大。

8常見問題

點問題展開答案。

Length 到底要填幾？▼

填的是「實際 byte 數 − 1」。要讀 1 個 byte 就填 0、要讀 16 個就填 15。這是 AUX 規範的定義，工具的欄位提示也寫了同一件事。解碼結果那邊顯示的則是換算後的實際 byte 數，兩邊差 1 是正常的。

查了某個位址說「找不到」？▼

資料庫收錄 289 個常用暫存器，不是完整的位址空間——RESERVED 區段與極少用到的位址不在其中。先確認位數（要 5 位 hex，例如 00101 而不是 101），再用反向搜尋確認名稱是否正確。真的沒有就代表這個位址目前不在收錄範圍。

Preamble 兩行提示互相矛盾，到底合不合格？▼

工具是同時對兩組規範檢查：DP／eDP 1.2~1.3 要 26–32，eDP 1.4 以上要 18–24，兩者本來就不重疊。請看你的面板宣告的版本那一行。另外注意：紅色（低於最小值）才是真的有風險，灰色只是超出建議上限，功能仍相容。

解碼結果的位址點不動？▼

只有 Native（DPCD）交易的位址才是連結，因為只有它對應到 DPCD 位址空間。I2C 交易的位址是 I2C 裝置位址，工具會改為比對常見裝置（例如 EDID），不會跳轉。

Reply 一定要填嗎？▼

不用。Reply 區是選填，只想確認 Request 的內容時把它留在「不填」即可。填了才會多出回覆的解讀，以及波形中的回覆段落。

重整之後怎麼回到我剛剛看的分頁？▼

它已經幫你記住了——分頁狀態存在瀏覽器的工作階段裡，重整後自動回到原分頁。要指定開哪一頁也可以直接用網址：aux.html?auxTab=dpcd、?auxTab=verdiff、?auxTab=decode。
