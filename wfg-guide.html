1工具簡介

面板訊號模擬與取樣是一個純網頁的時序波形模擬器，讓你不必接上真實面板，就能把 TCON 的 Phase Counter 參數變成看得見的波形。

它在做什麼？

TCON（Timing Controller）內部用一組暫存器參數描述每一條輸出信號「什麼時候拉高、什麼時候拉低」。這些參數（ACT_TYPE、R_PH、F_PH、ST_LINE、SP_LINE、R_DLY、F_DLY…）彼此耦合，光看數字很難想像實際波形長什麼樣子。

本工具把這組參數即時算成波形畫在畫面上，你改一個數字，波形立刻跟著變。可以用來：

  • 練習與教學 — 理解 Phase Counter 各參數對波形的實際影響
  • 事前驗證 — 在燒錄到真機之前，先確認時序關係是否正確
  • 量測演練 — 用內建的游標、脈衝計數、即時測量，模擬示波器/邏輯分析儀的量測動作
  • 設定交換 — 匯出 .txt 設定檔或複製到剪貼簿，傳給同事重現同一組波形

2快速開始

第一次使用，照著這六步就能看到波形。

開啟工具並確認模式

開啟面板訊號模擬與取樣後，確認頁首的模式頁籤停在「面板訊號模擬」（預設就是這個）。

從「預設」下拉載入一組範例

左側最上方的「預設」下拉，選 FHD 60Hz Single Gate (LS：Multi CPV)。這會一次填好系統設定、18 條數位信號、Level Shifter 設定與 18 條輸出通道，畫面立刻出現完整波形。建議第一次使用先從預設開始，而不是從空白慢慢建。

展開「系統設定」看時序骨架，再到「系統模擬」拖拉霸

系統設定卡片裡的 Vactive / Vblank / Hactive / Hblank / Frame Rate 決定整張畫面的時間骨架（VTOTAL、HTOTAL、TCON HTOTAL、Pixel Rate 是算出來的唯讀值，改不動）。設好之後，到下面橘框那張「系統模擬」卡片拖三條拉霸，看換個更新率或加大 Vblank 會怎麼樣 —— 波形與所有數值即時重算。

調一條信號試試看

展開「數位信號」→ 點開 CK1 → 拖動 R_DLY 的滑桿。波形上的 CK1 會即時左右位移。所有欄位都是即時計算，沒有「計算」按鈕。

用游標量測

按鍵盤 1 放下游標 A1（會跟著滑鼠跑），在想要的位置按一下滑鼠左鍵釘住；再按 2 放下 A2。右側「時基標尺」會顯示兩者的時間差與換算頻率。

匯出設定分享

工具列「檔案」區的匯出會下載一個 .txt 設定檔；複製則把同樣內容放進剪貼簿，可直接貼到聊天軟體傳給同事，對方用貼上就能重現一模一樣的波形。手機上按貼上時，若瀏覽器擋掉自動讀取剪貼簿，會跳出「手動貼上設定」視窗讓你自己長按貼進去，一樣能套用。

手機也可以用 版面是手機優先設計。手機上可用單指拖曳平移波形、雙指縮放；左側參數卡片預設收合，點卡片標題即可展開。
不要期待它等於真機 本工具是依參數推算的理想波形模擬，不含類比上升/下降的真實 RC 行為、雜訊與負載效應。它用來驗證時序關係，不是用來驗證電氣特性。

參數之間的關係

  • 🔴 VTOTAL 與 HTOTAL 是唯讀顯示，不是輸入格（v3.28.0 起）。你輸入的是四格 ACTIVE ＋ BLANKING，total 由它們相加而來：VTOTAL = Vactive + Vblank、HTOTAL = Hactive + Hblank。想改 total 就去改那四格其中之一。
  • Htotal × Vtotal = 一張畫面的總時脈數
  • Pixel Rate = Htotal × Vtotal × Frame Rate，唯讀。它只由這三個參數決定，把 TX DCLK 往上調並不會改變它
  • RX DCLK = Pixel Rate ÷ 2，唯讀顯示，不能直接打字改（但可以用「系統模擬」卡片的 RX DCLK 拉霸間接推它，那條拉霸實際是在反推 Frame Rate）
  • TX DCLK 可以手動輸入，但永遠 ≥ RX DCLK。定頻下改 TX DCLK 不會回頭改 Frame Rate；變頻下會（v4.29.0 起雙向連動，見下方專節）。
  • TCON UI DCLK = TX DCLK × 機種係數，可以手動輸入，與 TX DCLK 互相連動（改哪一格另一格都會立刻跟著算好）
  • TCON HTOTAL 與上面那個 HTOTAL 不是同一個數字，它另外標出來就是要你確認 —— 詳見下方「兩個 HTOTAL 差在哪」
  • TCON Pixel Rate（v4.31.0 新增）= VTOTAL × TCON HTOTAL × Frame Rate，唯讀。它和左邊的 Pixel Rate 只差在 Htotal 用哪一個，所以把 TX DCLK 往上調它會跟著變大（左邊那個不會）—— 詳見下方「兩個 Pixel Rate 差在哪」
  • Vactive / Hactive 只影響有效顯示區的位置標示，不影響總時間長度；而且它們沒有任何下限保護，輸入多少就是多少
🔴 兩個 HTOTAL 差在哪 —— 為什麼 TCON HTOTAL 被特別標成亮藍色 同一個 H Total 框裡有兩個數字，很容易看成重複：

・HTOTAL（左，白字）＝ 系統端的 Htotal，就是 Hactive + Hblank，是你剛剛自己輸入出來的那個值。它描述的是面板／系統這一側一行有多長。
・TCON HTOTAL（右，亮藍字）＝ TCON 內部實際用的 Htotal。它由左邊那個值依 TX/RX DCLK 的比例換算而來：TCON HTOTAL = round(HTOTAL × TX DCLK ÷ RX DCLK)。所以兩者只有在 TX ＝ RX 時才會剛好一樣；一旦把 TX DCLK 拉高，右邊的數字就會和左邊分開。

🔴 v4.31.0 更正：本頁先前寫「依 Gate Type 與 TX/RX 比例換算」，其中 Gate Type 那半句是錯的。換算式裡沒有 Gate Type 這一項，實測 Single ⇄ Dual 切換時 TCON HTOTAL 逐值不變（2200 → 2200；另一組 2560×1440@120 Dual、TX 300 亦與公式吻合）。Gate Type 影響的是 Line Buffer 與內部時序推算，不影響 TCON HTOTAL。

它不是另一個要你填的參數，是一個註明值：拿去和你手上 TCON 設定檔／官方 UI 上的 HTOTAL 對一下，對得起來才代表這組模擬和真機是同一件事。這正是它被 highlight 的原因 —— 提醒你「這一格要看一眼」，不是提醒你「這一格要改」。
🔴 兩個 Pixel Rate 差在哪（v4.31.0 起卡片最下方是左右兩欄） 結構和上面那兩個 HTOTAL 完全一樣 —— 左邊白色＝系統端，右邊亮藍＝TCON 內部，而且就排在 HTOTAL／TCON HTOTAL 的正下方，上下對齊看得出對應關係：

Pixel Rate（左，白）
HTOTAL × VTOTAL × Frame Rate
・用系統端的 HTOTAL
・調高 TX DCLK 不會變
・＝ RX DCLK × 2
TCON Pixel Rate（右，亮藍）
VTOTAL × TCON HTOTAL × Frame Rate
・用 TCON 內部的 TCON HTOTAL
・調高 TX DCLK 會跟著變大
・≈ TX DCLK × 2（差異只來自 TCON HTOTAL 取整數）
兩邊算出來本來就會不一樣，這不是錯，正是這一版把它們並排列出來的理由。實測一組：
2560×1440@120、Hblank 160、Vblank 40、TX DCLK 300 ⇒ HTOTAL 2720／TCON HTOTAL 3378 ⇒ Pixel Rate 483.072 ／ TCON Pixel Rate 599.9328。

什麼時候看哪一個：要判斷「這組時序對面板／訊號源合不合理」看左邊；要和 TCON 設定檔或官方 UI 上的內部頻率對帳，看右邊。
從 TCON UI 抄 DCLK 之前，先確認機種 不同系列的 TCON，介面上那個「D-Clock／DCLK」代表的東西不一樣：
・EM01 系列與所有 NB TCON（E501A / E501B / E503 / EN01）→ 係數 ×1，UI 上的數字就等於 TX DCLK
・EM02 / E512（同一系列，E512 在前、EM02 是它的改版）→ 係數 ×2，UI 上的數字是 TX DCLK 的兩倍
所以在預設狀態（TX DCLK = RX DCLK）下，EM02 的 UI 會顯示整個 Pixel Rate（例如 148.5），EM01 則顯示它的一半（74.25）。 把 EM02 UI 上看到的 148.5 直接填進 TX DCLK 會差兩倍——請填在「TCON UI DCLK」那一格，並確認左邊的機種選對了。

注意「UI ＝ Pixel Rate」「UI ＝ Pixel Rate ÷ 2」只是預設狀態下的結果，不是恆等式。 係數是乘在 TX DCLK 上的：一旦把 TX DCLK 調高，UI DCLK 會跟著 TX 走，而 Pixel Rate 不動。
v4.7.0 起：TX DCLK 與 TCON UI DCLK 是硬下限／硬上限 上下鍵、滑鼠滾輪、輸入框箭頭調到界限就停住，不會再往下（或往上）走； 手動打字超出範圍時會在套用前擋下並就地說明，保留原本的值， 既不會靜默改成界限值，也不會先套用再彈回。

範圍由兩組限制疊起來：
・TX DCLK ≥ RX DCLK（一直都有的約束）
・TCON UI DCLK 的機種規格：Monitor（EM01／EM02／E512）40 – 500 MHz； Notebook（E501A／E501B／E503／EN01）20 – 105 MHz
兩格的界限由同一份計算換算而來，所以不會出現「一格擋下、另一格放行」。

🔴 v4.29.0 起，超出機種能力時畫面會直接講出路。舊版只會說「不相容，請調整 Frame Rate／HTOTAL／VTOTAL」， 你還得自己算要調到多少；現在會直接寫成一句話，例如：
「E503 這組解析度最高只跑得到 90 Hz，目前是 144 Hz。請先降低 Frame Rate，VBLANK／HBLANK 才調得動。」
會出現這句話，通常是因為匯入了一份超出這顆機種能力的 code／設定檔（用打字是進不到這個狀態的，輸入格會先擋下來）。 照著它做 —— 先把 Frame Rate 降到它說的那個數字以下，其他格子就會重新解鎖。
v4.7.0 起：定頻／變頻跟著機種走 Notebook TCON（E501A／E501B／E503／EN01）一定是定頻應用，所以選到 NB 機種時 「變頻應用」會變灰、不能選，並自動切回定頻。
Monitor TCON（EM01／EM02／E512）兩種都可能，不會去動你當下的選擇。
你自己選過的型態會被記住：在 MNT 選了變頻、切到 NB（被強制定頻）、再切回 MNT 時， 會還原成變頻，你的選擇不會被機種切換吃掉。
Frame 重複數越大越吃資源 它決定要模擬幾張畫面（1–4096）。預設 10 張足夠觀察大部分時序；要看跨很多張畫面的 Toggle 行為（例如 FRM_NO 週期）才需要調大。設到上千張時，第一次繪製會需要一點時間。

4-1　四張卡片各管什麼，為什麼這樣分（v4.30.0）

v4.30.0 之前，這些參數全部擠在一張叫「Frame 參數」的大卡片裡：一收就把 DCLK、Gate Type、三條拉霸全部一起收掉， 而且看不出「哪些是先設好就不再動的、哪些是拿來反覆試的」。現在拆成四張，順序就是使用順序：

順序卡片它管什麼什麼時候動它
① 系統設定
（原「Frame 參數」）		 Vactive／Vblank／Hactive／Hblank 四格輸入，算出 VTOTAL／HTOTAL／TCON HTOTAL；Frame Rate 輸入格；最下方 Pixel Rate 與 TCON Pixel Rate 兩欄顯示 一開始設一次。這是「這片面板長什麼樣」的規格，設定好之後通常整段分析都不會再動。
② 系統模擬
（橘框 ＋ 放大標題）		 三條拉霸：Frame Rate、Vblank、RX DCLK 反覆拖曳的地方。①設定完之後，「換個更新率會怎樣」「Vblank 拉長會怎樣」全部在這裡試。它被框成橘色就是這個意思 —— 要你來動的是這一張。
③ TCON頻率設定 定頻／變頻應用選擇；RX DCLK 顯示、TX DCLK、TCON UI DCLK（含機種下拉） 對到真機的地方。把 TCON 官方 UI 上看到的 D-Clock 填進來，或反過來看模擬出來的值是多少。
④ TCON 其他設定

4-3　「系統模擬」的三條拉霸

三條拉霸都不是新的參數，只是換一種方式去動既有的真值。共同點：拖曳時波形即時重繪，而且畫面會以波形區的中心為錨，不會拖一下就整段波形跑掉。

拉霸它實際在改什麼什麼東西守恆範圍
Frame Rate (Hz) 直接改 Frame Rate HTOTAL／VTOTAL 不動；Pixel Rate、RX DCLK 跟著變 兩端＝目前機種／解析度下真正跑得到的上下限，會隨其他參數即時更新
Vblank
(Pixel Rate 不變)		 改 Vblank ⇒ VTOTAL 變大，同時反推 Frame Rate 🔴 Pixel Rate 與 RX DCLK 逐值不變 左端 ＝ 拉霸出現當下的 Vblank 值；右端 ＝ 65535
RX DCLK
(= Pixel Rate ÷ 2)		 反推 Frame Rate（RX 本身仍是唯讀衍生值） HTOTAL／VTOTAL 不動 只會停在「Frame Rate 為整數」對得上的可達點
🔴 V-Blanking 拉霸：拉它的時候 Pixel Rate 與 RX DCLK 一個位數都不會變 這是這條拉霸存在的唯一理由，也是它和「直接去改 Vblank 輸入格」最大的差別：

・直接改 Vblank 輸入格 ⇒ VTOTAL 變大、Frame Rate 不動 ⇒ Pixel Rate 跟著變大。
・拉 Vblank 拉霸 ⇒ VTOTAL 變大，工具同步把 Frame Rate 等比降下來補回去 ⇒ Pixel Rate = HTOTAL × VTOTAL × fps 的乘積不變，RX DCLK 自然也不變。

用途：「這顆 TCON 的頻寬就這麼多，我想多塞一點垂直空白，代價是多少 Frame Rate？」——拉一下就直接看到答案，不必自己算。

兩個端點：
・左端 ＝ 拉霸出現的當下、你最後一次手動輸入的 Vblank 值。拉高之後隨時拉得回來，它不會被你自己推上去（否則拉高一次就再也回不到原點了）。要換一個新的左端，就去 Vblank 輸入格重打一個值。
・右端 ＝ 65535（暫存器位寬上限）。

會出現小數的 Frame Rate，這是正常的。要守住 Pixel Rate，Frame Rate 幾乎不可能剛好是整數（65535 個 Vblank 值裡只有 19 個對得上整數）。所以這條路徑刻意採用全精度浮點。 小數只從這條路徑產生：Frame Rate 的輸入格仍然只收整數、Frame Rate 拉霸仍然是一格一格跳。
拖拉霸時，畫面不會跑掉（v4.28.2） 拖 Frame Rate 拉霸與拖 Vblank 拉霸，都以波形區的中心為錨：你原本盯著第 5 張畫面的某個位置，拖完之後還是停在第 5 張畫面的同一個位置，不用重新找。
Vblank 這一條特別容易感覺得出來，因為它會改變 VTOTAL —— 舊版拖一格畫面就跳到別張畫面去了。這個錨定對所有讓 VTOTAL 改變的路徑都有效（拉霸、Vblank／Vactive 輸入格、匯入設定檔），不是只有拉霸。

4-4　哪些格子有下限保護、哪些完全沒有

🔴 H-Active 與 V-Active 完全不設限，輸入多少就是多少 這兩格是面板的解析度，是一個事實，不是一個可以被工具「修正」的數字。所以：
・沒有下限保護、不會被工具改寫成別的值、也不納入內部的邊界稽核。
・你打 800 就是 800，即使算出來的 TCON UI DCLK 會低於機種規格下限，工具也不會擋你——它只會在下方顯示一則說明，告訴你目前這個狀態超出規格、以及怎麼回到合法範圍。
（唯一的例外是既有的 total 上限判定：把解析度往上加到超過機種能力時，工具會把 ACTIVE 回退，這是 v4.7.1 就有的行為，與這裡講的下限是兩件事。）

相對地，V-Blanking 與 H-Blanking 兩格有下限保護（v4.28.1 起），由兩層疊起來、取較大的那一個：

層值怎麼來的什麼時候存在
① 硬底線 10 直接規定的最小值，沒有推導。太小的 blanking 在真機上本來就沒有意義。 一直都在
② 機種規格反推 依目前機種的 TCON UI DCLK 規格下限反推出來的 blanking 最小值 blanking 太小 ⇒ HTOTAL／VTOTAL 太小 ⇒ Pixel Rate 太低 ⇒ TCON UI DCLK 掉到規格下限以下。把這條反過來解，就得到 blanking 的下限。 只有變頻應用下存在。定頻下 TX DCLK 不跟著 RX 往下走，這條約束構不到上游，所以只剩硬底線 10。

實際下限 ＝ max(10, 機種反推值)。 打字打到比下限小的值時，工具會在套用前擋下並就地說明理由，畫面上的值一個位元都不會動。兩層的理由不同，訊息也分開寫 —— 撞到硬底線時不會扯「UI DCLK 會低於規格」這種不相干的理由。

下限只擋「往更糟的方向走」，永遠留退路 判定是「低於下限」而且「比原本更小」才擋。所以萬一你載入了一份 blanking 本來就低於下限的舊設定檔，往上調一定放行，不會被卡在一個既違規又動不了的狀態。
同理，Vblank 拉霸只吃硬底線 10，不吃機種層 —— 因為拉它時 Pixel Rate 守恆，UI DCLK 一步都不會低於規格下限，套上機種層只會無故縮小可拖曳範圍。

4-5　TCON UI DCLK ↔ Frame Rate 雙向連動（v4.29.0）

先決條件：這一節講的行為只在「變頻應用」下成立。定頻／變頻在「TCON頻率設定」卡片最上方選（NB 機種只有定頻，變頻會變灰）。

定頻應用變頻應用
TX DCLK 與 RX DCLK 的關係 TX 可以大於 RX，兩者各走各的 TX ≡ RX，永遠相等
🔴 TX DCLK 可不可以小於 RX DCLK 都不可以。填低了會在套用前擋下並就地說明，保留原本的值（不會靜默夾成下限，也不會先套用再彈回）。
改 TX／UI DCLK 之後 Frame Rate 會不會動 不會。TX 是獨立的一個量。 🔴 會。設 D-Clock 就等於反過來設 Frame Rate。
改 Frame Rate 之後 TX／UI DCLK 會不會動 會（Frame Rate ⇒ Pixel Rate ⇒ RX DCLK；定頻下 TX 只在被 RX 追上時才被抬起來）
🔴 變頻下：TX 增加 ⇒ RX 跟著增加；TX 減少 ⇒ RX 跟著減少 變頻應用裡 TX ≡ RX，所以動 TX／TCON UI DCLK 任一格，另一格與 RX DCLK 會一起跟著走，並且回頭把 Frame Rate 反推出來：

Frame Rate = 2 × TX DCLK × 10⁶ ÷ (HTOTAL × VTOTAL)

反推時守住的是解析度（HTOTAL／VTOTAL），變的是 Pixel Rate。
舉例：4320×2220 打 TCON UI DCLK ＝ 432 ⇒ Frame Rate 反推成 90.0901 Hz。

🔴 這條路徑守恆的東西剛好和 Vblank 拉霸相反，兩條不要混著想：
・Vblank 拉霸 ⇒ 動 VTOTAL，守住 Pixel Rate。
・D-Clock 反推 ⇒ 動 Pixel Rate，守住 HTOTAL／VTOTAL。

v4.29.0 之前的舊行為（若你記得的是這個）：變頻下 TX／TCON UI DCLK 兩格與兩條拉霸是灰掉、動不了的，因為它們被 RX 的下限鎖死了 —— TX 只能往上、拉高之後再也回不去。現在四個控制項一起解鎖，左端下限也改成機種規格下限（不再是「RX 自己」），所以整段範圍都拖得動、也拖得回來。

5TCON 其他設定（Gate Type ／ Toggle FRM_NO）

三個全域共用的影格編號參數。所有數位信號只要開啟 Toggle 模式，都是共用這一組設定，不需要（也不能）逐條分別設定。

它在控制什麼

Toggle 模式讓信號的 ACTIVE 極性每隔幾張畫面翻轉一次，常見於極性反轉（Polarity Inversion）相關的控制信號。FRM_NO_0/1/2 決定翻轉的節奏，每條信號用自己的 TG_INI_VAL 選要吃三個裡面的哪一個。

Toggle 的 INI_VAL 是「每張畫面開頭」的初始電位 它不是每一行重置一次，而是每一個影格（frame）開頭決定該張畫面的起始準位。這是最常被誤解的一點。
🔴 第一個 frame 一定不翻 極性的閉式是 ACTIVE(frame) = base XOR ( floor(frame / (FRM_NO + 1)) & 1 )，其中 base 就是 INI_VAL 給的初始極性（0 - Low → 0、1 - High → 1、Keep 因為沒有前一張畫面可延續 → 0）。
代進去就是 frame 0 恆等於 base —— 初始極性是 0 它就是 0、是 1 它就是 1，不會「一律從 HIGH 開始」。
🔴 1-based / 0-based 換算：「FRM_NO = 99 代表每 100 張畫面變一次極性，第 1 張到第 100 張極性都一樣，第 101 張才反過來」是從 1 數起的講法；工具與程式內部的 frame 是從 0 數起，對應「frame 0～99 相同、frame 100 反相」。

6-0　TCON 型態（MNT／NB）— 全域設定

TCON 型態決定 ACT_TYPE / R_PH / F_PH 這三個欄位的位元寬。所有數位信號共用同一個設定，不是逐條分別設。

v4.6.0 起：型態不再是獨立選項，改由「機種」決定 以前「數位信號」卡片最上方有一組 MNT／NB 的手動選項，v4.6.0 起已移除。 型態現在直接由你選的 TCON 機種推得：
・EM01 / EM02 / E512 → Monitor（MNT，9 bit）
・E501A / E501B / E503 / EN01 → Notebook（NB，6 bit）
機種在兩個地方都可以選，兩處是同一個設定：「TCON頻率設定 → DCLK → TCON UI DCLK」的下拉， 以及上方工具列 Code group 的型號下拉。
這樣改的好處：同一件事不再有兩個真值來源。舊版只有「匯入 code 成功」才會把型態同步成機種該有的， 所以「換了機種但還沒匯入」會停在錯的位元寬 —— 現在不會了。
選項位元寬三個欄位的範圍計數器溢位點
MNT（Monitor TCON）9 bit0 – 511數到 511 後 +1 繞回 0
NB（Notebook TCON）6 bit0 – 63數到 63 後 +1 繞回 0
  • 預設機種 EM01 ⇒ 預設 MNT。機種不跟內建預設綁定 —— 換快捷設定時會保留你目前選的機種。
  • 換成 NB 機種時，所有數位信號中大於 63 的 ACT_TYPE / R_PH / F_PH 會被夾為 63（是 clamp，不是 & 0x3F 截斷，所以 500 會變 63 而不是 52）。這個動作不可逆，換回 MNT 機種不會還原原值。
  • 一般（非 Toggle）信號的欄位上限一樣吃這個限制。
  • 機種會隨匯出／匯入一起帶走。舊設定檔的相容處理：檔案裡若有舊的 tcon_type 欄位而沒有機種欄位，會用它推回同類別的代表機種（MNT → EM01、NB → E501B），位元寬與舊檔完全相同，波形不會變；兩者都沒有的更舊檔案則當成 EM01（MNT）。反方向也顧到了：新版匯出的檔案仍會寫出 tcon_type，拿去用舊版打開位元寬一樣正確。
什麼時候看得出 MNT 與 NB 的差別？ 只有在 Toggle 模式、而且計數器真的數到位元寬上限時才看得出來。例如 ACT_TYPE=0 / R_PH=60 / F_PH=1 / ST_LINE=0 / SP_LINE=12：
NB → 60, 61, 62, 63, 0, 0, 0 …（第 4 條溢位歸零，而 0 剛好等於 ACT_TYPE 所以鎖死）→ 波形 H L H L H H H H H H H H H
MNT → 60, 61, 62 … 72（要數到 511 才繞回）→ 波形 H L H L H L H L H L H L H

控制項型別範圍／選項說明

控制項型別範圍說明
R_DLY滑桿列0–65535Rising Delay，上升邊緣延後幾個 DCLK。起算點是「R_PH_CNT 數到 ACT_TYPE 的那一條」的行首。這是調整信號水平位置最直接的參數。

R_DLY2／F_DLY2：不影響波形，但會進匯入匯出 這兩格18 條信號每一條都有，位置就在 R_DLY／F_DLY 那一列的正下方（總表裡則夾在 F_DLY 與 OAX_MODE 之間）。
・畫面上不會有任何反應：改了之後波形一個像素都不會動，這是正常的，不是壞掉。
・但它會跟著檔案走：匯入 TCON code 時會從晶片的暫存器讀回來填進這兩格；匯出時會照樣寫回去（MNT 每條訊號多 4 行 write -m、NB 每條訊號多 2 列）。
・所以「匯入某顆 TCON 的 code、只改別的東西、再匯出」不會把第二組延遲弄丟 —— 這正是加這兩格的理由。要在這裡順手把第二組延遲一起調好再匯出，也可以。
七顆機種（EM01／EM02／E512／E501A／E501B／E503／EN01）的上限都是 65535（16 bit），沒有型號差異。

實務上：R_PH / F_PH 決定「在第幾條 line 觸發」的粗調，R_DLY / F_DLY 決定「該條 line 之內偏移幾個時脈」的細調。兩者合起來才是最終的邊緣位置。

起算點怎麼判斷？兩個例子
XSTB（ACT_TYPE=0、R_PH=0、F_PH=0）：ACT_TYPE 是 0，兩個計數器一開始就等於最大值，所以每一條 line 都同時是 R 與 F 的觸發條。R_DLY 與 F_DLY 都從同一條的行首起算，一行內先上升再下降，形成每行一個窄脈衝。
VST1（ACT_TYPE=15、R_PH=15、F_PH=13、ST_LINE=2）：R_PH_CNT 在第 2 條就載入 15 = ACT_TYPE，所以 R_DLY 從第 2 條起算；F_PH_CNT 從 13 開始數，第 2 條是 13、第 3 條是 14、第 4 條才數到 15，所以 F_DLY 從第 4 條起算。兩者相差 2 條，脈衝寬度就是 2 條 line。
把滑鼠停在波形上時，畫布會用綠色與橘色箭頭分別標出 R_DLY 與 F_DLY 的起算條到邊緣的距離；上方 R_PH_CNT / F_PH_CNT 兩列會把觸發的那一格反白，可以直接對照。

6-2　Toggle 模式：另一套演算法（任一信號勾選即適用）

這是 18 條信號中唯一需要獨立說明的部分。只要勾選 Toggle，這條信號就改用另一套演算法 —— 判準是「Toggle 有沒有被勾」，與信號名稱無關。XSTB、VST1／2、CK1–CK8、TEND、VS、HS、GPO0／1 任何一支勾了 Toggle，行為都與 XPOL 完全一致（同一組參數在不同信號上會產生一模一樣的波形）。實務上最常用在 XPOL 與 LC，但那是慣例，不是限制。

勾選後卡片上還會多出七顆快速設定按鈕，一鍵把 ACT_TYPE、R_PH、F_PH 三個參數同時填成對應的極性反轉模式，並一併設定 ST_LINE / SP_LINE 的行區間，省去逐一計算。

為什麼這七組值叫「極性反轉模式」？ 這七組數值是為極性反轉（Polarity Inversion）設計的標準組合，而極性反轉正是 XPOL 這條信號的職責 — Source Driver 就是看 XPOL 決定要充正極還是負極 Gamma。任何一條信號勾選 Toggle 後都會出現這七顆按鈕（它們填的就是那三個通用參數），只是其他信號按了單純把參數填成這組數值而已。

🔴 勾了 Toggle 的信號，演算法與一般打 pulse 的信號完全不同（適用任一信號，不限 XPOL／LC） 一般信號是「兩個計數器各自數到 ACT_TYPE，一個管上升一個管下降」；Toggle 信號只有一個計數器，而且 F_PH 不是相位起始值，是位元遮罩（bitmask）：
  1. R_PH_CNT 在 ST_LINE 那一條直接載入 R_PH（不取模，就算 R_PH 比 ACT_TYPE 大也照載）。
  2. 之後每條 line 更新一次，有兩個歸零來源：
    ① 這條的值等於 ACT_TYPE → 下一條歸零（正常週期，長度 = ACT_TYPE + 1）
    ② 加一之後溢位 → 依 TCON 型態的位元寬繞回（MNT 9bit 到 511、NB 6bit 到 63，見 6-0）
    寫成一行就是 cnt(n+1) = (cnt(n) == ACT_TYPE) ? 0 : ((cnt(n) + 1) & maskBits)。
    兩者合起來會有一個容易忽略的行為：溢位歸零後如果剛好等於 ACT_TYPE（例如 ACT_TYPE = 0），計數器就從此鎖死在 0，波形之後恆定不再轉態。
  3. 把 F_PH 轉成二進位當位元遮罩，bit(n) = (cnt(n) & F_PH) != 0。例如 F_PH = 2（0b10）→ 看 bit 1。
  4. ST_LINE 那一條無條件被驅動到 ACTIVE（套 R_DLY）。之後每一條的準位是相對於 ST_LINE 那一條判斷的：
    bit(n) == bit(ST_LINE) → ACTIVE；不等 → 反相。
    🔴 注意是「與起點同相／反相」，不是「bit=1 就 HIGH」。R_PH 只要改，整條波形的相位就跟著平移。
    🔴 也注意 ACTIVE 不等於 HIGH —— ACTIVE 是「這張畫面的作用極性」，它可能是 HIGH 也可能是 LOW，由 INI_VAL 與 FRM_NO 決定（見下一條）。所以 ST_LINE 那一條不保證是「上升邊」，只是「進入 ACTIVE」。
  5. R_DLY 只在「準位改變」的那一條作用，而且兩個方向都用 R_DLY（low→high 與 high→low 皆然）。沒變的那一條不套任何延遲，直接維持前一條的準位。
  6. Toggle 模式沒有 F_DLY，該欄位在此模式下無作用（原廠 timing 文件的 XPOL 暫存器表也把它標為「Toggle mode 時 無用」，實際值設 0）。
  7. SP_LINE 是「最後一條參與 toggle 的 line」（含）。超過之後停止計數、不再轉態，一路 keep 住 SP_LINE 那條的準位到 frame 結束；下一個 frame 再從 ST_LINE 重新載入 R_PH。
  8. 整個 frame 的 ACTIVE 是 HIGH 還是 LOW：ACTIVE(frame) = base XOR ( floor(frame / (FRM_NO + 1)) & 1 )，base 由 INI_VAL 給。frame 0 恆等於 base，第一個 frame 一定不翻；之後每 FRM_NO + 1 個 frame 反相一次。XPOL 用 FRM_NO_0 = 0，就是每 1 個 frame 反相一次。詳見第 5 章。

把滑鼠停在 Toggle 信號的波形上時，畫布只會畫一支 R_DLY 箭頭（起算條就是準位改變的那一條），不會畫 F_DLY —— 因為 Toggle 模式下它不存在。上方 R_PH_CNT 列顯示計數值、F_PH_CNT 列改顯示被選中 bit 的值（0/1），兩列的高亮都到 SP_LINE 為止，之後轉灰。
「3-line」為什麼在畫面上看起來像「正正負」或「正負負」？ 這顆按鈕在 v2.97.479 之前叫 +-+，指的是一個週期內的三行極性：正、負、正。但因為週期的頭尾都是正，相鄰兩個週期的「尾正」與「頭正」會連在一起，所以連續看下去實際是 + - + | + - + | + - + —— 每 3 行只有 1 行是反極性，肉眼讀起來就成了「正正負」不斷重複。名稱容易被誤讀成「一個週期就是正負正三段」，因此改名為 3-line，與其他按鈕一樣以週期行數命名。
再加上 XPOL 會依 FRM_NO 設定逐 frame 整體反相，下一個 frame 同一段就變成 - + - | - + -，也就是「負負正」。所以同一組設定，看的 frame 不同、起算的行不同，會分別讀成「正正負」或「正負負」，兩者都是同一個 3 行週期、正負比 2:1 的樣式。

當目前的 ACT_TYPE / R_PH / F_PH 三者同時符合某顆按鈕的組合時，那顆按鈕會自動反白成橘色，讓你一眼看出目前處於哪個模式。手動改動任一參數後，反白就會消失。

6-3　參數如何疊成最終波形

運算順序：ACT_TYPE 決定週期 → R_PH / F_PH 決定相位內的邊緣 → R_DLY / F_DLY 做時脈級位移 → ST_LINE / SP_LINE 裁掉範圍外 → OAX 與另一條信號運算 → INV 最後反相 → 若開 Toggle 則依 FRM_NO 逐影格翻初始電位。

VCOM 會參與計算，但不會改變 Subpixel 波形本身 VCOM 與 Vpix（Subpixel）波形之間的正、負極性面積比會換算成兩側的灰階底色；兩側面積不相等時，那個底色還會閃爍提醒你。Vpix 波形的電壓數值不受 VCOM 影響 —— VCOM 只是基準線。
Gate 條數加大之後波形亂跳？請確認版本在 v4.26.3 以上 當 CK 的 SP_LINE 超過一整個 frame、而且 CKO 在 frame 結尾剛好停在高電位（VGH）時，v4.26.3 之前沒有在 frame 交界重置電位狀態，於是新的一張畫面裡 Gate 的脈衝序號整排位移一格，看起來就是把 Gate 條數加到 4 或 8 時波形亂跳。
CKO 在 frame 邊界本來就回到 VGL 的設定（絕大多數）波形逐值不變，這個修正碰不到它們。

12-3　匯入時的檢查與相容處理

  1. JSON 語法檢查 — 格式錯誤會跳出「JSON 格式錯誤」訊息並中止，不會破壞目前的設定。
  2. 格式標記檢查 — _format 不是 tcon-wfg-config 會提示「不是有效的 WFG 設定檔」。所以隨便一個 JSON 檔是載不進來的。
  3. 缺欄位自動補預設 — 舊版檔案缺少的欄位會套用預設值（Vtotal 1125、Htotal 2200、DCLK 74.25、Frame Rate 60、Single Gate、10 張影格…），不會出錯。
  4. 信號類型校正 — 前 18 條強制視為數位信號，第 19 條之後強制校正回正確的類比類型（Source Driver 或 Level Shifter），避免舊檔的錯誤資料造成異常。
  5. 舊名稱轉換 — 很舊版本使用的 ls1 之類命名會自動轉換成現行的 cko1。
  6. 通道數上限 — 最多讀取 64 條通道，超出的忽略。
  7. 載入完成後 — 預設下拉會自動重設為空白，提醒你目前顯示的是匯入的內容而非內建預設。
信號名稱不會被匯入覆蓋 匯入時會刻意跳過信號名稱欄位，18 條數位信號永遠保持原本的名字（XSTB、XPOL…）。想在波形上顯示不同名稱，請改「輸出通道」的通道名稱 — 那個是會被匯入的。

  • 匯出時：只有你真的動過 TCON UI DCLK 才會把對應的暫存器寫回清單。「匯入 → 什麼都不改 → 匯出」一列都不會多寫。
  • 算不出來時不會亂填：型號指紋不符、值超出 NB 的 20～105 MHz 規格、或 code 本身沒做過標準化，都會維持畫面上原本的值不動，並把理由寫在匯入卡片上、把 DCLK 那一項留著要你自己確認。
  • 🔴 EN01 不做這件事：目前手上的 EN01 真檔都沒有做過 AGBSFR 標準化，套公式會算出明顯偏低的值。選 EN01 時提醒卡片仍會保留 TCON UI DCLK 那一項，請照舊自己確認。

為什麼官方 UI 認得這份 xlsx：表頭字串逐字對得上

  • 欄名必須一字不差，連儲存格內的換行都算。例如 TCON\n(內部型號)、Slave Address\n(HEX)、Offset\n(HEX)、Case 0 Value\n(HEX) —— \n 是儲存格裡真的有一個換行，不是筆誤。
  • 欄名對不上就整欄讀不到，而且不會報錯（for cell in sheet[1]: if cell.value in columns: 沒命中就直接跳過）。這是這份檔案唯一會靜默失敗的地方。
  • 列數由 Offset\n(HEX) 那一欄決定：從第 2 列往下數，遇到第一個空格就停（27196–27201 行的 if cell.value is not None ... else: break），數到的長度就是 length_defaultcase。

所以「匯入永遠先進 CURRENT」不是本工具的偷懶 .script 的 write 指令只能寫暫存器，位址欄位是 [add 15:0]、上限 0xFFFF（見 13-1 的語法表）；而三個模式分頁在 0x35000 這個量級的 Flash 檔案偏移上。script 在物理上就搆不到那三個 —— 這才是「匯入只會改到 Current、之後還要自己搬一次」的原因。
🔴 模式標籤由「檔案裡的固定位置」決定，跟暫存器內容沒有關係 0x35000 ＝ 200%、0x35300 ＝ 133%、0x35600 ＝ Normal。這是原廠工具內部寫死的位址表，不是從 timing 值反推出來的。曾經用「reg_val 反推模式」的做法，結果把 0x35300 標成 200%，連帶讓人以為 Enable 被程式弄丟了 —— 其實那一個模式本來就只寫了兩條訊號。

200% ／ 133% 指的是 HSR／DLG 高刷新率應用的倍率（例如對 TCON 而言 Normal 是 2560×1440 200Hz、2x 是 2560×720 300／400Hz）。三模只在有這類應用的機種上才會寫滿。

GPO 分頁長什麼樣

  • 四個子分頁：Normal ／ 200% ／ 133% ／ Current。每個模式子分頁上都有一個 CRC16: 標籤。
  • 子分頁上方有一條工具列，最左邊是 File IO（Align = alLeft）、最右邊是 Flash R/W（Align = alRight），兩顆都是分割式按鈕（Style = bsSplitButton），按右側箭頭展開下拉選單。

兩個數字決定一切

  • 取樣率決定「看得多細」。要能還原一個訊號，取樣率至少是它頻率的數倍；量 1 MHz 的 SCL，用 200 MHz 取樣代表一個 bit 有 200 點，邊緣位置才準。
  • 深度決定「錄得多久」。錄製時間 = 深度 ÷ 取樣率，工具列會直接把這個數字寫在取樣群組下方（「理論取樣時間」）。

「理論」兩個字是真的 深度 ≥ 1 GSa 且理論時間超過 5 秒時，數字後面會加註「實際長度依硬體壓縮率」。硬體是用邊緣壓縮方式存資料，訊號越密、可錄時間越短，實際拿到的長度會比理論值短。

完全不要觸發條件把已設定的那顆按鈕再點一次取消不等條件、按下擷取就直接錄
A 與 B 不能設在同一條通道 在某條通道設定 B 事件時，若該通道原本是 A 事件通道，A 會自動被關閉（反過來也一樣）。這不是 bug——同一條線上的同一種邊緣無法區分先後，工具直接幫你避開這個矛盾設定。

控制項型別範圍說明
PWM1 / PWM2 啟用核取方塊—勾選才會輸出。未勾選時該列的頻率與 duty 欄位為停用狀態。
頻率數值＋單位0.05 Hz – 20 MHz，單位可選 Hz／KHz／MHz實際週期會量化成裝置時基的整數倍，設定極端值時輸出頻率會略有誤差。

PWM 燈不亮不代表設定沒存到 PWM 按鈕的綠燈只有在硬體連線為 ON 時才會亮。未連線時按確定，設定會存起來但不會送到裝置（狀態列會提示），等連線後重開視窗勾選即可。斷線或按 OFF 時，PWM 會被強制關閉——控制權都釋放了，輸出自然不該還算在本工具頭上。

三個前提，缺一不可 ① 桌面版 Chrome 或 Edge（WebUSB 不支援 Safari 與行動瀏覽器）；② 網頁必須在 https 下開啟；③ 同一台裝置不能同時被原廠軟體占用——USB 介面一次只能被一個程式握著。

第一次使用：匯入裝置支援包

按下單次或循環擷取

尚未匯入支援包時，工具會自動跳出引導視窗，說明接下來要做什麼。

取得並匯入 zip

視窗裡有「聯絡 Bruce」與「匯入 zip」兩顆按鈕。取得 la-device-support-pack-v4.zip 後回到這裡選擇該檔案。

匯入成功後自動接續

匯入完成會自動接著跑剛才被中斷的擷取流程。檔案內容存在這台電腦的這個瀏覽器裡，之後按擷取直接使用，不必再匯入。

為什麼不能自動下載 瀏覽器的安全限制讓網頁無法記住或讀取你的下載資料夾路徑，所以必須手動選一次檔案。匯入之後才由網頁自行保存，後續就不用再重複。

硬體連線 ⏻ 按鈕：ON 與 OFF 各做了什麼

按 ON開啟裝置並取得 USB 介面控制權（必要時跳出瀏覽器的裝置選擇視窗）成功＝按鈕亮綠並提示已取得控制權；若裝置尚未初始化，會提示需先匯入支援包或按一次單次擷取

  • 存在瀏覽器裡：通道名稱、通道顯示順序、取樣率、深度、門檻電壓、觸發通道／邊緣／位置，以及目前選的快捷設定。重新整理或下次開啟都會沿用。

20常見問題

點問題展開答案。

我改了參數，但波形完全沒變化？▼

依可能性由高到低檢查：

  1. 該信號的 ENABLE 沒有勾 — 卡片標題會顯示灰色的 OFF。
  2. 該信號沒有被指派到任何輸出通道 — 到「輸出通道」卡片檢查。
  3. 對應通道的顯示切換是 ○（隱藏）而不是 👁。
  4. ST_LINE 大於 Vtotal，或 SP_LINE 小於 ST_LINE，導致這條信號在模擬範圍內完全沒有輸出。
  5. 目前的檢視範圍剛好避開了該信號有動作的區段 — 按「全覽」看全貌。
匯入設定檔之後，滾輪縮放很卡？▼

先確認版本 —— 這是 v4.27.2 的效能優化題目。舊版的計算量綁在「視野裡有幾行」而不是「畫面上有幾個像素」，所以縮得越遠越卡：遠端視野每縮一格要等 1.3 秒（約 0.75 FPS），跳到全覽的單次重繪要 11 秒。

v4.27.2 起，遠端與近端都穩定在每格約 33 ms（約 30 FPS），全覽重繪降到 0.03 秒。畫出來的波形逐像素完全相同，這一版只是把過度的計算量拿掉，沒有把畫面簡化。

🔴 還有一種卡頓沒有被這次優化改到：把畫面縮到最遠、放開滑鼠之後的那一次凍結。那一段是類比訊號的預先計算，是另一個題目。詳見 第 11 章。

VTOTAL／HTOTAL 那兩格點下去改不動？▼

那兩格自 v3.28.0 起就是唯讀顯示，不是輸入格。要改的是它們上面那四格：VTOTAL = Vactive + Vblank、HTOTAL = Hactive + Hblank。改任一格，下面的 total 立刻跟著算好。

拉 Vblank 拉霸，Frame Rate 怎麼變成小數了？▼

這是正常的，而且是刻意的。Vblank 拉霸的唯一目的就是「加大 Vblank 而 Pixel Rate 與 RX DCLK 完全不變」。因為 Pixel Rate = HTOTAL × VTOTAL × fps，VTOTAL 一變大，fps 就必須等比降下來補回去 —— 而這個等比降下來的值幾乎不可能剛好是整數（65535 個 Vblank 值裡只有 19 個對得上整數）。取整就守不住 Pixel Rate，所以這條路徑採全精度浮點。

小數只會從這條路徑產生：Frame Rate 的輸入格仍然只收整數。

變頻應用下，我改了 TX DCLK，Frame Rate 怎麼跟著變了？▼

變頻下這兩個量是雙向連動的（v4.29.0 起），設 D-Clock 就等於反過來設 Frame Rate。變頻應用裡 TX ≡ RX，所以動 TX 或 TCON UI DCLK，RX 會跟著走，Frame Rate 再由 fps = 2 × TX × 10⁶ ÷ (HTOTAL × VTOTAL) 反推出來。TX 增加 ⇒ RX 增加；TX 減少 ⇒ RX 減少。反推時守住的是解析度，變的是 Pixel Rate。

定頻下則不會 —— 定頻的 TX 是獨立的量，可以大於 RX，改它不影響 Frame Rate。但兩種型態下 TX 都不可以小於 RX，填低了會在套用前被擋下並保留原值。

若你記得的是「變頻下 TX 那兩格是灰的、動不了」，那是 v4.29.0 之前的行為，現在已經解鎖。詳見 4-5。

匯出的 script 用官方 TCON UI 匯入後，畫面上還是舊的 timing？▼

script 沒有問題，是官方 UI 匯入之後不會自動重讀。到 GPO 分頁按一次 Read，設定就會出現在 Current 子分頁裡。MNT 機種匯出時會跳一個提醒視窗講這件事（NB 不跳）。

要把 CURRENT 的值再複製到 Normal／200%／133% 子分頁，正確步驟是：① GPO 分頁按 Read → ② 先切到目標子分頁 → ③ 點左下角的 File IO → ④ 在 --- Copy Data --- 底下選 From Current。完整說明見 12-4。

把面板 Gate 條數加大（例如 4 或 8 條）之後，波形整排亂跳？▼

這是 v4.26.3 修掉的一個 bug，請確認你用的是 v4.26.3 以後的版本。當 CK 的 SP_LINE 超過一整個 frame、而且 CKO 在 frame 結尾剛好停在高電位（VGH）時，舊版沒有在 frame 交界把電位狀態重置，於是新的一張畫面裡 Gate 的脈衝序號整排位移一格，看起來就是波形亂跳。

CKO 在 frame 邊界本來就回到 VGL 的設定（絕大多數情況）波形逐值不變，這個修正不會影響到它們。

重新整理之後，Hblank 變成 1、Pixel Rate 整個跑掉？▼

這是 v4.29.1 修掉的還原順序 bug。只要 Hactive 不等於預設的 1920（例如 QHD 2560×1440），舊版重新整理後會把 HTOTAL 算成「1920 ＋ 你的 Hblank」，Hblank 被推成負數再被夾成 1，並跳出一句自相矛盾的「blanking 與 total 不一致」。

存下來的檔案本身一直都是對的，錯的只有讀回來的順序 —— 所以舊版存的檔用新版打開就是對的，不必重存。自動還原、手動匯入設定檔、貼上設定三條路徑一起修好了。

為什麼有些拉霸是橘色、有些數字是亮藍色？▼

顏色是有意義的，不是裝飾：

  • 橘 ＝「系統模擬」卡片 —— 系統設定設完之後，要你來動的就是這一張。卡片外框、放大的標題、三條拉霸的滑塊都是橘的。
  • 亮藍 ＝ 一般控制項（TCON頻率設定那兩條拉霸），以及TCON 內部實際跑的唯讀註明值（TCON HTOTAL、TCON Pixel Rate）。這個藍色和 Rx/Tx 頻率計算工具分頁上那些計算結果是同一個色。
    🔴 v4.31.0 起「系統設定」卡片裡的亮藍只代表一件事：TCON 內部的數字。 同一列左邊的系統端數字（HTOTAL、Pixel Rate）一律白色。先前 Pixel Rate 也是亮藍，和隔壁的 TCON HTOTAL 同色，容易被誤會成同一側的東西。

完整說明見 4-2。

為什麼沒有「計算」按鈕？▼

「面板訊號模擬」模式的所有欄位都是即時計算：輸入的當下就重新產生波形，不需要也沒有確認按鈕。這樣調參數時可以邊拖滑桿邊看波形變化，比按一次算一次直覺得多。

Toggle 勾了卻看不出翻轉效果？▼

兩個常見原因：

  • Frame 重複數太小。Toggle 是逐影格翻轉，若 FRM_NO 設 99 而只模擬 10 張畫面，範圍內根本輪不到翻轉。把 Frame 重複數調到大於 FRM_NO 的值。
  • 檢視範圍太窄。要看跨影格的行為，得先按「全覽」縮到能看見多張畫面的尺度。
按了數字鍵，游標怎麼不見了？▼

游標有三個狀態循環：未啟用 → 跟隨滑鼠 → 已釘住。從「跟隨滑鼠」狀態再按一次同一鍵，就會移除。若你放下游標後沒有按滑鼠左鍵釘住，它一直處於跟隨狀態，此時再按一次鍵就會消失。正確做法是：按數字鍵 → 移動滑鼠到想要的位置 → 按一下左鍵釘住。

時間差輸入框輸入數字後沒反應？▼

要滿足三個條件才會生效：

  • 該組的兩支游標都必須已經放下（只有一支時不會出現輸入框）
  • 輸入必須是正實數，不能是 0 或負數
  • 換算成秒之後不小於 0.5 ns，太小的值會被拒絕

輸入完要按 Enter 才會套用（按 Esc 是放棄）。

拖動一支游標，另一支怎麼跟著跑？▼

這是時間差鎖定生效中，代表你先前用時間差輸入框設定過該組的間距。兩支游標會維持固定間距一起移動，像一把固定寬度的卡尺。要解除，按該組的 × 關閉再重新放置，或用快捷鍵切換該組游標。

類比通道的脈衝計數結果和預期不同？▼

類比通道是用該通道的 V1 電壓游標當作高低判準。V1 拉太高或太低，都會導致計數結果不符預期。請先在通道名稱旁點開 V1/V2 游標，把 V1 拖到波形擺幅的中間附近，再看計數結果。

改了 GOA Phase，CKO 通道跑到哪去了？▼

改 GOA Phase 會重建所有 CKO。新產生的 CKO 會自動填進第一個空著的輸出通道並命名為「CKO n」。若 64 條通道已經全部被佔用，新的 CKO 就沒有位置可放 — 這時請先把不需要的通道來源改成「無」，再重新設定 GOA Phase。

按了 XPOL 快速設定按鈕，其他欄位怎麼也變了？▼

這是設計上的預期行為。快速設定按鈕除了填入 ACT_TYPE / R_PH / F_PH 之外，還會把 INI_VAL 設成 2 - Keep，並在 ACT_TYPE 大於 0 時把 SP_LINE 設成最大值 16383。若你需要不同的設定，按完按鈕後再手動改這兩個欄位即可。

匯出的檔案為什麼是 .txt 而不是 .json？▼

內容確實是 JSON 格式，用 .txt 副檔名純粹是為了方便：很多通訊軟體與郵件系統會擋掉 .json 附件，但 .txt 通常暢行無阻。匯入時 .txt 與 .json 兩種都接受。

波形拖不動、卡卡的？▼

最常見的原因是「Frame 重複數」設得太大（例如上千張）同時又處於全覽狀態，需要繪製的資料量非常大。解法：先放大到你真正關心的區段，或把 Frame 重複數降到需要的最小值。載入預設「FHD 60Hz Single Gate」時 Frame 重複數是 1000，若不需要看跨影格行為，可以先調小。

可以直接改波形左邊的通道名稱嗎？▼

不行。波形左側的名稱欄不支援雙擊改名或右鍵選單。請到左側「輸出通道」卡片，在對應那列的名稱輸入框修改。改完波形左邊會立即同步。

模擬結果可以直接當成真機規格嗎？▼

不建議。本工具是依參數推算的理想波形，用來驗證時序邏輯關係，不包含真實電路的 RC 延遲、負載效應、製程偏差與雜訊。它能幫你在上機前找出時序設定的錯誤，但電氣特性仍需以實機量測與正式規格文件為準。

「LA分析器」頁籤呢？▼

LA分析器是完整獨立的邏輯分析儀功能，已收錄於本手冊第 13–18 章：簡介與快速開始、取樣與觸發設定、工具列、波形區與通道欄、右側面板與協定解碼、硬體連線與裝置支援包。

LA：一進去就有波形，可是我根本還沒接線？▼

那是示範波形——沒有任何擷取資料也沒有匯入檔案時，工具會依你選的取樣率與深度生成一段假訊號，只為了讓版面不是空白。它沒有任何量測意義。確認方式：右側「解碼結果」若停在「等待 analyzer decode data」、且頁首沒有匯入檔名，看到的就是示範波形。

LA：某條通道整條都是平的，是沒訊號還是設定錯？▼

先看該通道名稱欄最右邊的燈：沒亮綠且顯示 0 或 1，代表這條線在整段擷取中沒有任何邊緣變化。依可能性排查：

  1. 門檻電壓設錯——量 1.8 V 訊號卻留在 2.5 V 檔（Vth 1.25 V）尚可，但若留在 5 V 檔（Vth 2.5 V）就會恆為 0。這是最常見的原因。
  2. 探棒沒接到、地線沒接。
  3. 該通道沒有被啟用（用 CH0-15 或設定面板勾選）。
  4. 訊號真的沒有動作（例如受測物尚未進入該狀態）。
LA：按單次擷取沒有反應，或跳出要我匯入 zip？▼

實際擷取需要三個條件：桌面版 Chrome／Edge、網頁在 https 下開啟、裝置沒有被原廠軟體占用。第一次使用還要匯入一次裝置支援包（見第 19 章），匯入後會自動接續剛才的擷取。若提示「裝置被其他程式占用」，請先關閉原廠軟體再按硬體連線 ⏻。

LA：解碼結果一片紅，是面板真的有問題嗎？▼

先排除解碼器設定問題再下結論：

  1. 通道指派錯了——SDA／SCL 或 AUX 通道選到別條線。通道名稱欄會顯示分析器角色，對一下就知道。
  2. DP AUX 的 Bit Rate 被改過——應為 1,000,000。
  3. 極性相反——把 Polarity 改成 Invert 試試。
  4. Tolerance 收太緊——訊號邊緣抖動大時先放回 25%。
  5. 以上都正確才是真的異常。點 Type 欄的徽章可以看到該筆被判為異常的具體理由。
