1About this tool

Draw the differential waveform that the iSP interface is supposed to produce, so you can compare it directly with what you measure on the scope. It also works the other way round: type in the 9 bits you measured and the tool tells you which control code or which gray level it is.

What it does

  • Forward - set the mode and the pixel values, and it builds the bit sequence for a whole line: BK, BAC, POL, data, EOL, each segment labelled with a color and a name.
  • Reverse - enter a 9-bit waveform and it matches it against the three possible readings: Command, DLL Data and PLL Data.
  • Every encoding is 8B9B: 8 bits of data go out as 9 bits, with one lookup table for DLL and one for PLL.

Three things to get straight first

  • Bit order is LSB-first: b0 sits at the far left of the waveform, b8 at the far right. Reverse the hex values from the datasheet before you compare.
  • DLL and PLL differ only in BK: among the control codes only BK has two different encodings, while BAC / POL / SET / EOL are identical. The data side uses two completely different LUTs.
  • There is no Calculate button: change any setting and the waveform redraws immediately.

2Quick start

Match the mode

First set the four items in Mode Settings to match the real IC: Source Driver Bits, Pair Count, Data Zone Encoding and BK Zone Encoding. Pick the wrong encoding and the whole bit sequence comes out different.

Set the pixels to send

Solid Color is the simplest choice: give R/G/B one gray level each and set Pixel Count to 2–4 for now, so the waveform stays short and easy to compare.

Read the waveform and the frame info

Above the waveform you get the segment order of the whole line (BK BAC POL+ R1 G1 B1 … EOL) and the total bit count. Every segment carries a color and a name.

Zoom in to compare

Use the + / − buttons on H-Zoom until single bits are visible, or press Fullscreen. Click the Overview below to jump to a position.

Look it up the other way

Measured 9 bits on the scope that you do not recognise? Scroll down to Waveform Reverse Lookup, type the name in the search box or simply tick b0–b8, and the three result lines tell you what it is straight away.

3Mode Settings

Six settings decide what bits a given pixel value turns into. → Open this card in the tool

ControlTypeOptions / defaultDescription
Source Driver BitsRadio buttons6 / 8 (default) bitsDecides how the data segment is assembled. 8-bit: each pixel sends three bytes, R, G and B. 6-bit: each pixel is 18 bits (6 each for R/G/B); once concatenated the stream is re-sliced into a byte every 8 bits before encoding, which is why segment labels such as R1+G1 span two fields.
Pair CountRadio buttons1 pair (default) / 2 pairWith 2 pair the screen shows two waveforms, one above the other (Pair 0 / Pair 1), and the pixel data is handed to the two of them in a cycle of 3 slots (see chapter 4).
Data Zone EncodingRadio buttonsDLL-based (default) / PLL-basedWhich 8B9B lookup table the data segment uses. The two tables are two completely different mappings, so the same gray level encodes to different 9 bits.
BK Zone EncodingRadio buttonsDLL-based (default) / PLL-basedAffects only the BK control code. The PLL version of BK is an alternating, clock-like pattern for the PLL to lock onto; the DLL version is a different fixed pattern. All the other control codes are the same in both.
ScramblerRadio buttonsOff (default) / OnWhen it is on, the data is XORed with a key from an LFSR before encoding (this breaks up runs of identical values and lowers EMI). While it is on, the data segments on the waveform are marked as scrambled.
Initial KeyText input16-bit hex, default FFFFOnly appears when Scrambler is set to On. It has to match the initial value on the IC side, otherwise the waveforms will not line up.
BKPOLRadio buttonsON (default) / OFFWhen it is on, a VBK segment is added at the end of the frame: BK · BAC · BKPOL± · BK. This segment follows EOL and carries no EOL of its own. Click the BKPOL color block on the waveform to switch it between positive and negative.
How the Scrambler works A 16-bit LFSR (Galois form, polynomial x¹⁶+x⁵+x⁴+x³+1) that advances once per pixel sent; bit i of each byte is XORed with the matching key bit before it goes into the 8B9B encoder. So the same gray level draws a completely different waveform with the Scrambler on and off - check this item first when things do not match.

Control codes at a glance (9-bit, LSB-first)

The bits in the table below read left to right exactly as they appear on the waveform.

Control codeb0…b8Purpose
BK（DLL）1 0 0 0 0 1 1 1 1Blanking filler code, DLL version.
BK（PLL）0 0 1 0 1 0 1 0 1Blanking filler code, PLL version, with a clock-like pattern that makes it easy for the PLL to lock.
BAC0 1 1 1 1 0 0 0 0Command start code; the real command follows it.
POL+0 1 1 0 0 1 1 1 1This line has positive polarity.
POL−1 0 0 1 1 0 0 0 0This line has negative polarity.
SET1 0 0 0 0 0 0 1 1Identifier for the Setting line, followed by the REG data.
EOL0 1 1 1 1 1 1 0 0End of one line.
BKPOL+0 1 1 1 0 1 1 1 1Polarity command for the VBK segment (positive).
BKPOL−1 0 0 0 1 0 0 0 0Polarity command for the VBK segment (negative).
Positive and negative codes are inverses of each other Every bit of POL+ and POL−, and of BKPOL+ and BKPOL−, is exactly opposite. The quickest way to tell the polarity apart on the scope is the first bit: starting with 0 is positive, starting with 1 is negative.

What "Repeat sub-pixel count" means It sets how many consecutive sub-pixels share one gray level before the value changes. Set it to 3 and you get R = G = B, so the gray level changes once per pixel (a gray gradient); set it to 1 and every sub-pixel differs (a color gradient).

How the data is split across 2 pair

Each pair is a complete line in its own right (each has its own BK / BAC / POL / EOL); only the data segment is split. The cycle is 2 pixels long and has 3 slots:

SlotPair 0Pair 1
Slot 1R (pixel 1)G (pixel 1)
Slot 2B (pixel 1)R (pixel 2)
Slot 3G (pixel 2)B (pixel 2)

So Pair 1 is not "the second half of the pixels"; it carries the sub-pixels interleaved with Pair 0. Put the two side by side when you measure to see the complete data.

How the whole line is assembled

Depending on the settings, the waveform holds up to three segments from top to bottom:

Data line: BK×n · BAC · POL± · data… · EOL · BK×m
↓
Setting line (optional): BK×n · BAC · SET · REG0…REGn · EOL · BK×m
↓
BKPOL segment (optional): BK×n · BAC · BKPOL± · BK×m
The BKPOL segment has no EOL It is the VBK command that follows EOL, and it carries no EOL of its own. Seeing BAC followed straight by BKPOL and then back to BK on the scope is correct, not something missing.

8Waveform Reverse Lookup (8-bit)

Measured 9 bits you cannot read? Type them in and the tool matches them against the control codes and both data tables at once. → Open this card in the tool

Three ways to enter it

MethodActionDescription
Waveform name searchText inputType BK, BAC, BKPOL+, L0, L255… and pick an entry from the list; the 9 bits fill in automatically. Control codes, DLL gray levels and PLL gray levels are all in the index, and entries with the same name are listed separately (BK, for instance, has one DLL entry and one PLL entry).
Tick b0–b8CheckboxNine checkboxes below the waveform; ticking one means that bit is 1.

How to read the result

FieldContentsDescription
9-bit valueFor example 0x10F (100001111)Inside the brackets is the LSB-first display, matching the waveform from left to right; the hex outside the brackets is the ordinary numeric form.
CommandName of the matching control codeMatched against every control code plus the PLL version of BK. Several matches are listed side by side with /. No match shows —.
DLL DataFor example L128 (0x80)Looked up in the DLL table, which gives you the gray level.
PLL DataFor example L64 (0x40)Looked up in the PLL table.
All three lines having a value is normal The same 9 bits can match a control code and also sit in one of the data tables. To decide what it really is, look at its position in the waveform: what follows BAC is a command, what sits between POL and EOL is data. The tool only tells you what the possibilities are.
Why it says "8-bit" The reverse lookup is built on the byte ↔ 9-bit mapping, and that mapping has nothing to do with 6-bit or 8-bit mode (6-bit only differs in how the bytes are packed upstream). So the tool works in 6-bit mode just as well; the Lx it returns is simply the packed byte value rather than the gray level of one color.

9FAQ

Click a question to open the answer.

The waveform I get does not match what the scope shows?▼

Work through the likely causes:

  1. The wrong Data Zone Encoding (DLL ↔ PLL) - the whole data segment comes out different. This is the most common cause.
  2. The Scrambler state does not match, or the Initial Key differs from the IC side.
  3. The wrong BK Zone Encoding - only the BK segments differ, everything else is right. "Only the blanking is off" points straight at this one.
  4. The bit order is being read backwards - both this tool and the scope are LSB-first (b0 on the left), so hex from the datasheet has to be reversed before you compare.
  5. Source Driver Bits or Pair Count does not match the real setup.
Why do segment names turn into things like R1+G1 in 6-bit mode?▼

Because 6-bit data is not packed one color at a time. Each pixel is 18 bits (6 each for R/G/B); after concatenation a byte is cut every 8 bits and then 8B9B encoded - so the cut naturally lands in the middle of a color. One byte can therefore hold the back half of R1 and the front half of G1, and the label is written R1+G1. That is the correct packing, not a display error.

In 2 pair mode, why is Pair 1 not the second half of the data?▼

iSP 2 pair is interleaved, not cut in half. Over a cycle of 2 pixels, Pair 0 sends R1, B1 and G2 while Pair 1 sends G1, R2 and B2. Put the two side by side to see the complete picture. The table in chapter 4 has the details.

The waveform is too long to make out single bits?▼

Three ways to fix it: turn Pixel Count down (2–4 is enough to read the encoding), zoom in step by step with H-Zoom + (1.4× per press, up to 12×), or press Fullscreen and zoom there. Press Fit to get the whole picture back, and click the Overview below to jump to a particular position.

I filled in REG values, but I cannot see my numbers on the waveform?▼

REG data goes through 8B9B encoding as well, so the waveform shows the encoded 9 bits, not the original byte. To check that the encoding is right, type the 9 bits of that segment into Waveform Reverse Lookup and see whether DLL / PLL Data gives back the value you filled in.

How do I switch POL between positive and negative?▼

No need to hunt through the settings card - click the POL color block on the waveform and it swaps between positive and negative. The BKPOL color block works the same way, and the two are independent. After the switch, the frame info line and the whole bit sequence update immediately.
