1工具簡介

這是一支不預設對面是什麼晶片的 I2C 讀寫工具：任意 slave 位址、任意 offset、任意長度，讀回來攤成 16×16 表格，可以就地改值、跟另一份資料逐 byte 比對、再一次寫回去並自動回讀驗證。

它解決什麼問題

  • 看得到整片內容 — 一次讀最多 262,144 byte（256K），分頁呈現，每頁 256 byte。
  • 改了什麼一目了然 — 兩份資料（A／B）同時在手上，不同的格子會上色，差異清單逐筆列出「位址 / Data A / Data B」。
  • 寫進去不必猜 — 寫完自動回讀同一段，逐 byte 比對，不一致的格子標紅並列出位址。
  • 不擋路 — 沒有位址白名單、沒有「允許寫入」開關。所有讀寫都完整記在畫面的操作紀錄與 I2C Bridge 的記錄檔裡。

它不做什麼

  • 不替你判斷對面是什麼 — 除了 EEPROM 的容量確認之外，工具不猜晶片型號、不套暫存器定義。
  • 不自動寫 — 除了你按下「寫入」或就地改一格（已連線時）以外，沒有任何路徑會送出寫入。
  • 不記住你的資料 — 關掉分頁，dump 內容就沒了；要留就用「另存新檔」。
瀏覽器為什麼碰不到治具 USB 轉 I2C 的治具由驅動層綁定，瀏覽器沒有任何一條路可以直接存取它。所以這一頁必須搭配一支在你電腦上執行的小程式（I2C Bridge），由它代為操作治具，網頁透過本機的 WebSocket 跟它講話。

2取得與啟動 I2C Bridge

連不到的時候，畫面上第一個出現的就是下載按鈕，版本號直接印在按鈕上。

下載

按畫面上的「⬇ 下載 I2C Bridge 版本」。按下去會跳一個三行的說明視窗，照著做即可。

整包解壓到同一個資料夾

包內是四個檔：i2c-bridge.exe、libMPSSE.dll、ftd2xx.dll、DLL_I2C_BCB.dll。四個必須在同一個資料夾，少一個就起不來。

雙擊 i2c-bridge.exe

第一次執行 Windows 會擋一次（程式內容一變，雜湊就變，所以每次換版都會再擋一次）。黑視窗留著不要關，它就是那條通道。

回到這一頁

頁面會自動嘗試連線，通常不必按任何東西。沒自動連上就按一下「連線」。

黑視窗最後一行是一個大寫字母 G ＝ 一切正常。不是 G 的時候，把整份 i2c-bridge.log 留下來，字母的意思由工具的維護者查 —— 這一頁刻意不把對照表印給使用者看。
項目型別範圍／選項說明
下載 I2C Bridge按鈕—連不到時自動出現。版本號印在按鈕上，來源是工具的版本單一來源檔，不是寫死在這一頁。
I2C Bridge 資訊與疑難排解摺疊卡—收在診斷模式裡。內含 zip 與 exe 的 SHA256、四個檔的清單、常見連不上的原因。
SHA256 zip / exe唯讀顯示—下載回來要核對的話比這兩個值。exe 內容一改 SHA 就變，Windows 也會再擋一次。
瀏覽器問你要不要「允許存取本機網路」時請按允許 從公開網址連本機（127.0.0.1）時，新版瀏覽器會先問一次權限。按了封鎖或把提示關掉，連線就不會成立，而且畫面上看起來跟「程式沒開」一模一樣。這一頁分得出來這兩種：慢到幾百毫秒才失敗的那一種，會另外顯示一行「請按允許」與一顆重試鈕。

3連線

連線是一顆開關：連上是綠的，斷開是灰的。旁邊那一行小字是對面那支程式的版本與協定版本。

控制項型別範圍／選項說明
連線 / 已連線開關—同一顆按鈕負責兩個方向。按掉不只是斷線：它會同時把治具交回去，別的程式就能用。
連線狀態燈唯讀顯示—燈號＋一句狀態。常見的有「未連線」「連不到 I2C Bridge」「已連線（本頁持有 I2C）」「I2C 在另一個頁面」。
I2C Bridge x.y.z · proto n唯讀顯示—連上之後才有字，未連線時是空的。proto 是雙方講的協定版本，有些新功能要對面夠新才有（見下方）。
I2C 時脈（kHz）文字輸入＋下拉下拉 50 / 100 / 200 / 400 / 1000；手動不設上限常用值放在下拉裡，也可以直接打。下方小字會印出實際會得到的頻率（見下面那段陷阱）。改完要重新連線才生效。

時脈：整數除法的陷阱

治具端換算頻率用的是兩次整數除法：

divisor = (12000 / kHz) / 2 − 1　（兩個除法都取整） 實際頻率因此是 12000 / (2 × (divisor + 1)) kHz。它不檢查輸入、也沒有檔位表：任何值都收，不整除的值會被默默算歪。
你填的值型別divisor實際頻率
400kHz14400 kHz　✔ 剛好整除
350kHz16352.94 kHz　← 不是你填的那個數字
100kHz59100 kHz　✔

所以下方小字一律把實際值算出來給你看 —— 對不上你填的數字時，它會標紅。這比任何警告都有用。

同一時間只有一個頁面握著治具 切到哪一頁，哪一頁就自動接手，不必按任何東西。對方正在量測時不會被搶走。要把治具交回去給別的程式，就按掉連線開關。

4讀寫參數（讀與寫共用同一組）

讀取與寫入共用同一組 slave 位址、offset 寬度與起始 offset。四個群組由左至右：① Slave 位址　② Offset　③ 總 byte 數　④ 對裝置。

① Slave 位址：7-bit 與 8-bit 的關係

三格是同一個位址的三種寫法，改任何一格，另外兩格立刻跟著變。

控制項型別範圍／選項說明
7-bit（實際送出）文字輸入＋下拉0x00–0x7F；下拉常用值 0x68 / 0x50 / 0x3E / 0x7C / 0x7D這一格才是真正送到匯流排上的值，所以它是被強調的那一格。
8-bit write文字輸入0x00–0xFF，偶數＝ 7-bit << 1。打了奇數會當場改成偶數並顯示修正後的值（不是偷偷換掉一個你看不到的東西）。
8-bit read文字輸入0x00–0xFF，奇數＝ (7-bit << 1) | 1。打了偶數會補上最低位並顯示修正後的值。
為什麼有兩套寫法 I2C 在匯流排上送出的第一個 byte 是「7 位位址 ＋ 1 位讀寫方向」。有些資料手冊直接把那整個 byte 寫成位址（所以同一顆會出現「寫 0xD0、讀 0xD1」兩個數字），有些只寫 7 位（0x68）。三格並排是為了不管手冊用哪一種寫法，你都可以直接照抄。

② Offset：寬度與起始位址

控制項型別範圍／選項說明
寬度（byte）文字輸入＋下拉下拉 0 / 1 / 2 / 4（預設 2）；手動可填 3位址相位要送幾個 byte，高位在前。填 5 以上會在送出前被擋下。
起始 offset文字輸入0 – 該寬度能表示的上限從哪個位址開始讀／寫。純數字當十六進位；要用十進位就加 d（如 80d）或加 # 前綴（如 #80）。
寬度型別位址相位這一格的意思
0byte沒有位址相位「起始 offset」那一格不再是位址，而是要寫出去的那 1 個 byte（標籤會跟著改成「寫入值（1 byte）」）。讀取則是從頭讀，表格的列標頭印的是索引（#0…）而不是位址。
1byte1 byte0x00 – 0xFF
2byte2 byte（預設）0x0000 – 0xFFFF
3byte3 byte（24 位元）不在下拉裡，手動打 3 才有。對面的 I2C Bridge 太舊時，小字會先告訴你它不吃。
4byte4 byte0x00000000 – 0xFFFFFFFF

③ 總 byte 數

控制項型別範圍／選項說明
總 byte 數文字輸入＋下拉1 – 262144（256K）；下拉常用值 4096 / 8192只管讀取。下方小字印出會分成幾頁、會切成幾則傳送。
這一欄不是寫入的前提 寫入要寫多少，由表格上那份資料自己決定（或你選取了哪幾格），跟這一欄完全無關。曾經有一版把兩者綁在一起，結果「讀 256 之後載入 8192 的檔」按鈕直接鎖死 —— 那是錯的，現在兩件事分開。

5讀取，與 A／B 兩份資料

按「讀取」把資料抓回來攤在 16×16 表格上。這一節最重要的是 A 與 B 到底是什麼 —— 搞清楚它，畫面上其他東西都會跟著合理。

A 與 B

  • A ＝ 比較基準（快照）。它是一份獨立的複本，只有在「重建 A」的時候才會變。
  • B ＝ 現在手上這一份，也就是表格上顯示、按下寫入會被寫出去的那一份。
  • 兩份都有內容時，點 A 或 B 那一行就切換看哪一份；看 A 的時候是唯讀的（它是基準，不該被改）。
發生什麼事型別AB ／ 來源標籤
第一次讀取狀態← 讀到的清空；A 的來源標成「讀取 slave 0x·· · 0x···· 起」
第一次載入檔案狀態← 檔案清空；A 的來源就是檔名
已有 A，再載入檔案（長度相同）狀態不動← 檔案；B 的來源是檔名
已有 A，再讀取（長度相同）狀態不動← 讀到的；B 的來源是「讀取」
改了任何一格狀態不動← 改完的內容；B 的來源是「A 的修改」
按「快照 A」按鈕← 目前內容清空，差異清單歸零；A 繼承目前的來源
長度不一樣（讀取或載入都一樣）狀態← 後者清空；舊的來源標籤消失
換 slave ＋ 讀取狀態← 新讀到的清空
兩條容易誤會的規則 ①「換 slave」本身不會清掉 A —— 要換了而且讀取才會。你可能只是切過去看看。
② 只要 A 被重建，B 就自動清空。A、B 是一組，不會出現「新的 A 配舊的 B」這種比不了的狀態。

讀取相關的控制項

控制項型別範圍／選項說明
讀取按鈕—依 ①②③ 的參數抓資料。長讀取有進度與中止鈕；中止會停在下一個分段邊界，並回報讀到哪裡。
快照 A按鈕—把目前內容存成 A 當比較基準。副作用寫在提示裡：B 會被清空、差異清單歸零。
另存新檔按鈕＋下拉.hex / .bin / .txt / .rom讀多少存多少。.hex 是 Intel HEX（每列 16 byte）。不需要連線，讀完拔線也能存。
載入檔案按鈕.bin .hex .txt .rom .ihx .ihex .eep .dat .raw自動辨識格式：Intel HEX、帶位址的 hex dump、純 hex 文字、raw binary。Intel HEX 的位址跳躍處會補 0xFF 並在紀錄裡說補了幾個。
清空按鈕—回到「完全沒有資料」的狀態。連線與參數保留，可以接著做下一輪比對。
頁碼（0x ▢▢▢ 00）文字輸入＋上下鍵—256 byte 一頁。最左的 0x 與最右的 00 是固定的，只有中間可以填。
跳到（表格左上角）文字輸入—頁內任意位址定位並畫十字。位址不在當前頁時會先自動翻頁。
整片讀回來都是 0xFF 的意思 I2C 匯流排閒置時就是高電位。整片 FF 通常代表沒有人回應，而不是「資料真的是 FF」。先確認 slave 位址、板子有沒有供電、治具有沒有接好。另外，如果讀回來的內容每 N byte 完整重複一次，那通常是超過裝置容量、位址回捲到 0 —— 循序讀不會報錯，只會一直重複，所以這一頁會主動提醒。

6編輯、選取與搜尋

表格不只是拿來看的。每一格都可以就地改值；已連線時改一格就是真的寫一格（而且會立刻回讀驗證），未連線時只改本地並標成「尚未寫入」。

一格三層

每一格最多有三個數字：中間的大字是主值（按下寫入會被寫進去的那一個），左上角小字是快照值 A，右上角小字是被換出去的值 B。左上與右上絕不會同時出現：

狀態型別主值角落
狀態 1（改過值之後）狀態B（新值）左上 ＝ A（快照值）；右上空
狀態 2（點了左上之後）狀態A（快照值）左上空；右上 ＝ B（被換出去的新值）
A 與 B 相等狀態那個值兩角都空（沒有可切換的東西）
點角落也會真的寫進裝置 在已連線、而且這一格不是「改過還沒寫」的狀態下，點角落還原＝真的要改裝置 ⇒ 會送出寫入並回讀驗證。如果那一格的改動本來就沒送出去過，點角落只動本地、不發任何傳輸。

編輯一格

操作型別按鍵會發生什麼
進入編輯滑鼠單擊一格選中＋畫十字＋直接進入編輯。
打字鍵盤十六進位字元只顯示、不生效；湊滿兩位也不會自動送出。打滿兩位再打會往左移位（像計算機）。
生效鍵盤／滑鼠Enter，或離開這一格只打一位當作高位補 0（A ⇒ 0A）。已連線 ⇒ 寫入＋回讀；未連線 ⇒ 只改本地並標示尚未寫入。
放棄鍵盤Esc值回復原狀。
位元（bit 7–0）核取方塊—側欄會列出所點那一格的 8 個位元，勾／取消就直接改值，走的是與手動改格完全同一條路徑（同樣會寫入、同樣會回讀驗證）。
offset 寬度 0 時不能逐格寫 沒有位址相位就沒辦法指定要寫哪一格。這個模式下請改用上方的「寫入資料」欄。

選取要寫哪些格子

操作型別按鍵會發生什麼
連續選取滑鼠／鍵盤Shift ＋ 點擊，或 Shift ＋ 方向鍵選的是線性位址區間（不是矩形）。在 0x00 點一下再按 Shift＋下，選到的是 0x00 一直到 0x10 共 17 格。
跳躍選取滑鼠Ctrl ＋ 點擊可以挑不相鄰的格子，而且支援跨頁。再 Ctrl＋點同一格就是取消那一格。
取消選取滑鼠普通單擊任一格跳躍選取整個清掉。
選取清單唯讀顯示—側欄最上面逐段列出選了哪些位址：連續段印起訖，跳躍選取每一段一行。標題列同時印總 byte 數與段數。
跳躍選取會逐段重下位址 不相鄰的區段之間，位址沒辦法靠自動遞增走過去。所以每一段都會各自重下一次 slave address ＋ offset —— 寫入是這樣，寫完的回讀驗證也是這樣。按鈕上會直接寫出「寫入 選取的 N byte · M 段」，操作紀錄裡也會逐段列出。

搜尋

控制項型別範圍／選項說明
搜尋輸入格文字輸入—找連在一起的那幾個 byte。輸入格式與「寫入資料」同一支解析器：61 41 B4、0x61,0x41、A1h、6141B4 都吃。半個 byte 一律拒絕，不臆測。
全部範圍 / 本頁單選鈕二擇一「本頁」的定義是整段都要落在本頁 256 byte 之內；跨頁的命中留給「全部範圍」，這樣同一筆才不會被數兩次。
▲ / ▼按鈕—上一筆／下一筆，兩端都循環。跨頁的命中會自動翻頁並畫十字。

7寫入、EEPROM 與驗證

按鈕上永遠寫著這一下會寫哪一份、多少 byte。寫完自動回讀同一段、逐 byte 比對，結果放在畫面最上面。

寫入來源：以中心值為準

寫出去的是表格上每一格的主值（中間那個大字），不是「總 byte 數」那一欄、也不是原始檔案。優先順序：

有選取 ⇒ 只寫選取的那幾格

按鈕上寫「寫入 選取的 N byte」；多段時再加上「· M 段」。

沒有選取 ⇒ 寫目前顯示的那一整份

按鈕上寫「寫入 A／B · N byte」。按鈕裡不放檔名（檔名在 A／B 那兩行，放兩次只是重複，而且長檔名會把按鈕撐爆）。

offset 寬度 0 ⇒ 只寫 ③ 的那 1 byte

沒有位址相位，這是這個模式下唯一能寫的東西。

EEPROM：page 與段間距

控制項型別範圍／選項說明
Page 大小下拉8 / 16 / 32 / 64 / 128 / 256 B，或「不分段」EEPROM 的 page write 有硬體上限，跨頁的連續寫會在頁內回捲，結果是靜默寫錯。選小一定安全（只是慢），選大才會出事。
目標段間距文字輸入毫秒；預設 5這是匯流排上量得到的段與段之間的距離，不是「額外睡多久」。固定開銷由 I2C Bridge 自己每段量、自己扣掉。
段間距是裝置的規格，不是可以隨便調小的參數 EEPROM 收到一段資料之後要花時間把它真正寫進記憶體（tWR，內部寫入週期）。這段期間它不回應。等不夠就會靜默寫不進去 —— 不會有錯誤、不會有提示，回讀才會發現。填低於 5 ms 時畫面會標紅提醒；常見的 24C32／24C64 是 5 ms，較舊的 AT24C32 要 10 ms。
slave 落在 0x50–0x57 時會先問型號 那八個位址是 I2C EEPROM 的慣例位址。寫之前會跳一個視窗請你選型號（不是 page size）—— 因為你知道手上這顆是 24C32，但不見得記得它的 page 是幾 byte。選了型號，page 由系統填，不可能選錯。同一個 slave 只問一次；重新連線或這次要寫的範圍超過已確認的容量時會再問。

寫完的回讀驗證

  • 寫完自動回讀同一段，逐 byte 比對。跳躍選取則逐區段回讀，每段各自重下位址。
  • 完全一致 ⇒ 綠底一行「寫入與回讀完全一致：驗證 N byte，全部相同」。
  • 有不一致 ⇒ 紅底列出幾個 byte 不同，前幾筆直接印出「位址：寫 0x·· 、讀回 0x··」，其餘在下方的操作紀錄裡；表格上那些格子會標紅。
  • 讀不回來 ⇒ 明講「無法確認有沒有燒進去」，不會假裝成功。
  • 寫到一半失敗或中止 ⇒ 會講清楚哪一段位址已經寫進去、哪一段之後完全沒寫，也就是裝置上現在是一份半更新的內容。

差異清單與總和檢查碼

控制項型別範圍／選項說明
差異（位址 / Data A / Data B）唯讀顯示—只列有差異的位址，相同的不列。點一列會跳到 dump 的對應位址並畫十字 —— 它只定位、不改值，改值請在 dump 上做。
重新比較按鈕—用目前的 A 與 B 重新比一次。兩份不可比（長度／slave／offset 不同）時會講出來。
checksum（A 列／B 列各一）唯讀顯示—把整份資料的每一個 byte 相加，不取模、不截斷，十六進位顯示，位數依實際值自然增長。算的是中心值（也就是會被寫出去的那一份），任何一格一改就立刻重算。
耗時紀錄唯讀顯示—每一次讀寫的 byte 數、總耗時、走的路徑與結論。同一次操作的幾筆會框成一組，方便前後比較。
操作紀錄唯讀顯示—每一筆讀寫的 slave、offset 寬度、位址與 byte 都完整記著。可以一鍵複製整份。
checksum 為什麼不截斷 有些工具會把總和取 16 位（% 0x10000）。這一頁刻意不這麼做：檔案大到 256K byte 時，加到多少就是多少。實測用兩個檔名本身就帶著總和的真實檔案交叉驗證過，截斷的話那兩個值就對不上檔名了。

8常見問題

點問題展開答案。

一直「連不到 I2C Bridge」，可是我明明開著它▼

三種可能，依序排除：① 瀏覽器的「允許存取本機網路」被拒了 —— 這一頁分得出來，那一種會另外顯示一句「請按允許」與重試鈕；② 黑視窗最後一行不是 G，代表它自己沒起來，留下 i2c-bridge.log；③ 四個檔沒放在同一個資料夾。

讀回來整片都是 FF▼

那通常不是資料，是沒有人回應（匯流排閒置就是高電位）。先確認 slave 位址對不對、板子有沒有供電、治具有沒有接好。想快速確認整條路通不通，可以在診斷模式下按「自檢（黃金向量）」。

寫了但是沒寫進去，也沒有任何錯誤▼

寫 EEPROM 時這幾乎都是段間距太短：裝置還在做內部寫入就收到下一段，它不回應，而連續寫不會報錯。把「目標段間距」拉到 5 ms 以上（舊款 10 ms），Page 大小也不要選得比實際大。回讀驗證就是為了當場抓到這件事。

我填 350 kHz，小字卻說 352.94▼

正常。頻率是用兩次整數除法換算的（divisor = (12000 / kHz) / 2 − 1），不整除的值會被默默算歪。小字印的是實際會得到的頻率；要剛好就挑能整除的值（50 / 100 / 200 / 400 / 1000）。

差異清單突然變成 0，可是資料明明不一樣▼

代表兩份不可比（長度、slave 或起始 offset 不同），這時後來那一份會成為新的 A，比對停用。操作紀錄裡會有一行說明為什麼。要重新建立基準就按「快照 A」。

表格上的格子點不動、改不了值▼

三種情形：① 目前顯示的是 A（基準），它是唯讀的 —— 點下面那一行切回 B；② offset 寬度是 0，沒有位址相位就沒辦法逐格寫；③ 正在跑一次 I2C 傳輸（忙碌中）。未連線不會擋你編輯，那是刻意的：離線先把值編好，連線之後一次寫進去。

讀回來的內容每隔一段就完整重複一次▼

通常是讀過了裝置的容量，位址回捲到 0 又從頭讀一次。循序讀不會報錯，只會一直重複，所以這一頁偵測到週期就會主動講一句。把總 byte 數調到實際容量以內即可。

另一個分頁把治具搶走了▼

同一時間只有一個頁面握著治具。切到哪一頁，哪一頁就自動接手，不必按任何東西 —— 但對方正在量測時不會被搶走，那時畫面會講「等它跑完就能用」。

切了語言，可是操作紀錄裡舊的那幾行沒有跟著變▼

刻意的。操作紀錄是帶時間戳的流水紀錄，每一行記的是「那一刻發生了什麼」，所以它保留當下的語言；切語言之後新產生的每一行都會是新語言。畫面上其他所有東西（按鈕、欄位、提示、橫幅、耗時紀錄、A／B 兩列）都會立刻跟著換。
