1工具简介

面板信号仿真与取样是一个纯网页的时序波形仿真器，让你不必接上真实面板，就能把 TCON 的 Phase Counter 参数变成看得见的波形。

它在做什么？

TCON（Timing Controller）内部用一组寄存器参数描述每一条输出信号「什么时候拉高、什么时候拉低」。这些参数（ACT_TYPE、R_PH、F_PH、ST_LINE、SP_LINE、R_DLY、F_DLY…）彼此耦合，光看数字很难想象实际波形长什么样子。

本工具把这组参数实时算成波形画在画面上，你改一个数字，波形立刻跟着变。可以用来：

  • 练习与教学 — 理解 Phase Counter 各参数对波形的实际影响
  • 事前验证 — 在烧录到真机之前，先确认时序关系是否正确
  • 测量演练 — 用内建的光标、脉冲计数、即时测量，仿真示波器/逻辑分析仪的测量动作
  • 设定交换 — 导出 .txt 设定文件或复制到剪贴板，传给同事重现同一组波形

2快速开始

第一次使用，照着这六步就能看到波形。

打开工具并确认模式

打开面板信号仿真与取样后，确认页首的模式页签停在「面板信号仿真」（默认就是这个）。

从「预设」下拉载入一组范例

左侧最上方的「预设」下拉，选 FHD 60Hz Single Gate (LS：Multi CPV)。这会一次填好系统设定、18 条数字信号、Level Shifter 设定与 18 条输出通道，画面立刻出现完整波形。建议第一次使用先从预设开始，而不是从空白慢慢建。

展开「系统设定」看时序骨架，再到「系统行为模拟」拖滑块

系统设定卡片里的 Vactive / Vblank / Hactive / Hblank / Frame Rate 决定整张画面的时间骨架（VTOTAL、HTOTAL、TCON HTOTAL、Pixel Rate 是算出来的只读值，改不动）。设好之后，到下面绿框那张「系统行为模拟」卡片拖三条滑块，看换个刷新率或加大 Vblank 会怎么样 —— 波形与所有数值实时重算。

调一条信号试试看

展开「TCON 数字信号」→ 点开 CK1 → 拖动 R_DLY 的滑块。波形上的 CK1 会实时左右位移。所有字段都是实时计算，没有「计算」按钮。

用光标测量

按键盘 1 放下光标 A1（会跟着鼠标跑），在想要的位置按一下鼠标左键钉住；再按 2 放下 A2。右侧「时基标尺」会显示两者的时间差与换算频率。

导出设定分享

工具栏「文件」区的导出会下载一个 .txt 设定文件；复制则把同样内容放进剪贴板，可直接粘贴到聊天软件传给同事，对方用粘贴就能重现一模一样的波形。手机上按粘贴时，若浏览器挡掉自动读取剪贴板，会弹出「手动粘贴设置」窗口让你自己长按粘贴进去，一样能套用。

手机也可以用 版面是手机优先设计。手机上可用单指拖拽平移波形、双指缩放；左侧参数卡片默认收起，点卡片标题即可展开。
不要期待它等于真机 本工具是依参数推算的理想波形仿真，不含模拟上升/下降的真实 RC 行为、噪声与负载效应。它用来验证时序关系，不是用来验证电气特性。

参数之间的关系

  • 🔴 VTOTAL 与 HTOTAL 是只读显示，不是输入格。你输入的是四格 ACTIVE ＋ BLANKING，total 由它们相加而来：VTOTAL = Vactive + Vblank、HTOTAL = Hactive + Hblank。想改 total 就去改那四格其中之一。
  • Htotal × Vtotal = 一张画面的总时钟数
  • Pixel Rate = Htotal × Vtotal × Frame Rate，只读。它只由这三个参数决定，把 TX DCLK 往上调并不会改变它
  • RX DCLK = Pixel Rate ÷ 2，只读显示，不能直接打字改（但可以用「系统行为模拟」卡片的 RX DCLK 滑块间接推它，那条滑块实际是在反推 Frame Rate）
  • TX DCLK 可以手动输入。v4.32.0 起下限是机种规格下限，不再是 RX DCLK —— 调低它会把 Frame Rate（进而把 RX）一起带下来，所以 TX ≥ RX 仍然恒成立。定频下改 TX DCLK 会在超过新上限时自动下调 Frame Rate（琥珀色告知）；变频下会（双向联动，见下方专节）。
  • TCON UI DCLK = TX DCLK × 机种系数，可以手动输入，与 TX DCLK 互相联动（改哪一格另一格都会立刻跟着算好）
  • TCON HTOTAL 与上面那个 HTOTAL 不是同一个数字，它另外标出来就是要你确认 —— 详见下方「两个 HTOTAL 差在哪」
  • TCON Pixel Rate = VTOTAL × TCON HTOTAL × Frame Rate，只读。它和左边的 Pixel Rate 只差在 Htotal 用哪一个，所以把 TX DCLK 往上调它会跟着变大（左边那个不会）—— 详见下方「两个 Pixel Rate 差在哪」
  • Vactive / Hactive 只影响有效显示区的位置标示，不影响总时间长度；而且它们没有任何下限保护，输入多少就是多少
🔴 两个 HTOTAL 差在哪 —— 为什么 TCON HTOTAL 被特别标成亮蓝色 同一个 H Total 框里有两个数字，很容易看成重复：

・HTOTAL（左，白字）＝ 系统端的 Htotal，就是 Hactive + Hblank，是你刚刚自己输入出来的那个值。它描述的是面板／系统这一侧一行有多长。
・TCON HTOTAL（右，亮蓝字）＝ TCON 内部实际用的 Htotal。它由左边那个值依 TX/RX DCLK 的比例换算而来：TCON HTOTAL = round(HTOTAL × TX DCLK ÷ RX DCLK)。所以两者只有在 TX ＝ RX 时才会刚好一样；一旦把 TX DCLK 拉高，右边的数字就会和左边分开。

🔴 Gate Type 不在这条换算式里。Single ⇄ Dual 切换时 TCON HTOTAL 不会变。Gate Type 影响的是 Line Buffer 与内部时序推算，不影响 TCON HTOTAL。

它不是另一个要你填的参数，是一个注明值：拿去和你手上 TCON 设定文件／官方 UI 上的 HTOTAL 对一下，对得起来才代表这组仿真和真机是同一件事。这正是它被 highlight 的原因 —— 提醒你「这一格要看一眼」，不是提醒你「这一格要改」。
🔴 两个 Pixel Rate 差在哪（卡片最下方是左右两栏） 结构和上面那两个 HTOTAL 完全一样 —— 左边白色＝系统端，右边亮蓝＝TCON 内部，而且就排在 HTOTAL／TCON HTOTAL 的正下方，上下对齐看得出对应关系：

Pixel Rate（左，白）
HTOTAL × VTOTAL × Frame Rate
・用系统端的 HTOTAL
・调高 TX DCLK 不会变
・＝ RX DCLK × 2
TCON Pixel Rate（右，亮蓝）
VTOTAL × TCON HTOTAL × Frame Rate
・用 TCON 内部的 TCON HTOTAL
・调高 TX DCLK 会跟着变大
・≈ TX DCLK × 2（差异只来自 TCON HTOTAL 取整数）
两边算出来本来就会不一样，这不是错，这正是把它们并排列出来的理由。例如：
2560×1440@120、Hblank 160、Vblank 40、TX DCLK 300 ⇒ HTOTAL 2720／TCON HTOTAL 3378 ⇒ Pixel Rate 483.072 ／ TCON Pixel Rate 599.9328。

什么时候看哪一个：要判断「这组时序对面板／信号源合不合理」看左边；要和 TCON 设定文件或官方 UI 上的内部频率对账，看右边。
从 TCON UI 抄 DCLK 之前，先确认机种 不同系列的 TCON，界面上那个「DCLK」代表的东西不一样：
・EM01 系列与所有 NB TCON（E501A / E501B / E503 / EN01）→ 系数 ×1，UI 上的数字就等于 TX DCLK
・EM02 / E512（同一系列，E512 在前、EM02 是它的改版）→ 系数 ×2，UI 上的数字是 TX DCLK 的两倍
所以在默认状态（TX DCLK = RX DCLK）下，EM02 的 UI 会显示整个 Pixel Rate（例如 148.5），EM01 则显示它的一半（74.25）。 把 EM02 UI 上看到的 148.5 直接填进 TX DCLK 会差两倍——请填在「TCON UI DCLK」那一格，并确认左边的机种选对了。

注意「UI ＝ Pixel Rate」「UI ＝ Pixel Rate ÷ 2」只是默认状态下的结果，不是恒等式。 系数是乘在 TX DCLK 上的：一旦把 TX DCLK 调高，UI DCLK 会跟着 TX 走，而 Pixel Rate 不动。
TX DCLK 与 TCON UI DCLK 是硬下限／硬上限 上下键、鼠标滚轮、输入框箭头调到界限就停住，不会再往下（或往上）走； 手动打字超出范围时会在套用前挡下并就地说明，保留原本的值， 既不会静默改成界限值，也不会先套用再弹回。

范围由两组限制叠起来：
・TX DCLK ≥ RX DCLK（一直都有的约束）
・TCON UI DCLK 的机种规格：下限一律 40 MHz（v4.33.0 起不分机种）； 上限依机种 —— EM01 432／EM02 420／E512 360／ Notebook（E501A／E501B／E503／EN01）105 MHz
两格的界限由同一份计算换算而来，所以不会出现「一格挡下、另一格放行」。

🔴 超出机种能力时，画面会直接讲出路，不必自己算要调到多少，例如：
「E503 这组分辨率最高只跑得到 90 Hz，目前是 144 Hz。请先降低 Frame Rate，VBLANK／HBLANK 才调得动。」
会出现这句话，通常是因为导入了一份超出这颗机种能力的 code／设定文件（用打字是进不到这个状态的，输入格会先挡下来）。 照着它做 —— 先把 Frame Rate 降到它说的那个数字以下，其他格子就会重新解锁。
定频／变频跟着机种走 Notebook TCON（E501A／E501B／E503／EN01）一定是定频应用，所以选到 NB 机种时 「变频应用」会变灰、不能选，并自动切回定频。
Monitor TCON（EM01／EM02／E512）两种都可能，不会去动你当下的选择。
你自己选过的形态会被记住：在 MNT 选了变频、切到 NB（被强制定频）、再切回 MNT 时， 会还原成变频，你的选择不会被机种切换吃掉。
Frame 重复数越大越吃资源 它决定要仿真几张画面（1–4096）。默认 10 张足够观察大部分时序；要看跨很多张画面的 Toggle 行为（例如 FRM_NO 周期）才需要调大。设到上千张时，第一次绘制会需要一点时间。

4-1　四张卡片各管什么，为什么这样分

这些参数分成四张卡片，让「哪些是先设好就不再动的、哪些是拿来反复试的」一眼看得出来。 卡片的顺序就是使用顺序：

顺序卡片它管什么什么时候动它
① 系统设定 Vactive／Vblank／Hactive／Hblank 四格输入，算出 VTOTAL／HTOTAL／TCON HTOTAL；Frame Rate 输入格；最下方 Pixel Rate 与 TCON Pixel Rate 两栏显示 一开始设一次。这是「这片面板长什么样」的规格，设定好之后通常整段分析都不会再动。
② 系统行为模拟
（绿框 ＋ 放大标题）		 三条滑块：Frame Rate、Vblank、RX DCLK 反复拖拽的地方。①设定完之后，「换个刷新率会怎样」「Vblank 拉长会怎样」全部在这里试。它被框成绿色就是这个意思 —— 要你来动的是这一张。
③ TCON频率设定 定频／变频应用选择；RX DCLK 显示、TX DCLK、TCON UI DCLK（含机种下拉） 对到真机的地方。把 TCON 官方 UI 上看到的 DCLK 填进来，或反过来看仿真出来的值是多少。
④ TCON 其他设定 Gate / Frame 群组（Gate Type、Frame 重复数）＋ Toggle FRM_NO（全局共用） 群组 设一次就好的全局开关。详见第 5 章。
四张卡片各自可以独立收起 只想专心拖滑块时，可以把①③④收起来，画面上只剩绿框那张。收起状态会被记住，下次打开维持原样。
分成四张卡片没有把任何东西藏起来 —— 每一格控件都在，只是中间多了几条卡片标题。

要拉更高怎么办：先到上面「TCON频率设定」卡片把 TCON UI DCLK 调高，这条滑块的右端就跟着变高；调低则跟着变低。往下拉永远不会被挡。

红色什么时候出现：只有因为你设的 TCON UI DCLK 而停住时才转红（＝还有救，去把它调高就好）。若是顶到机种规格上限（例如 EM01 已经设到 432），维持原本的绿色 —— 那个上限你调不动，讯息会叫你改分辨率或换机种。离开上限后颜色自动变回绿色。

同一张卡片的 Vblank 滑块维持绿色：它守恒 Pixel Rate（DCLK 一个位数都不会变），不会踩到这条上限。RX DCLK 滑块则会跟着 Frame Rate 一起转红 —— 它的两端本来就是由 Frame Rate 的区间反推的，「RX 顶到右端」与「Frame Rate 顶到右端」是同一件事。

🔴 「变频应用」一样套这条上限（v4.32.0 起）。变频指的是 TX DCLK 跟着 RX 走，不是 TCON 的能力跟着长 —— 那颗 TCON 被设定的 UI DCLK 仍然是一个固定值。所以变频下拉 RX DCLK 或拉 Frame Rate 把 TX 推上去，一顶到你设的 TCON UI DCLK 就停住并转红。
上限读的是你主动设定过的那个 TCON UI DCLK（在 TX DCLK／TCON UI DCLK 两格或它们的滑块上动过的值），不是此刻画面上跟着 fps 跑的那个数字 —— 否则上限会等于当前值，滑块就永远动不了。还没设定过就不套上限（＝机种规格上限）。
🔴 把 TCON UI DCLK 调低时，Frame Rate 会自动跟着降下来（v4.32.0 起） 规则是「所有数据都不能超过 TX DCLK」，而且两个方向都成立：
・你把 Frame Rate／RX DCLK 往上推 ⇒ 顶到 TCON UI DCLK 换算的上限就停住并转红；
・你把 TCON UI DCLK 往下调（天花板往下移）⇒ 超过新上限的 Frame Rate 会自动跟着降到新上限，并在下方显示一则琥珀色告知（「Frame Rate 已自动从 300 Hz 降为 282 Hz…」）。

v4.31.5 为止的做法是挡下这个输入、叫你自己先去把 Frame Rate 降下来 —— 本版改成连动，不再挡。

只有 Frame Rate 会被动到。V-Blanking／H-Blanking／H-Active／V-Active／分辨率一个字都不会改。降到的目标值就是新上限（取整数），不会多降。

拖滑块时是连续跟着降的，不是放开手才跳一次 —— 这样过程中不会出现「已经超过上限」的中间状态。

那什么时候还是会被挡 —— 两道，取较高者：
・机种规格下限：v4.33.0 起一律 40 MHz（含 NB 四颗 E501A／E501B／E503／EN01，先前写的是 20 MHz）。实测：EM01 ＋ 3584×720（HTOTAL 3864 × VTOTAL 770）、Frame Rate 290 ⇒ UI DCLK 一路调到 40 MHz、Frame Rate 跟着降到 26 Hz 才停住。
・Frame Rate 自己的下限（v4.33.0 起是 0.001 Hz，先前是 1 Hz）：Frame Rate 降到工具下限就不能再降，此时 UI DCLK 下限 = HTOTAL × VTOTAL × 0.001 ÷ 2 ÷ 10⁶ × 机种系数。下限缩小 1000 倍之后，这一道要 HTOTAL × VTOTAL 超过 800 亿（EM01）才咬得住，实务上等于不会遇到 —— 而先前是 8,000 万，VBLANK 一拉大就会撞到，正是「UI DCLK 调不到 40」的来源。真的撞到时讯息会说「Frame Rate 已经降到工具下限 0.001 Hz，再低就撑不住这组 HTOTAL／VTOTAL，请先缩小 HTOTAL／VTOTAL」。
🔴 V-Blanking 滑块：拉它的时候 Pixel Rate 与 RX DCLK 一个位数都不会变 这是这条滑块存在的唯一理由，也是它和「直接去改 Vblank 输入格」最大的差别：

・直接改 Vblank 输入格 ⇒ VTOTAL 变大、Frame Rate 不动 ⇒ Pixel Rate 跟着变大。
・拉 Vblank 滑块 ⇒ VTOTAL 变大，工具同步把 Frame Rate 等比降下来补回去 ⇒ Pixel Rate = HTOTAL × VTOTAL × fps 的乘积不变，RX DCLK 自然也不变。

用途：「这颗 TCON 的带宽就这么多，我想多塞一点垂直空白，代价是多少 Frame Rate？」——拉一下就直接看到答案，不必自己算。

两个端点：
・左端 ＝ 滑块出现的当下、你最后一次手动输入的 Vblank 值。拉高之后随时拉得回来，它不会被你自己推上去（否则拉高一次就再也回不到原点了）。要换一个新的左端，就去 Vblank 输入格重打一个值。
・右端 ＝ 65535（寄存器位宽上限）。

会出现小数的 Frame Rate，这是正常的。要守住 Pixel Rate，Frame Rate 几乎不可能刚好是整数（65535 个 Vblank 值里只有 19 个对得上整数）。所以这条路径刻意采用全精度浮点。 小数只从这条路径产生：Frame Rate 的输入格仍然只收整数、Frame Rate 滑块仍然是一格一格跳。
拖滑块时，画面不会跑掉 拖 Frame Rate 滑块与拖 Vblank 滑块，都以波形区的中心为锚：你原本盯着第 5 张画面的某个位置，拖完之后还是停在第 5 张画面的同一个位置，不用重新找。
Vblank 这一条特别容易感觉得出来，因为它会改变 VTOTAL。这个锚定对所有让 VTOTAL 改变的路径都有效（滑块、Vblank／Vactive 输入格、导入设定文件），不是只有滑块。
🔴 v4.34.0：换机种时 TCON UI DCLK 会自动夹到新机种的上限 —— 但只有大变小 机种一换，规格上限就跟着换。从这一版起：

・大变小 ⇒ 夹。例如 EM01（上限 432 MHz）＋ TCON UI DCLK 设在 432，切到 E503（上限 105 MHz）⇒ 自动降成 105，TX DCLK 跟着变。
・小变大 ⇒ 完全不动。E503（105）切回 EM01（432）时维持 105，不会自己跳上去。

Frame Rate 会跟着被拉下来（只有在必要时）：TX ≥ RX 是硬条件，天花板往下移之后如果现在的 Frame Rate 已经把 RX 顶过新上限，Frame Rate 就会降到新上限撑得住的值。
实测：EM01 ／ 1920×1080 ／ Frame Rate 144 Hz（RX 178.2 MHz）／ UI DCLK 432 ⇒ 切到 E503 之后变成 UI DCLK 105、TX 105、Frame Rate 84 Hz、RX 103.95 MHz。v4.33.0 为止这一组完全不会被夹，UI DCLK 会留在 432。

不会静默改掉：只有 UI DCLK 被夹时显示红字「已换成 E503：TX DCLK 由 432 调整为 105 MHz…」；连 Frame Rate 也被动到时改用琥珀色把两件事一起讲。
🔴 分辨率／V-Blanking／H-Blanking 一个字都不会改，Frame Rate 也只降到刚好合法为止，不会多降。导入 code 这条路径不套用本规则（那时候 Frame Rate 由文件内容决定，v4.31.1 已另有处理）。

4-4　哪些格子有下限保护、哪些完全没有

🔴 H-Active 与 V-Active 完全不设限，输入多少就是多少 这两格是面板的分辨率，是一个事实，不是一个可以被工具「修正」的数字。所以：
・没有下限保护、不会被工具改写成别的值、也不纳入内部的边界审核。
・你打 800 就是 800，即使算出来的 TCON UI DCLK 会低于机种规格下限，工具也不会挡你——它只会在下方显示一则说明，告诉你目前这个状态超出规格、以及怎么回到合法范围。
（唯一的例外是既有的 total 上限判定：把分辨率往上加到超过机种能力时，工具会把 ACTIVE 回退 —— 那是上限，与这里讲的下限是两件事。）

相对地，V-Blanking 与 H-Blanking 两格有下限保护，由两层叠起来、取较大的那一个：

层值怎么来的什么时候存在
① 硬底线 10 直接规定的最小值，没有推导。太小的 blanking 在真机上本来就没有意义。 一直都在
② 机种规格反推 依目前机种的 TCON UI DCLK 规格下限反推出来的 blanking 最小值 blanking 太小 ⇒ HTOTAL／VTOTAL 太小 ⇒ Pixel Rate 太低 ⇒ TCON UI DCLK 掉到规格下限以下。把这条反过来解，就得到 blanking 的下限。 只有变频应用下存在。定频下 TX DCLK 不跟着 RX 往下走，这条约束构不到上游，所以只剩硬底线 10。

实际下限 ＝ max(10, 机种反推值)。 打字打到比下限小的值时，工具会在套用前挡下并就地说明理由，画面上的值一个比特都不会动。两层的理由不同，提示信息也分开写 —— 撞到硬底线时不会扯「UI DCLK 会低于规格」这种不相干的理由。

下限只挡「往更糟的方向走」，永远留退路 判定是「低于下限」而且「比原本更小」才挡。所以万一你载入了一份 blanking 本来就低于下限的旧设定文件，往上调一定放行，不会被卡在一个既违规又动不了的状态。
同理，Vblank 滑块只吃硬底线 10，不吃机种层 —— 因为拉它时 Pixel Rate 守恒，UI DCLK 一步都不会低于规格下限，套上机种层只会无故缩小可拖拽范围。

5TCON 其他设定（Gate Type ／ Toggle FRM_NO）

三个全局共用的帧编号参数。所有数字信号只要开启 Toggle 模式，都是共用这一组设定，不需要（也不能）逐条分别设定。

它在控制什么

Toggle 模式让信号的 ACTIVE 极性每隔几张画面翻转一次，常见于极性反转（Polarity Inversion）相关的控制信号。FRM_NO_0/1/2 决定翻转的节奏，每条信号用自己的 TG_INI_VAL 选要吃三个里面的哪一个。

Toggle 的 INI_VAL 是「每张画面开头」的初始电位 它不是每一行重置一次，而是每一帧（frame）开头决定该张画面的起始准位。这是最常被误解的一点。
🔴 第一个 frame 一定不翻 极性的闭式是 ACTIVE(frame) = base XOR ( floor(frame / (FRM_NO + 1)) & 1 )，其中 base 就是 INI_VAL 给的初始极性（0 - Low → 0、1 - High → 1、Keep 因为没有前一张画面可延续 → 0）。
代进去就是 frame 0 恒等于 base —— 初始极性是 0 它就是 0、是 1 它就是 1，不会「一律从 HIGH 开始」。
🔴 1-based / 0-based 换算：「FRM_NO = 99 代表每 100 张画面变一次极性，第 1 张到第 100 张极性都一样，第 101 张才反过来」是从 1 数起的讲法；工具与程序内部的 frame 是从 0 数起，对应「frame 0～99 相同、frame 100 反相」。
FRM_NO周期frame 0 起的 ACTIVE（b = base）
01 张b, !b, b, !b, b, !b …（每张都翻）
23 张b, b, b, !b, !b, !b, b …
99100 张frame 0～99 = b，frame 100 起 = !b

要看到 Toggle 效果，「Frame 重复数」必须够大（至少大于 FRM_NO 的设定值），否则仿真范围内根本还没轮到翻转。

6-0　TCON 类型（MNT／NB）— 全局设定

TCON 类型决定 ACT_TYPE / R_PH / F_PH 这三个字段的位宽。所有数字信号共用同一个设定，不是逐条分别设。

类型不是独立选项，由「机种」决定 「TCON 数字信号」卡片上没有 MNT／NB 的手动选项，类型直接由你选的 TCON 机种推得：
・EM01 / EM02 / E512 → Monitor（MNT，9 bit）
・E501A / E501B / E503 / EN01 → Notebook（NB，6 bit）
机种在两个地方都可以选，两处是同一个设定：「TCON频率设定 → DCLK → TCON UI DCLK」的下拉， 以及上方工具栏 Code group 的型号下拉。
这样做的好处：同一件事只有一个真值来源。一换机种，位宽立刻跟着变，不必先导入 code 才会同步。
选项位宽三个字段的范围计数器溢出点
MNT（Monitor TCON）9 bit0 – 511数到 511 后 +1 绕回 0
NB（Notebook TCON）6 bit0 – 63数到 63 后 +1 绕回 0

  • 换成 NB 机种时，所有数字信号中大于 63 的 ACT_TYPE / R_PH / F_PH 会被夹为 63（是夹到上限，不是截断，所以 500 会变 63）。这个动作不可逆，换回 MNT 机种不会还原原值。
  • 一般（非 Toggle）信号的字段上限一样吃这个限制。
  • 机种会随导出／导入一起带走。旧设定档的兼容处理：文件里若有旧的 tcon_type 字段而没有机种字段，会用它推回同类别的代表机种（MNT → EM01、NB → E501B），位宽与该档原本的一致，波形不会变；两者都没有的文件则当成 EM01（MNT）。反方向也顾到了：导出的文件除了机种字段，仍会一并写出 tcon_type。
什么时候看得出 MNT 与 NB 的差别？ 只有在 Toggle 模式、而且计数器真的数到位宽上限时才看得出来。例如 ACT_TYPE=0 / R_PH=60 / F_PH=1 / ST_LINE=0 / SP_LINE=12：
NB → 60, 61, 62, 63, 0, 0, 0 …（第 4 条溢出归零，而 0 刚好等于 ACT_TYPE 所以锁死）→ 波形 H L H L H H H H H H H H H
MNT → 60, 61, 62 … 72（要数到 511 才绕回）→ 波形 H L H L H L H L H L H L H

起算点怎么判断？两个例子
XSTB（ACT_TYPE=0、R_PH=0、F_PH=0）：ACT_TYPE 是 0，两个计数器一开始就等于最大值，所以每一条 line 都同时是 R 与 F 的触发条。R_DLY 与 F_DLY 都从同一条的行首起算，一行内先上升再下降，形成每行一个窄脉冲。
VST1（ACT_TYPE=15、R_PH=15、F_PH=13、ST_LINE=2）：R_PH_CNT 在第 2 条就载入 15 = ACT_TYPE，所以 R_DLY 从第 2 条起算；F_PH_CNT 从 13 开始数，第 2 条是 13、第 3 条是 14、第 4 条才数到 15，所以 F_DLY 从第 4 条起算。两者相差 2 条，脉冲宽度就是 2 条 line。
把鼠标停在波形上时，画布会用绿色与橙色箭头分别标出 R_DLY 与 F_DLY 的起算条到边缘的距离；上方 R_PH_CNT / F_PH_CNT 两列会把触发的那一格高亮，可以直接对照。

不勾选：切断点改到 ST_LINE，INI_VAL 也在那里才生效。Line 0 到 ST_LINE 之间，前一个 frame 的「产生行为」原封不动继续跑 —— 前一个 frame 若是每条 line 打一个 pulse，新 frame 的 Line 0、1、2（若 ST_LINE=3）也各会打一个 pulse，直到 ST_LINE 才切断重来。SP_LINE=16383 代表这个 frame 还没打完，所以会跨过 frame 边界一直打到下一个 ST_LINE；若 SP_LINE 在本 frame 内就结束了，延续过来的自然也是停着的状态。
INV复选框勾 / 不勾反相。勾选后整条波形上下翻转（高变低、低变高）。最后才套用，会盖过前面所有设定的极性。
OAX_MODE下拉菜单0 = 无 / 1 = OR / 2 = AND / 3 = XOR把这条信号与另一条信号做逻辑运算后才输出。选「无」表示不做运算，直接输出自己的波形。
OAX_SEL下拉菜单其余 17 条数字信号OAX 运算的对象。列表是全部 18 条，包含这条自己 —— 选自己代表「这条不做 COMBO 运算」，是正常值。只有 OAX_MODE 不是「无」时才有作用。
OAX 是什么？ 名称来自 OR / AND / XOR 三种运算的缩写。典型用途是把两条分别控制不同区段的信号合成一条输出，例如把 VST2 与 TEND 做 OR，让两者任一为高时输出就为高（预设范例 FHD 60Hz Single Gate 就是这样设定 VST2 的）。

6-2　Toggle 模式：另一套算法（任一信号勾选即适用）

这是 18 条信号中唯一需要独立说明的部分。只要勾选 Toggle，这条信号就改用另一套算法 —— 判准是「Toggle 有没有被勾」，与信号名称无关。XSTB、VST1／2、CK1–CK8、TEND、VS、HS、GPO0／1 任何一支勾了 Toggle，行为都与 XPOL 完全一致（同一组参数在不同信号上会产生一模一样的波形）。实际使用上最常用在 XPOL 与 LC，但那是惯例，不是限制。

勾选后卡片上还会多出七颗快速设定按钮，一键把 ACT_TYPE、R_PH、F_PH 三个参数同时填成对应的极性反转模式，并一并设定 ST_LINE / SP_LINE 的行区间，省去逐一计算。

为什么这七组值叫「极性反转模式」？ 这七组数值是为极性反转（Polarity Inversion）设计的标准组合，而极性反转正是 XPOL 这条信号的职责 — Source Driver 就是看 XPOL 决定要充正极还是负极 Gamma。任何一条信号勾选 Toggle 后都会出现这七颗按钮（它们填的就是那三个通用参数），只是其他信号按了单纯把参数填成这组数值而已。

🔴 勾了 Toggle 的信号，算法与一般打 pulse 的信号完全不同（适用任一信号，不限 XPOL／LC） 一般信号是「两个计数器各自数到 ACT_TYPE，一个管上升一个管下降」；Toggle 信号只有一个计数器，而且 F_PH 不是相位起始值，是位掩码（bitmask）：
  1. R_PH_CNT 在 ST_LINE 那一条直接载入 R_PH（不取模，就算 R_PH 比 ACT_TYPE 大也照载）。
  2. 之后每条 line 更新一次，有两个归零来源：
    ① 这条的值等于 ACT_TYPE → 下一条归零（正常周期，长度 = ACT_TYPE + 1）
    ② 加一之后溢出 → 依 TCON 类型的位宽绕回（MNT 9bit 到 511、NB 6bit 到 63，见 6-0）
    写成一行就是 cnt(n+1) = (cnt(n) == ACT_TYPE) ? 0 : ((cnt(n) + 1) & maskBits)。
    两者合起来会有一个容易忽略的行为：溢出归零后如果刚好等于 ACT_TYPE（例如 ACT_TYPE = 0），计数器就从此锁死在 0，波形之后恒定不再转态。
  3. 把 F_PH 转成二进制当位掩码，bit(n) = (cnt(n) & F_PH) != 0。例如 F_PH = 2（0b10）→ 看 bit 1。
  4. ST_LINE 那一条无条件被驱动到 ACTIVE（套 R_DLY）。之后每一条的电平是相对于 ST_LINE 那一条判断的：
    bit(n) == bit(ST_LINE) → ACTIVE；不等 → 反相。
    🔴 注意是「与起点同相／反相」，不是「bit=1 就 HIGH」。R_PH 只要改，整条波形的相位就跟着平移。
    🔴 也注意 ACTIVE 不等于 HIGH —— ACTIVE 是「这张画面的作用极性」，它可能是 HIGH 也可能是 LOW，由 INI_VAL 与 FRM_NO 决定（见下一条）。所以 ST_LINE 那一条不保证是「上升边缘」，只是「进入 ACTIVE」。
  5. R_DLY 只在「电平改变」的那一条作用，而且两个方向都用 R_DLY（low→high 与 high→low 皆然）。没变的那一条不套任何延迟，直接维持前一条的电平。
  6. Toggle 模式没有 F_DLY，该字段在此模式下无作用（原厂 timing 文档的 XPOL 寄存器表也把它标为「Toggle mode 时 无用」，实际值设 0）。
  7. SP_LINE 是「最后一条参与 toggle 的 line」（含）。超过之后停止计数、不再转态，一路 keep 住 SP_LINE 那条的电平到 frame 结束；下一个 frame 再从 ST_LINE 重新载入 R_PH。
  8. 整个 frame 的 ACTIVE 是 HIGH 还是 LOW：ACTIVE(frame) = base XOR ( floor(frame / (FRM_NO + 1)) & 1 )，base 由 INI_VAL 给。frame 0 恒等于 base，第一个 frame 一定不翻；之后每 FRM_NO + 1 个 frame 反相一次。XPOL 用 FRM_NO_0 = 0，就是每 1 个 frame 反相一次。详见第 5 章。

把鼠标停在 Toggle 信号的波形上时，画布只会画一支 R_DLY 箭头（起算条就是电平改变的那一条），不会画 F_DLY —— 因为 Toggle 模式下它不存在。上方 R_PH_CNT 列显示计数值、F_PH_CNT 列改显示被选中 bit 的值（0/1），两列的高亮都到 SP_LINE 为止，之后转灰。
「3-line」为什么在画面上看起来像「正正负」或「正负负」？ 这颗按钮和其他按钮一样以周期行数命名：一个周期 3 行，极性依序是正、负、正。但因为周期的头尾都是正，相邻两个周期的「尾正」与「头正」会连在一起，所以连续看下去实际是 + - + | + - + | + - + —— 每 3 行只有 1 行是反极性，肉眼读起来就成了「正正负」不断重复。
再加上 XPOL 会依 FRM_NO 设定逐 frame 整体反相，下一个 frame 同一段就变成 - + - | - + -，也就是「负负正」。所以同一组设定，看的 frame 不同、起算的行不同，会分别读成「正正负」或「正负负」，两者都是同一个 3 行周期、正负比 2:1 的样式。

当目前的 ACT_TYPE / R_PH / F_PH 三者同时符合某颗按钮的组合时，那颗按钮会自动高亮成橙色，让你一眼看出目前处于哪个模式。手动改动任一参数后，高亮就会消失。

6-3　参数如何叠成最终波形

运算顺序：ACT_TYPE 决定周期 → R_PH / F_PH 决定相位内的边缘 → R_DLY / F_DLY 做时钟级位移 → ST_LINE / SP_LINE 裁掉范围外 → OAX 与另一条信号运算 → INV 最后反相 → 若开 Toggle 则依 FRM_NO 逐帧翻初始电位。

10-1　即时测量

分成两部分：上半是跟着鼠标跑的即时读值，下半是可固定的指定通道测量。

上半：hover 即时读值（5 个显示字段）

鼠标停在波形上任一通道时，这四个值会即时更新；鼠标移开画布则变回 --。最上方另有一列显示目前所在的通道名称。

显示项目内容
通道名称鼠标目前所在的通道，未指向任何通道时显示 --。
脉宽鼠标所在位置那一个脉冲的宽度，自动选用 s / ms / µs / ns。数值右边另外标出等效几条 line（单位 H），例如 13.500 μs (1H)，说明见下方。
周期该处波形的一个完整周期长度。同样带 H 标注，例如 20.250 μs (1.5H)。
占空比高电平时间占整个周期的百分比。不是时间，没有 H 标注。
频率周期的倒数，自动选用 Hz / kHz / MHz。不是时间，没有 H 标注。

下半：指定通道测量（最多 4 组）

点卡片标题右侧的 ＋ 新增一组。与上半不同，这里的值不会随鼠标改变，会一直盯着指定的通道，适合同时比较多条信号。已达 4 组时 ＋ 会变成不可点。

每组的组成类型说明
颜色点只读显示对应通道的线条颜色。

✕ 删除钮按钮移除这一组测量。
频率 / 正脉宽 / 负脉宽 / 周期 / 占空比只读显示 × 5五个测量值。取该通道第一个上升沿起算：正脉宽＝高电平持续时间、负脉宽＝低电平持续时间、周期＝两者之和、占空比＝正脉宽 ÷ 周期。无法计算时显示 --。
其中正脉宽、负脉宽、周期这三个时间值，右边同样会多一个等效 line 数（单位 H）；占空比与频率没有。
时间类数值右边的 (1H) ＝ 等效几条扫描线 正脉宽、负脉宽、周期这三栏，数值右边会多一个等效 line 数，单位 H：13.500 μs (1H)、20.250 μs (1.5H)。占空比与频率没有（它们本来就不是时间）。用 ＋ 新增的测量小卡（最多 4 个）同样有。

🔴 导入 LA 录制数据（.kvdat）的模式下不显示 H。那份数据是真实硬件录回来的，与画面上的 HTOTAL／TX DCLK 无关，硬换算出来的 H 只会误导人。
操作中不会被打断 当你正在点开通道下拉菜单时，面板不会重建，只会就地更新数值，避免选单被关掉。这在波形持续变动时特别重要。

10-2　时基标尺

显示 A–E 五组光标的测量结果。只有至少放下一支光标的组别才会出现，没放光标时整张卡是空的。

元素类型说明
时间差显示列可输入两支光标都放下时出现，格式为 |A1 − A2| = [可输入框] 单位 / 频率 / 等效 line 数，整列用该组的颜色显示。实际长相：|A1 - A2| = 13.5 μs / 74.07 kHz / 1H。
时间差输入框文本输入可以直接键入数字。按 Enter 套用：程序会固定较早的那一支光标，把较晚的那一支精准移到「早 + 你输入的时间差」的位置。按 Esc 放弃并还原。输入必须是正实数，且换算后不小于 0.5 ns，否则不生效。
单位自动依时间差大小自动在 s / ms / µs / ns 之间切换，没有手动单位下拉。
频率只读显示时间差的倒数，方便直接读出对应频率。这是第二段。
等效 line 数只读显示第三段，单位 H：把时间差换算成等于几条扫描线。原本这一列只有「时间 / 频率」两段，现在是「时间 / 频率 / xH」三段。换算方式与 10-1「即时测量」完全相同（每 line 的 DCLK 数 ÷ TX DCLK，Dual Gate 是 HTOTAL ÷ 4、Single Gate 是 HTOTAL ÷ 2）。
× 关闭钮按钮一次移除该组的两支光标，并解除下面说的时间差锁定。
光标明细只读显示逐支列出 A1 @ 时间。若某支正在跟随鼠标，会在后面标上 ⟵。
时间差锁定：这是本工具最实用的功能之一 一旦用输入框设定过时间差，该组就进入「锁定」状态 — 之后拖动较早那支光标，较晚那支会维持固定间距一起移动，像一把固定宽度的卡尺。想量「某个边缘往后 10 µs 是什么状态」时非常好用。手动拖拽光标、用快捷键切换、或按 × 关闭组别，都会解除锁定。

连续缩放的性能

绘制的计算量绑在「画面上有几个像素」，而不是「视野里有几行」，所以缩得再远也不会变慢。即使导入内容比较多的设定文件，连续滚动滚轮缩放远端与近端都稳定在每格约 33 ms（约 30 FPS），跟着滚轮即时跟手；单次跳到全览的重绘约 0.03 秒。

有一种情况仍然会停顿 把画面缩到最远、放开鼠标之后的那一次冻结还在。那一段是模拟信号的预先计算，和上面讲的绘制路径不交集，是另一个性能题目，尚未处理。

12-3　导入时的检查与兼容处理

  • 导出时：只有你真的动过 TCON UI DCLK 才会把对应的寄存器写回清单。「导入 → 什么都不改 → 导出」一列都不会多写。
  • 算不出来时不会乱填：型号指纹不符、值超出 NB 的 40～105 MHz 规格（下限 v4.33.0 起由 20 改为 40，实测 TCON/Model 底下 359 份 NB 真档没有任何一份落在 20～40，判定结果逐档不变）、或 code 本身没做过标准化，都会维持画面上原本的值不动，并把理由写在导入卡片上、把 DCLK 那一项留着要你自己确认。
  • 🔴 EN01 不做这件事：目前手上的 EN01 真实文件都没有做过 AGBSFR 标准化，套公式会算出明显偏低的值。选 EN01 时提醒卡片仍会保留 TCON UI DCLK 那一项，请照旧自己确认。
官方标准化还会改的东西，本工具一律不碰 官方 UI 做 AGBSFR 标准化时，会顺便依 EDID 重写 HBLK／VBLK／FR_DET_TH 等一整组参数。本工具没有 EDID 那一整套输入，那些一律不写，导出后的信息里也会再讲一次。

🔴 要你确认的东西一项都不少：TCON UI DCLK 与 Line Buffer 的输入框、目前值徽章、提交前的验证都在。

🔴 v4.35.1 起，第 1 项的主角是「TCON UI DCLK」，不是「TX DCLK」。那一项的标题、「目前值」徽章、以及你主要要填的那一格全部是 TCON UI DCLK（＝你刚刚在那颗 TCON 的官方 UI 上看到、抄过来的那个数字）；TX DCLK 降到下一行的辅助说明，会即时显示换算出来的值。

  • 换算关系一个字没变：TCON UI DCLK = 机种系数 × TX DCLK（E503／EM01／NB 三颗是 1:1，EM02／E512 是 2:1）。方框下方那一行灰色关系式现在改成以 UI 起头，等式本身相同。

  • 上下限照旧：填超过机种规格会被挡、TX DCLK 不可低于 RX DCLK 也照旧 —— 验证走的是与左侧「Frame 参数」卡片完全同一套。

13-2　NB：.xlsx 是什么、怎么导入 RomCodeProcessUI

🔴 先讲最容易误会的一件事：这份 .xlsx 不是 code 档 它是一张「要改哪些寄存器、改成什么值」的核查清单，官方工具里叫 Check List。这份 xlsx 就是照 RomCodeProcessUI 的 Code Check 分页格式做的 —— 导出之后回官方 UI 的 Code Check 分页导入，用它去修改原始 code 里 GPO Timing 的部分，再另存成新的 code 档。整串动作的目的只有一个：修正 code。
🔴 整套流程只要存 Code —— 不用烧、不用接治具 从「打开 code 档」到「Save AS 存出新的 code 档」，全程都在改硬盘上的文件。不需要接任何治具、不需要连线、不需要把数据烧进 Flash。下面的八个步骤就是完整流程，没有省略的前置动作。

两个「不会叫、但结果是错的」陷阱

  • 官方 UI 只改写清单上有列出来的字段，没列的维持 code 档原值 —— 所以清单短不代表漏了什么，代表那些没被动到。
  • 手动编辑这份 xlsx 时，改单元格的值可以，绝对不要改第 1 行的列名。官方 UI 是靠列名认字段的，列名对不上就整列静默读不到，而且不会报错。

🔴 复制完就结束了 —— 不用再按 Flash R/W 去烧 这一整套流程不碰 Flash 烧录，只要存 Code。From Current 做完，该做的就做完了。右边 Flash R/W 底下那组 Write Normal ／ Write 200% ／ Write 133% ／ Write All 是另一件事，本流程用不到。
🔴 明确讲「不是什么」 ・入口不是右边的 Flash R/W 下拉。它底下是 Read Normal ／ Read 200% ／ Read 133% ／ Read All 与 Write Normal ／ Write 200% ／ Write 133% ／ Write All，那是另一组动作，不是「把 CURRENT 复制到某一模式」。
・不要选成 From Normal ／ From 200% ／ From 133%。那三项的来源是别的模式，选下去等于拿别组的值盖掉当前子分页。要的是 From Current。
・Init Three Mode 就排在 --- Copy Data --- 上面一项，非常容易点错。它实际做什么本站不确定 —— 复制数据请只用分隔线底下那四项。

两个数字决定一切

  • 采样率决定「看得多细」。要能还原一个信号，采样率至少是它频率的数倍；测 1 MHz 的 SCL，用 200 MHz 采样代表一个 bit 有 200 点，边缘位置才准。
  • 深度决定「录得多久」。录制时间 = 深度 ÷ 采样率，工具栏会直接把这个数字写在采样组下方（「理论采样时间」）。
  • 两者互相拉扯：想录久一点就得降采样率或加深度。先问自己「我要抓的事件多长」，再回头配。
「理论」两个字是真的 深度 ≥ 1 GSa 且理论时间超过 5 秒时，数字后面会加注「实际长度依硬体压缩率」。硬件是用边缘压缩方式存数据，信号越密、可录时间越短，实际拿到的长度会比理论值短。

PWM 灯不亮不代表设定没存到 PWM 按钮的绿灯只有在硬件连接为 ON 时才会亮。未连接时按确定，设定会存起来但不会送到装置（状态栏会提示），等连接后重开窗口勾选即可。断线或按 OFF 时，PWM 会被强制关闭——控制权都释放了，输出自然不该还算在本工具头上。

20常见问题

点问题展开答案。

我改了参数，但波形完全没变化？▼

依可能性由高到低检查：

  1. 该信号的 ENABLE 没有勾 — 卡片标题会显示灰色的 OFF。
  2. 该信号没有被指派到任何输出通道 — 到「输出通道」卡片检查。
  3. 对应通道的显示切换是 ○（隐藏）而不是 👁。
  4. ST_LINE 大于 Vtotal，或 SP_LINE 小于 ST_LINE，导致这条信号在仿真范围内完全没有输出。
  5. 目前的查看范围刚好避开了该信号有动作的区段 — 按「全览」看全貌。
导入设定档之后，滚轮缩放会卡吗？▼

不会。绘制的计算量绑在「画面上有几个像素」，不是「视野里有几行」，所以缩到多远都一样：远端与近端都稳定在每格约 33 ms（约 30 FPS），跳到全览的单次重绘约 0.03 秒。

🔴 只有一种停顿仍然存在：把画面缩到最远、松开鼠标之后的那一次冻结。那一段是模拟信号的预先计算，是另一个题目。详见 第 11 章。

VTOTAL／HTOTAL 那两格点下去改不动？▼

那两格是只读显示，不是输入格。要改的是它们上面那四格：VTOTAL = Vactive + Vblank、HTOTAL = Hactive + Hblank。改任一格，下面的 total 立刻跟着算好。

拉 Vblank 滑块，Frame Rate 怎么变成小数了？▼

这是正常的，而且是刻意的。Vblank 滑块的唯一目的就是「加大 Vblank 而 Pixel Rate 与 RX DCLK 完全不变」。因为 Pixel Rate = HTOTAL × VTOTAL × fps，VTOTAL 一变大，fps 就必须等比降下来补回去 —— 而这个等比降下来的值几乎不可能刚好是整数（65535 个 Vblank 值里只有 19 个对得上整数）。取整就守不住 Pixel Rate，所以这条路径采全精度浮点。

小数只会从这条路径产生：Frame Rate 的输入格仍然只收整数。

变频应用下，我改了 TX DCLK，Frame Rate 怎么跟着变了？▼

变频下这两个量是双向联动的，设 DCLK 就等于反过来设 Frame Rate。变频应用里 TX ≡ RX，所以动 TX 或 TCON UI DCLK，RX 会跟着走，Frame Rate 再由 fps = 2 × TX × 10⁶ ÷ (HTOTAL × VTOTAL) 反推出来。TX 增加 ⇒ RX 增加；TX 减少 ⇒ RX 减少。反推时守住的是分辨率，变的是 Pixel Rate。

定频下则不会 —— 定频的 TX 是独立的量，可以大于 RX，改它不影响 Frame Rate。但两种形态下 TX 都不可以小于 RX，填低了会在套用前被挡下并保留原值。

变频下 TX／TCON UI DCLK 两格与两条滑块都是可以动的，不会被锁住。详见 4-5。

导出的 script 用官方 TCON UI 导入后，画面上还是旧的 timing？▼

script 没有问题，是官方 UI 导入之后不会自动重读。到 GPO 分页按一次 Read，设定就会出现在 Current 子分页里。MNT 机种导出时会跳一个提醒窗口讲这件事（NB 不跳）。

要把 CURRENT 的值再复制到 Normal／200%／133% 子分页，正确步骤是：① GPO 分页按 Read → ② 先切到目标子分页 → ③ 点左下角的 File IO → ④ 在 --- Copy Data --- 底下选 From Current。完整说明见 12-4。

把面板 Gate 条数加大（例如 4 或 8 条）之后，脉冲序号会整排位移吗？▼

不会。当 CK 的 SP_LINE 超过一整个 frame、而且 CKO 在 frame 结尾刚好停在高电位（VGH）时，工具会在 frame 交界把电位状态重置，让新的一张画面从正确的起点开始画，Gate 的脉冲序号不会整排位移一格。

CKO 在 frame 边界本来就回到 VGL 的设定（绝大多数情况）不受这条规则影响。

做非默认分辨率（例如 QHD 2560×1440），刷新之后设定会跑掉吗？▼

不会。Hactive 不等于 1920 时，刷新之后 Hactive／Hblank／HTOTAL 与 Pixel Rate 都会照你离开时的样子还原。自动还原、手动导入设定档、粘贴设定三条路径的还原顺序一致。

「blanking 与 total 不一致」这句提示只在档案内容真的互相矛盾时才会出现。

为什么有些滑块是绿色、有些数字是亮蓝色？▼

颜色是有意义的，不是装饰：

  • 绿 ＝「系统设定 (Pattern Gen)」与「系统行为模拟」两张卡片 —— 这是系统／Pattern Gen 这一侧的数字，也是要你来动的地方。系统行为模拟的卡片外框、放大的标题、三条滑块的滑钮都是绿的（v4.34.0 由橙改绿）。
  • 亮蓝 ＝ 一般控制项（TCON频率设定那两条滑块），以及TCON 内部实际跑的只读注明值（TCON HTOTAL、TCON Pixel Rate）。这个蓝色和 Rx/Tx 频率计算工具分页上那些计算结果是同一个色。
    🔴 「系统设定」卡片里的亮蓝只代表一件事：TCON 内部的数字。 同一列左边的系统端数字（HTOTAL、Pixel Rate）一律白色。

完整说明见 4-2。

为什么没有「计算」按钮？▼

「面板信号仿真」模式的所有字段都是即时计算：输入的当下就重新产生波形，不需要也没有确认按钮。这样调参数时可以边拖滑块边看波形变化，比按一次算一次直觉得多。

Toggle 勾了却看不出翻转效果？▼

两个常见原因：

  • Frame 重复数太小。Toggle 是逐帧翻转，若 FRM_NO 设 99 而只仿真 10 张画面，范围内根本轮不到翻转。把 Frame 重复数调到大于 FRM_NO 的值。
  • 查看范围太窄。要看跨帧的行为，得先按「全览」缩到能看见多张画面的尺度。
按了数字键，光标怎么不见了？▼

光标有三个状态循环：未启用 → 跟随鼠标 → 已钉住。从「跟随鼠标」状态再按一次同一键，就会移除。若你放下光标后没有按鼠标左键钉住，它一直处于跟随状态，此时再按一次键就会消失。正确做法是：按数字键 → 移动鼠标到想要的位置 → 按一下左键钉住。

时间差输入框输入数字后没反应？▼

要满足三个条件才会生效：

  • 该组的两支光标都必须已经放下（只有一支时不会出现输入框）
  • 输入必须是正实数，不能是 0 或负数
  • 换算成秒之后不小于 0.5 ns，太小的值会被拒绝

输入完要按 Enter 才会套用（按 Esc 是放弃）。

拖动一支光标，另一支怎么跟着跑？▼

这是时间差锁定生效中，代表你先前用时间差输入框设定过该组的间距。两支光标会维持固定间距一起移动，像一把固定宽度的卡尺。要解除，按该组的 × 关闭再重新放置，或用快捷键切换该组光标。

模拟通道的脉冲计数结果和预期不同？▼

模拟通道是用该通道的 V1 电压光标当作高低判准。V1 拉太高或太低，都会导致计数结果不符预期。请先在通道名称旁点开 V1/V2 光标，把 V1 拖到波形摆幅的中间附近，再看计数结果。

改了 GOA Phase，CKO 通道跑到哪去了？▼

改 GOA Phase 会重建所有 CKO。新产生的 CKO 会自动填进第一个空着的输出通道并命名为「CKO n」。若 64 条通道已经全部被占用，新的 CKO 就没有位置可放 — 这时请先把不需要的通道来源改成「无」，再重新设定 GOA Phase。

按了 XPOL 快速设定按钮，其他字段怎么也变了？▼

这是设计上的预期行为。快速设定按钮除了填入 ACT_TYPE / R_PH / F_PH 之外，还会把 INI_VAL 设成 2 - Keep，并在 ACT_TYPE 大于 0 时把 SP_LINE 设成最大值 16383。若你需要不同的设定，按完按钮后再手动改这两个字段即可。

导出的文件为什么是 .txt 而不是 .json？▼

内容确实是 JSON 格式，用 .txt 扩展名纯粹是为了方便：很多通讯软件与邮件系统会挡掉 .json 附件，但 .txt 通常畅行无阻。导入时 .txt 与 .json 两种都接受。

波形拖不动、卡卡的？▼

最常见的原因是「Frame 重复数」设得太大（例如上千张）同时又处于全览状态，需要绘制的数据量非常大。解法：先放大到你真正关心的区段，或把 Frame 重复数降到需要的最小值。载入预设「FHD 60Hz Single Gate」时 Frame 重复数是 1000，若不需要看跨帧行为，可以先调小。

可以直接改波形左边的通道名称吗？▼

不行。波形左侧的名称栏不支持双击改名或右键菜单。请到左侧「输出通道」卡片，在对应那列的名称输入框修改。改完波形左边会立即同步。

仿真结果可以直接当成真机规格吗？▼

不建议。本工具是依参数推算的理想波形，用来验证时序逻辑关系，不包含真实电路的 RC 延迟、负载效应、制程偏差与噪声。它能帮你在上机前找出时序设定的错误，但电气特性仍需以实机测量与正式规格文件为准。

「LA分析器」页签呢？▼

LA分析器是完整独立的逻辑分析仪功能，已收录于本手册第 13–18 章：简介与快速开始、采样与触发设定、工具栏、波形区与通道栏、右侧面板与协议解码、硬件连线与设备支持包。

LA：一进去就有波形，可是我根本还没接线？▼

那是示范波形——没有任何采集数据也没有导入文件时，工具会依你选的采样率与深度生成一段假信号，只为了让版面不是空白。它没有任何测量意义。确认方式：右侧「解码结果」若停在「等待 analyzer decode data」、且页首没有导入文件名，看到的就是示范波形。

LA：某条通道整条都是平的，是没信号还是设定错？▼

先看该通道名称栏最右边的灯：没亮绿且显示 0 或 1，代表这条线在整段采集中没有任何边缘变化。依可能性排查：

  1. 阈值电压设错——量 1.8 V 信号却留在 2.5 V 档（Vth 1.25 V）尚可，但若留在 5 V 档（Vth 2.5 V）就会恒为 0。这是最常见的原因。
  2. 探头没接到、地线没接。
  3. 该通道没有被启用（用 CH0-15 或设定面板勾选）。
  4. 信号真的没有动作（例如受测物尚未进入该状态）。
LA：按单次采集没有反应，或跳出要我导入 zip？▼

实际采集需要三个条件：桌面版 Chrome／Edge、网页在 https 下开启、装置没有被原厂软件占用。第一次使用还要导入一次设备支持包（见第 19 章），导入后会自动接续刚才的采集。若提示「装置被其他程序占用」，请先关闭原厂软件再按硬件连线 ⏻。

LA：解码结果一片红，是面板真的有问题吗？▼

先排除解码器设定问题再下结论：

  1. 通道指派错了——SDA／SCL 或 AUX 通道选到别条线。通道名称栏会显示分析器角色，对一下就知道。
  2. DP AUX 的 Bit Rate 被改过——应为 1,000,000。
  3. 极性相反——把 Polarity 改成 Invert 试试。
  4. Tolerance 收太紧——信号边缘抖动大时先放回 25%。
  5. 以上都正确才是真的异常。点 Type 栏的徽章可以看到该笔被判为异常的具体理由。
