1工具简介

这是一支不预设对面是什么芯片的 I2C 读写工具：任意 slave 地址、任意 offset、任意长度，读回来摊成 16×16 表格，可以就地改值、跟另一份数据逐 byte 比对、再一次写回去并自动回读验证。

它解决什么问题

  • 看得到整片内容 — 一次最多读 262,144 byte（256K），分页呈现，每页 256 byte。
  • 改了什么一目了然 — 两份数据（A／B）同时在手上，不同的格子会上色，差异列表逐条列出“地址 / Data A / Data B”。
  • 写进去不必猜 — 写完自动回读同一段，逐 byte 比对，不一致的格子标红并列出地址。
  • 不挡路 — 没有地址白名单、没有“允许写入”开关。所有读写都完整记在画面的操作记录与 I2C Bridge 的日志文件里。

它不做什么

  • 不替你判断对面是什么 — 除了 EEPROM 的容量确认之外，工具不猜芯片型号、不套寄存器定义。
  • 不自动写 — 除了你按下“写入”或就地改一格（已连接时）以外，没有任何路径会发出写入。
  • 不记住你的数据 — 关掉标签页，dump 内容就没了；要留就用“另存为”。
浏览器为什么碰不到工装 USB 转 I2C 的工装由驱动层绑定，浏览器没有任何一条路可以直接访问它。所以这一页必须搭配一支在你电脑上运行的小程序（I2C Bridge），由它代为操作工装，网页通过本机的 WebSocket 跟它通信。

2获取与启动 I2C Bridge

连不到的时候，画面上第一个出现的就是下载按钮，版本号直接印在按钮上。

下载

按画面上的“⬇ 下载 I2C Bridge 版本”。按下去会弹一个三行的说明窗口，照着做即可。

整包解压到同一个文件夹

包内是四个文件：i2c-bridge.exe、libMPSSE.dll、ftd2xx.dll、DLL_I2C_BCB.dll。四个必须在同一个文件夹，少一个就起不来。

双击 i2c-bridge.exe

第一次运行 Windows 会拦一次（程序内容一变，哈希就变，所以每次换版都会再拦一次）。黑窗口留着不要关，它就是那条通道。

回到这一页

页面会自动尝试连接，通常不必按任何东西。没自动连上就按一下“连接”。

黑窗口最后一行是一个大写字母 G ＝ 一切正常。不是 G 的时候，把整份 i2c-bridge.log 留下来，字母的意思由工具的维护者查 —— 这一页刻意不把对照表印给使用者看。
项目类型范围／选项说明
下载 I2C Bridge按钮—连不到时自动出现。版本号印在按钮上，来源是工具的版本单一来源文件，不是写死在这一页。
I2C Bridge 信息与疑难排解折叠卡—收在诊断模式里。含 zip 与 exe 的 SHA256、四个文件的清单、常见连不上的原因。
SHA256 zip / exe只读显示—下载回来要核对的话比这两个值。exe 内容一改 SHA 就变，Windows 也会再拦一次。
浏览器问你要不要“允许访问本地网络”时请点允许 从公开网址连本机（127.0.0.1）时，新版浏览器会先问一次权限。点了阻止或把提示关掉，连接就不会成立，而且画面上看起来跟“程序没开”一模一样。这一页分得出这两种：慢到几百毫秒才失败的那一种，会另外显示一行“请点允许”与一个重试按钮。

3连接

连接是一个开关：连上是绿的，断开是灰的。旁边那一行小字是对面那支程序的版本与协议版本。

控件类型范围／选项说明
连接 / 已连接开关—同一个按钮负责两个方向。关掉不只是断开：它会同时把工装交回去，别的程序就能用。
连接状态灯只读显示—灯号＋一句状态。常见的有“未连接”“连不到 I2C Bridge”“已连接（本页持有 I2C）”“I2C 在另一个页面”。
I2C Bridge x.y.z · proto n只读显示—连上之后才有字，未连接时是空的。proto 是双方讲的协议版本，有些新功能要对面够新才有（见下方）。
I2C 时钟（kHz）文本输入＋下拉下拉 50 / 100 / 200 / 400 / 1000；手动不设上限常用值放在下拉里，也可以直接输入。下方小字会印出实际会得到的频率（见下面那段陷阱）。改完要重新连接才生效。

时钟：整数除法的陷阱

工装端换算频率用的是两次整数除法：

divisor = (12000 / kHz) / 2 − 1　（两个除法都取整） 实际频率因此是 12000 / (2 × (divisor + 1)) kHz。它不检查输入、也没有档位表：任何值都收，不整除的值会被默默算歪。
你填的值类型divisor实际频率
400kHz14400 kHz　✔ 刚好整除
350kHz16352.94 kHz　← 不是你填的那个数字
100kHz59100 kHz　✔

所以下方小字一律把实际值算出来给你看 —— 对不上你填的数字时，它会标红。这比任何警告都有用。

同一时间只有一个页面握着工装 切到哪一页，哪一页就自动接管，不必按任何东西。对方正在测量时不会被抢走。要把工装交回去给别的程序，就把连接开关关掉。

4读写参数（读与写共用同一组）

读取与写入共用同一组 slave 地址、offset 宽度与起始 offset。四个分组由左至右：① Slave 地址　② Offset　③ 总 byte 数　④ 对设备。

① Slave 地址：7-bit 与 8-bit 的关系

三格是同一个地址的三种写法，改任何一格，另外两格立刻跟着变。

控件类型范围／选项说明
7-bit（实际发出）文本输入＋下拉0x00–0x7F；下拉常用值 0x68 / 0x50 / 0x3E / 0x7C / 0x7D这一格才是真正发到总线上的值，所以它是被强调的那一格。
8-bit write文本输入0x00–0xFF，偶数＝ 7-bit << 1。输入奇数会当场改成偶数并显示修正后的值（不是偷偷换掉一个你看不到的东西）。
8-bit read文本输入0x00–0xFF，奇数＝ (7-bit << 1) | 1。输入偶数会补上最低位并显示修正后的值。
为什么有两套写法 I2C 在总线上发出的第一个 byte 是“7 位地址 ＋ 1 位读写方向”。有些数据手册直接把那整个 byte 写成地址（所以同一颗会出现“写 0xD0、读 0xD1”两个数字），有些只写 7 位（0x68）。三格并排是为了不管手册用哪一种写法，你都可以直接照抄。

② Offset：宽度与起始地址

控件类型范围／选项说明
宽度（byte）文本输入＋下拉下拉 0 / 1 / 2 / 4（默认 2）；手动可填 3地址相位要发几个 byte，高位在前。填 5 以上会在发出前被拦下。
起始 offset文本输入0 – 该宽度能表示的上限从哪个地址开始读／写。纯数字当十六进制；要用十进制就加 d（如 80d）或加 # 前缀（如 #80）。
宽度类型地址相位这一格的意思
0byte没有地址相位“起始 offset”那一格不再是地址，而是要发出去的那 1 个 byte（标签会跟着改成“写入值（1 byte）”）。读取则是从头读，表格的行标头印的是索引（#0…）而不是地址。
1byte1 byte0x00 – 0xFF
2byte2 byte（默认）0x0000 – 0xFFFF
3byte3 byte（24 位）不在下拉里，手动输入 3 才有。对面的 I2C Bridge 太旧时，小字会先告诉你它不吃。
4byte4 byte0x00000000 – 0xFFFFFFFF

③ 总 byte 数

控件类型范围／选项说明
总 byte 数文本输入＋下拉1 – 262144（256K）；下拉常用值 4096 / 8192只管读取。下方小字印出会分成几页、会切成几则传送。
这一栏不是写入的前提 写入要写多少，由表格上那份数据自己决定（或你选取了哪几格），跟这一栏完全无关。曾经有一版把两者绑在一起，结果“读 256 之后载入 8192 的文件”按钮直接锁死 —— 那是错的，现在两件事分开。

5读取，与 A／B 两份数据

按“读取”把数据抓回来摊在 16×16 表格上。这一节最重要的是 A 与 B 到底是什么 —— 搞清楚它，画面上其他东西都会跟着合理。

A 与 B

  • A ＝ 比较基准（快照）。它是一份独立的副本，只有在“重建 A”的时候才会变。
  • B ＝ 现在手上这一份，也就是表格上显示、按下写入会被写出去的那一份。
  • 两份都有内容时，点 A 或 B 那一行就切换看哪一份；看 A 的时候是只读的（它是基准，不该被改）。
发生什么事类型AB ／ 来源标签
第一次读取状态← 读到的清空；A 的来源标成“读取 slave 0x·· · 0x···· 起”
第一次载入文件状态← 文件清空；A 的来源就是文件名
已有 A，再载入文件（长度相同）状态不动← 文件；B 的来源是文件名
已有 A，再读取（长度相同）状态不动← 读到的；B 的来源是“读取”
改了任何一格状态不动← 改完的内容；B 的来源是“A 的修改”
按“快照 A”按钮← 当前内容清空，差异列表归零；A 继承当前的来源
长度不一样（读取或载入都一样）状态← 后者清空；旧的来源标签消失
换 slave ＋ 读取状态← 新读到的清空
两条容易误会的规则 ①“换 slave”本身不会清掉 A —— 要换了而且读取才会。你可能只是切过去看看。
② 只要 A 被重建，B 就自动清空。A、B 是一组，不会出现“新的 A 配旧的 B”这种比不了的状态。

读取相关的控件

控件类型范围／选项说明
读取按钮—依 ①②③ 的参数抓数据。长读取有进度与中止按钮；中止会停在下一个分段边界，并报告读到哪里。
快照 A按钮—把当前内容存成 A 当比较基准。副作用写在提示里：B 会被清空、差异列表归零。
另存为按钮＋下拉.hex / .bin / .txt / .rom读多少存多少。.hex 是 Intel HEX（每行 16 byte）。不需要连接，读完拔线也能存。
载入文件按钮.bin .hex .txt .rom .ihx .ihex .eep .dat .raw自动识别格式：Intel HEX、带地址的 hex dump、纯 hex 文本、raw binary。Intel HEX 的地址跳跃处会补 0xFF 并在记录里说补了几个。
清空按钮—回到“完全没有数据”的状态。连接与参数保留，可以接着做下一轮比对。
页码（0x ▢▢▢ 00）文本输入＋上下键—256 byte 一页。最左的 0x 与最右的 00 是固定的，只有中间可以填。
跳到（表格左上角）文本输入—页内任意地址定位并画十字。地址不在当前页时会先自动翻页。
整片读回来都是 0xFF 的意思 I2C 总线空闲时就是高电平。整片 FF 通常代表没有人响应，而不是“数据真的是 FF”。先确认 slave 地址、板子有没有供电、工装有没有接好。另外，如果读回来的内容每 N byte 完整重复一次，那通常是超过设备容量、地址回卷到 0 —— 顺序读不会报错，只会一直重复，所以这一页会主动提醒。

6编辑、选取与搜索

表格不只是拿来看的。每一格都可以就地改值；已连接时改一格就是真的写一格（而且会立刻回读验证），未连接时只改本地并标成“尚未写入”。

一格三层

每一格最多有三个数字：中间的大字是主值（按下写入会被写进去的那一个），左上角小字是快照值 A，右上角小字是被换出去的值 B。左上与右上绝不会同时出现：

状态类型主值角落
状态 1（改过值之后）状态B（新值）左上 ＝ A（快照值）；右上空
状态 2（点了左上之后）状态A（快照值）左上空；右上 ＝ B（被换出去的新值）
A 与 B 相等状态那个值两角都空（没有可切换的东西）
点角落也会真的写进设备 在已连接、而且这一格不是“改过还没写”的状态下，点角落还原＝真的要改设备 ⇒ 会发出写入并回读验证。如果那一格的改动本来就没发出去过，点角落只动本地、不发任何传输。

编辑一格

操作类型按键会发生什么
进入编辑鼠标单击一格选中＋画十字＋直接进入编辑。
输入键盘十六进制字符只显示、不生效；凑满两位也不会自动发出。输满两位再输会往左移位（像计算器）。
生效键盘／鼠标Enter，或离开这一格只输一位当作高位补 0（A ⇒ 0A）。已连接 ⇒ 写入＋回读；未连接 ⇒ 只改本地并标示尚未写入。
放弃键盘Esc值恢复原状。
位（bit 7–0）复选框—侧栏会列出所点那一格的 8 个位，勾／取消就直接改值，走的是与手动改格完全同一条路径（同样会写入、同样会回读验证）。
offset 宽度 0 时不能逐格写 没有地址相位就没办法指定要写哪一格。这个模式下请改用上方的“写入数据”栏。

选取要写哪些格子

操作类型按键会发生什么
连续选取鼠标／键盘Shift ＋ 点击，或 Shift ＋ 方向键选的是线性地址区间（不是矩形）。在 0x00 点一下再按 Shift＋下，选到的是 0x00 一直到 0x10 共 17 格。
跳跃选取鼠标Ctrl ＋ 点击可以挑不相邻的格子，而且支持跨页。再 Ctrl＋点同一格就是取消那一格。
取消选取鼠标普通单击任一格跳跃选取整个清掉。
选取列表只读显示—侧栏最上面逐段列出选了哪些地址：连续段印起止，跳跃选取每一段一行。标题行同时印总 byte 数与段数。
跳跃选取会逐段重下地址 不相邻的区段之间，地址没办法靠自动递增走过去。所以每一段都会各自重下一次 slave address ＋ offset —— 写入是这样，写完的回读验证也是这样。按钮上会直接写出“写入 选取的 N byte · M 段”，操作记录里也会逐段列出。

搜索

控件类型范围／选项说明
搜索输入框文本输入—找连在一起的那几个 byte。输入格式与“写入数据”同一支解析器：61 41 B4、0x61,0x41、A1h、6141B4 都吃。半个 byte 一律拒绝，不臆测。
全部范围 / 本页单选钮二选一“本页”的定义是整段都要落在本页 256 byte 之内；跨页的命中留给“全部范围”，这样同一条才不会被数两次。
▲ / ▼按钮—上一条／下一条，两端都循环。跨页的命中会自动翻页并画十字。

7写入、EEPROM 与验证

按钮上永远写着这一下会写哪一份、多少 byte。写完自动回读同一段、逐 byte 比对，结果放在画面最上面。

写入来源：以中心值为准

写出去的是表格上每一格的主值（中间那个大字），不是“总 byte 数”那一栏、也不是原始文件。优先顺序：

有选取 ⇒ 只写选取的那几格

按钮上写“写入 选取的 N byte”；多段时再加上“· M 段”。

没有选取 ⇒ 写当前显示的那一整份

按钮上写“写入 A／B · N byte”。按钮里不放文件名（文件名在 A／B 那两行，放两次只是重复，而且长文件名会把按钮撑爆）。

offset 宽度 0 ⇒ 只写 ③ 的那 1 byte

没有地址相位，这是这个模式下唯一能写的东西。

EEPROM：page 与段间距

控件类型范围／选项说明
Page 大小下拉8 / 16 / 32 / 64 / 128 / 256 B，或“不分段”EEPROM 的 page write 有硬件上限，跨页的连续写会在页内回卷，结果是静默写错。选小一定安全（只是慢），选大才会出事。
目标段间距文本输入毫秒；默认 5这是总线上量得到的段与段之间的距离，不是“额外睡多久”。固定开销由 I2C Bridge 自己每段量、自己扣掉。
段间距是设备的规格，不是可以随便调小的参数 EEPROM 收到一段数据之后要花时间把它真正写进存储（tWR，内部写入周期）。这段期间它不响应。等不够就会静默写不进去 —— 不会有错误、不会有提示，回读才会发现。填低于 5 ms 时画面会标红提醒；常见的 24C32／24C64 是 5 ms，较旧的 AT24C32 要 10 ms。
slave 落在 0x50–0x57 时会先问型号 那八个地址是 I2C EEPROM 的惯例地址。写之前会弹一个窗口请你选型号（不是 page size）—— 因为你知道手上这颗是 24C32，但不见得记得它的 page 是几 byte。选了型号，page 由系统填，不可能选错。同一个 slave 只问一次；重新连接或这次要写的范围超过已确认的容量时会再问。

写完的回读验证

  • 写完自动回读同一段，逐 byte 比对。跳跃选取则逐区段回读，每段各自重下地址。
  • 完全一致 ⇒ 绿底一行“写入与回读完全一致：验证 N byte，全部相同”。
  • 有不一致 ⇒ 红底列出几个 byte 不同，前几条直接印出“地址：写 0x·· 、读回 0x··”，其余在下方的操作记录里；表格上那些格子会标红。
  • 读不回来 ⇒ 明讲“无法确认有没有烧进去”，不会假装成功。
  • 写到一半失败或中止 ⇒ 会讲清楚哪一段地址已经写进去、哪一段之后完全没写，也就是设备上现在是一份半更新的内容。

差异列表与总和校验码

控件类型范围／选项说明
差异（地址 / Data A / Data B）只读显示—只列有差异的地址，相同的不列。点一行会跳到 dump 的对应地址并画十字 —— 它只定位、不改值，改值请在 dump 上做。
重新比较按钮—用当前的 A 与 B 重新比一次。两份不可比（长度／slave／offset 不同）时会讲出来。
checksum（A 行／B 行各一）只读显示—把整份数据的每一个 byte 相加，不取模、不截断，十六进制显示，位数依实际值自然增长。算的是中心值（也就是会被写出去的那一份），任何一格一改就立刻重算。
耗时记录只读显示—每一次读写的 byte 数、总耗时、走的路径与结论。同一次操作的几条会框成一组，方便前后比较。
操作记录只读显示—每一笔读写的 slave、offset 宽度、地址与 byte 都完整记着。可以一键复制整份。
checksum 为什么不截断 有些工具会把总和取 16 位（% 0x10000）。这一页刻意不这么做：文件大到 256K byte 时，加到多少就是多少。实测用两个文件名本身就带着总和的真实文件交叉验证过，截断的话那两个值就对不上文件名了。

8常见问题

点问题展开答案。

一直“连不到 I2C Bridge”，可是我明明开着它▼

三种可能，依序排除：① 浏览器的“允许访问本地网络”被拒了 —— 这一页分得出来，那一种会另外显示一句“请点允许”与重试按钮；② 黑窗口最后一行不是 G，代表它自己没起来，留下 i2c-bridge.log；③ 四个文件没放在同一个文件夹。

读回来整片都是 FF▼

那通常不是数据，是没有人响应（总线空闲就是高电平）。先确认 slave 地址对不对、板子有没有供电、工装有没有接好。想快速确认整条路通不通，可以在诊断模式下按“自检（黄金向量）”。

写了但是没写进去，也没有任何错误▼

写 EEPROM 时这几乎都是段间距太短：设备还在做内部写入就收到下一段，它不响应，而连续写不会报错。把“目标段间距”拉到 5 ms 以上（旧款 10 ms），Page 大小也不要选得比实际大。回读验证就是为了当场抓到这件事。

我填 350 kHz，小字却说 352.94▼

正常。频率是用两次整数除法换算的（divisor = (12000 / kHz) / 2 − 1），不整除的值会被默默算歪。小字印的是实际会得到的频率；要刚好就挑能整除的值（50 / 100 / 200 / 400 / 1000）。

差异列表突然变成 0，可是数据明明不一样▼

代表两份不可比（长度、slave 或起始 offset 不同），这时后来那一份会成为新的 A，比对停用。操作记录里会有一行说明为什么。要重新建立基准就按“快照 A”。

表格上的格子点不动、改不了值▼

三种情形：① 当前显示的是 A（基准），它是只读的 —— 点下面那一行切回 B；② offset 宽度是 0，没有地址相位就没办法逐格写；③ 正在跑一次 I2C 传输（忙碌中）。未连接不会挡你编辑，那是刻意的：离线先把值编好，连接之后一次写进去。

读回来的内容每隔一段就完整重复一次▼

通常是读过了设备的容量，地址回卷到 0 又从头读一次。顺序读不会报错，只会一直重复，所以这一页检测到周期就会主动讲一句。把总 byte 数调到实际容量以内即可。

另一个标签页把工装抢走了▼

同一时间只有一个页面握着工装。切到哪一页，哪一页就自动接管，不必按任何东西 —— 但对方正在测量时不会被抢走，那时画面会讲“等它跑完就能用”。

切了语言，可是操作记录里旧的那几行没有跟着变▼

刻意的。操作记录是带时间戳的流水记录，每一行记的是“那一刻发生了什么”，所以它保留当下的语言；切语言之后新产生的每一行都会是新语言。画面上其他所有东西（按钮、字段、提示、横幅、耗时记录、A／B 两行）都会立刻跟着换。
