I2C Read / Write Test

Read and write any slave and offset through the local I2C Bridge; view, edit and compare in a 16×16 table — the complete user guide.

Web tool · requires the local I2C Bridge · desktop browser

1Overview

This is an I2C read/write tool that assumes nothing about what is on the other end: any slave address, any offset, any length. What comes back is laid out as a 16×16 table where you can edit values in place, compare byte by byte against another copy, and write it back with an automatic read-back verification.

What it is for

  • See the whole thing — up to 262,144 bytes (256K) in one read, paged 256 bytes at a time.
  • See what changed — two copies (A and B) are held at once, differing cells are coloured, and the difference list spells out “address / Data A / Data B”.
  • No guessing after a write — the same range is read back automatically and compared byte by byte; mismatching cells turn red and their addresses are listed.
  • It does not get in your way — no address allowlist, no “enable writing” switch. Every read and write is recorded in full, both on screen and in the I2C Bridge log file.

What it does not do

  • It does not identify the device for you — apart from the EEPROM capacity confirmation, it does not guess part numbers or apply register definitions.
  • It never writes on its own — nothing is written unless you press Write or edit a cell in place while connected.
  • It does not remember your data — close the tab and the dump is gone. Use “Save as” to keep it.
Why the browser cannot reach the adapter A USB-to-I2C adapter is bound at the driver level; a browser has no path to it at all. So this page works together with a small program running on your PC (the I2C Bridge) that drives the adapter, and the page talks to it over a local WebSocket.

2Getting and starting the I2C Bridge

When the page cannot reach it, the first thing you see is the download button, with the version printed on the button itself.

Download

Press “⬇ Download I2C Bridge version”. A three-line instruction window appears; just follow it.

Unzip everything into one folder

The package contains four files: i2c-bridge.exe, libMPSSE.dll, ftd2xx.dll, DLL_I2C_BCB.dll. All four must sit in the same folder; it will not start if one is missing.

Double-click i2c-bridge.exe

Windows blocks it the first time (any change to the program changes its hash, so it is blocked again after every update). Leave the console window open — that is the channel.

Come back to this page

The page tries to connect by itself, so usually there is nothing to press. If it does not connect, press “Connect”.

The last line in the console window is a single capital letter G means everything is fine. When it is not G, keep the whole i2c-bridge.log; what the letter means is looked up by whoever maintains the tool — this page deliberately does not print the lookup table at you.

Clock: the integer-division pitfall

The adapter side converts the frequency with two integer divisions:

divisor = (12000 / kHz) / 2 − 1　(both divisions truncate) The actual frequency is therefore 12000 / (2 × (divisor + 1)) kHz. It does not validate the input and has no table of allowed steps: it accepts any value, and a value that does not divide evenly is silently turned into something else.
What you typeTypedivisorActual frequency
400kHz14400 kHz　✔ divides evenly
350kHz16352.94 kHz　← not the number you typed
100kHz59100 kHz　✔

That is why the small text always works out the real value for you, and marks it red when it differs from what you typed. That is more use than any warning.

Only one page holds the adapter at a time Whichever page you switch to takes over automatically, with nothing to press. It will not be taken away while the other page is measuring. To hand the adapter back to another program, switch the connection toggle off.

4Read / write parameters (shared)

Reading and writing share the same slave address, offset width and start offset. Four groups, left to right: ① Slave address　② Offset　③ Total bytes　④ To device.

① Slave address: 7-bit and 8-bit

The three fields are three notations for the same address; change any one and the other two follow immediately.

ControlTypeRange / optionsNotes
7-bit (actually sent)text input + dropdown0x00–0x7F; dropdown 0x68 / 0x50 / 0x3E / 0x7C / 0x7DThis is the value that really goes onto the bus, which is why it is the highlighted field.
8-bit writetext input0x00–0xFF, even= 7-bit << 1. Typing an odd number corrects it on the spot and shows the corrected value — nothing is swapped behind your back.
8-bit readtext input0x00–0xFF, odd= (7-bit << 1) | 1. Typing an even number sets the low bit and shows the corrected value.
Why there are two notations The first byte on an I2C bus is “7 address bits plus one read/write bit”. Some datasheets write that whole byte as the address (so the same part appears as “write 0xD0, read 0xD1”), others write only the 7 bits (0x68). Having all three side by side means you can copy whichever notation your datasheet uses.

5Reading, and the two copies A and B

Press “Read” to pull the data into the 16×16 table. The important part of this section is what A and B actually are — once that is clear, everything else on screen makes sense.

A and B

  • A is the reference (the snapshot). It is an independent copy and only changes when A is rebuilt.
  • B is the copy you have now — what the table shows, and what a write sends out.
  • When both exist, clicking the A or B row switches which one you are looking at. While viewing A the table is read-only (it is the reference; it should not be edited).

Two rules that are easy to misread ① Changing the slave does not by itself clear A — you have to change it and read. You might just be switching over to have a look.
② Whenever A is rebuilt, B is cleared automatically. A and B are a pair; there is never a “new A with an old B”, which could not be compared anyway.

What it means when everything reads back as 0xFF An idle I2C bus sits high. All FF usually means nobody answered, not “the data really is FF”. Check the slave address, whether the board is powered, and whether the adapter is properly connected. Also: if the data repeats exactly every N bytes, you have probably read past the device capacity and the address wrapped to 0 — a sequential read does not error, it just repeats, so this page points it out.

6Editing, selecting and searching

The table is not just for looking at. Every cell can be edited in place; while connected, editing a cell really writes that cell (and immediately reads it back to verify). While not connected it only changes the local copy and marks it as “not written yet”.

Three values per cell

A cell holds up to three numbers: the large one in the middle is the main value (what a write would send), the small one at the top left is snapshot value A, and the one at the top right is the value that was swapped out, B. Top-left and top-right never appear at the same time:

State 1 (after editing)stateB (the new value)top-left = A (snapshot); top-right empty
State 2 (after clicking the top-left)stateA (snapshot)top-left empty; top-right = B (the new value)
A equals Bstatethat valueboth corners empty (there is nothing to switch to)
Clicking a corner also really writes to the device While connected, and when that cell is not in the “edited but not written” state, restoring it means genuinely changing the device — so a write is sent and read back. If the edit on that cell was never sent in the first place, clicking a corner only changes the local copy and sends nothing.

7Writing, EEPROM and verification

The button always says which copy this press writes, and how many bytes. After the write, the same range is read back and compared byte by byte, with the result at the top of the page.

What gets written: the main values

What goes out is the main value of each cell in the table (the large digit), not the “Total bytes” field and not the original file. In order of priority:

Something selected ⇒ only those cells

The button says “Write N selected bytes”, plus “· M segments” when the selection is in several runs.

Nothing selected ⇒ the whole copy being shown

The button says “Write A/B · N bytes”. No file name on the button — the file name is already on the A/B rows, and a long one would stretch the button out of shape.

Offset width 0 ⇒ only the single byte in ③

Without an address phase that is the only thing that can be written in this mode.

EEPROM: page size and segment gap

ControlTypeRange / optionsNotes
Page sizedropdown8 / 16 / 32 / 64 / 128 / 256 B, or “No paging”An EEPROM page write has a hardware limit, and a continuous write that crosses a page wraps around inside that page — silently writing the wrong thing. Choosing a smaller value is always safe (just slower); only a larger one causes damage.
Target segment gaptext inputmilliseconds; default 5This is the gap you can measure on the bus between segments, not “how much extra to sleep”. The fixed overhead is measured per segment by the I2C Bridge and subtracted by it.
The gap is a device specification, not a knob to turn down After receiving a segment, an EEPROM needs time to commit it to memory (tWR, the internal write cycle). During that time it does not respond. Not waiting long enough means the data silently fails to program — no error, no warning; you only find out on read-back. Values below 5 ms are marked red. The common 24C32/24C64 need 5 ms; older AT24C32 parts need 10 ms.
A slave in 0x50–0x57 asks for the part first Those eight addresses are the conventional ones for I2C EEPROMs. Before writing, a window asks you to pick the part — not the page size — because you know the part in your hand is a 24C32, but you may not remember its page size. Pick the part and the page size is filled in for you, so it cannot be wrong. Each slave is asked once; it asks again after reconnecting, or when the range about to be written exceeds the capacity already confirmed.

Read-back verification

  • After the write the same range is read back automatically and compared byte by byte. A non-adjacent selection is read back run by run, each re-issuing its address.
  • All identical ⇒ a green line: “Write and read-back match exactly: N bytes verified, all identical.”
  • Any mismatch ⇒ a red line with how many bytes differ; the first few are printed as “address: wrote 0x··, read back 0x··” and the rest go to the activity log. Those cells turn red in the table.
  • Cannot be read back ⇒ it says plainly that it cannot confirm whether the data was programmed. It never pretends to have succeeded.
  • Failed or aborted part-way ⇒ it spells out which addresses were written and which were not, i.e. that the device now holds half-updated contents.

Why the checksum is not truncated Some tools take the sum modulo 16 bits (% 0x10000). This page deliberately does not: with a file as large as 256K bytes, whatever it adds up to is what it shows. This was cross-checked against real files whose names already carry the checksum computed by another tool — truncating would have made those two values disagree with their own file names.

8FAQ

Click a question to expand the answer.

It keeps saying “Cannot reach I2C Bridge”, but I have it running▼

Three possibilities, in order: ① the browser’s “allow local network access” was denied — this page can tell that case apart and shows a separate line asking you to allow it, plus a retry button; ② the last line in the console window is not G, meaning it did not start properly — keep i2c-bridge.log; ③ the four files are not all in the same folder.

Everything reads back as FF▼

That is usually not data — it is nobody answering (an idle bus sits high). Check the slave address, whether the board is powered, and whether the adapter is connected. To check the whole path quickly, use “Self-test (golden vector)” in diagnostic mode.

The write went through but nothing was stored, and there was no error▼

On an EEPROM this is almost always too short a segment gap: the device is still committing the previous segment when the next one arrives, so it does not respond — and a continuous write does not report that. Raise “Target segment gap” to 5 ms or more (10 ms for older parts) and do not pick a page size larger than the real one. Read-back verification exists to catch exactly this.

I typed 350 kHz but the small text says 352.94▼

That is correct. The frequency is derived with two integer divisions (divisor = (12000 / kHz) / 2 − 1), so a value that does not divide evenly is silently turned into something else. The small text prints what you will actually get; to land exactly, pick a value that divides evenly (50 / 100 / 200 / 400 / 1000).

The difference list suddenly shows 0, but the data clearly differs▼

That means the two copies cannot be compared (different length, slave or start offset). In that case the newer one becomes the new A and diffing is disabled. The activity log has a line explaining why. Press “Snapshot A” to establish a reference again.

Cells in the table will not respond or will not take a new value▼

Three cases: ① you are viewing A (the reference), which is read-only — click the row below to switch back to B; ② the offset width is 0, and without an address phase there is no per-cell write; ③ an I2C transfer is in progress. Being disconnected does not stop you editing — that is deliberate: prepare the values offline, then write them in one go once connected.

The data read back repeats itself every so often▼

Usually you have read past the device capacity: the address wrapped to 0 and it started over. A sequential read does not error, it just repeats, so this page mentions it as soon as it detects a period. Reduce the total byte count to within the real capacity.

Another tab took the adapter away from me▼

Only one page holds the adapter at a time. Whichever page you switch to takes over automatically, with nothing to press — except while the other page is measuring, when it will not be taken, and the screen says so.

I switched language but the older lines in the activity log did not change▼

That is deliberate. The activity log is a timestamped transcript: each line records what happened at that moment, so it keeps the language it was written in. Every line produced after the switch is in the new language. Everything else on screen (buttons, fields, hints, banners, the timing log, the A/B rows) changes immediately.
