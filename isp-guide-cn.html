1工具简介

把 iSP 接口上「应该长什么样」的差分信号波形画出来，让你拿示波器上量到的画面直接比对。也可以反过来：把量到的 9 个 bit 敲进去，反推它是哪一个控制码或哪一阶灰阶。

它在做什么

  • 正推 — 设定模式与像素值，产生一整条 line 的位序列：BK、BAC、POL、数据、EOL，一段一段标上颜色与名称。
  • 反推 — 输入 9-bit 波形，比对出 Command、DLL Data、PLL Data 三种可能的解释。
  • 所有编码都是 8B9B：8 个 bit 的数据编成 9 个 bit 送出，DLL 与 PLL 两张对照表各一份。

先弄清楚三件事

  • 位顺序是 LSB-first：波形最左边是 b0，最右边是 b8。看规格书上的十六进制值时要记得反过来对。
  • DLL 与 PLL 只差在 BK：控制码里只有 BK 两种编码不同，其余 BAC／POL／SET／EOL 完全相同；数据则是两张完全不同的 LUT。
  • 没有计算按钮：任何设定一改，波形立刻重画。

2快速开始

对齐模式

先把「模式设定」四项调成与实际 IC 一致：Source Driver Bits、Pair 数、Data Zone 编码、BK Zone 编码。编码选错，画出来的位序列会整条不同。

设定要送的像素

用「纯色画面」最单纯：R/G/B 各给一个灰阶，Pixel 数量先设 2–4，波形短一点好对照。

看波形与 Frame 信息

波形上方会列出整条 line 的段落顺序（BK BAC POL+ R1 G1 B1 … EOL）与总 bit 数。每一段都有颜色与名称标示。

放大比对

用 H-Zoom 的 +／− 放大到看得见单一 bit，或按全屏。下方 Overview 点一下可跳到该位置。

反过来查

示波器上量到一段不认识的 9-bit？滚动到最下方的「波形反推」，用搜索框输入名称、或直接勾 b0–b8，三行结果立刻告诉你它是什么。

3模式设定

六项设定决定「同样的像素值会被编成什么位」。→ 直接打开工具的这张卡

控件类型选项／默认说明
Source Driver Bits单选钮6 / 8（默认）bits决定数据段怎么组。8-bit：每个 pixel 直接送 R、G、B 三个 byte。6-bit：每个 pixel 是 18 bits（R/G/B 各 6），串起来后每 8 bits 重新切成一个 byte 再编码，所以段落标签会出现 R1+G1 这种跨字段的名称。
Pair 数单选钮1 pair（默认）/ 2 pair2 pair 时画面会出现上下两条波形（Pair 0／Pair 1），像素数据依 3 个 slot 为一循环分配到两条上（见第 4 章的说明）。
Data Zone 编码单选钮DLL-based（默认）/ PLL-based数据段用哪一张 8B9B 对照表。两张表是完全不同的映射，同一个灰阶编出来的 9-bit 不一样。
BK Zone 编码单选钮DLL-based（默认）/ PLL-based只影响 BK 这一个控制码。PLL 版的 BK 是类似时钟的交替样式（供 PLL 锁相用），DLL 版则是另一种固定样式。其余控制码两者相同。
Scrambler单选钮Off（默认）/ On开启后数据在编码前先与 LFSR 产生的 key 做 XOR（打散连续相同值，降低 EMI）。开启时波形上的数据段会标记为已加扰。
初始 Key文本输入16-bit 十六进制，默认 FFFF只有 Scrambler 选 On 时才出现。要和 IC 端的初始值一致，波形才对得起来。
BKPOL单选钮ON（默认）/ OFF开启后在 frame 末端加入 VBK 段：BK · BAC · BKPOL± · BK。这一段接在 EOL 之后、本身不带 EOL。点波形上的 BKPOL 色块可直接切换正／负。
Scrambler 的运作方式 16-bit LFSR（Galois form，多项式 x¹⁶+x⁵+x⁴+x³+1），每送完一个 pixel 推进一次；每个 byte 的第 i 个 bit 与 key 的对应 bit 做 XOR 之后才进 8B9B 编码。所以 Scrambler 开与关，同一个灰阶画出来的波形完全不同——比对不上时先确认这一项。

控制码一览（9-bit，LSB-first）

下表的位由左至右就是波形上由左至右的顺序。

控制码b0…b8用途
BK（DLL）1 0 0 0 0 1 1 1 1Blanking 填充码，DLL 版本。
BK（PLL）0 0 1 0 1 0 1 0 1Blanking 填充码，PLL 版本，样式像时钟，方便 PLL 锁相。
BAC0 1 1 1 1 0 0 0 0命令起始码，后面接的才是真正的命令。
POL+0 1 1 0 0 1 1 1 1本行极性为正。
POL−1 0 0 1 1 0 0 0 0本行极性为负。
SET1 0 0 0 0 0 0 1 1Setting line 的识别码，其后接 REG 数据。
EOL0 1 1 1 1 1 1 0 0一条 line 的结束。
BKPOL+0 1 1 1 0 1 1 1 1VBK 段的极性命令（正）。
BKPOL−1 0 0 0 1 0 0 0 0VBK 段的极性命令（负）。
正负码互为反相 POL+ 与 POL−、BKPOL+ 与 BKPOL− 每个 bit 刚好相反。在示波器上分辨极性时，看第一个 bit 最快：0 开头是正、1 开头是负。

4像素设定

要送出去的画面内容。→ 直接打开工具的这张卡

三种像素模式

模式控件范围／默认用途
纯色画面R / G / B Gray Level（滑块＋数值＋色块）各 0–255；默认 R255 G128 B0默认模式。每个 pixel 都送同一组 RGB。要验证某一个特定灰阶的编码时用这个最直接。
递增起始灰阶 / Step / 重复 sub-pixel 数起始 0–255（默认 0）；Step 1–255（滑块到 64，默认 4）；重复 1–255（滑块到 48，默认 3）灰阶逐渐变大，达 255 后保持不变。用来一次看多个灰阶的编码差异，或做渐变测试图。
递减同上起始默认 255；其余同上灰阶逐渐变小，达 0 后保持不变。
Pixel 数量滑块＋数值1–255，默认 4三种模式共用。数量越多波形越长，比对细节时建议先调小。
「重复 sub-pixel 数」是什么 它决定连续几个 sub-pixel 用同一个灰阶之后才变化一次。设 3 时刚好是 R＝G＝B，也就是每个 pixel 换一次灰阶（灰阶渐变）；设 1 则是每个 sub-pixel 都不同（彩色渐变）。

2 pair 时数据怎么分配

两条 pair 各自是完整的一条 line（都有自己的 BK／BAC／POL／EOL），只有数据段被拆开。以每 2 个 pixel 为一个循环、共 3 个 slot：

SlotPair 0Pair 1
第 1 个R（第 1 个 pixel）G（第 1 个 pixel）
第 2 个B（第 1 个 pixel）R（第 2 个 pixel）
第 3 个G（第 2 个 pixel）B（第 2 个 pixel）

所以 Pair 1 不是「后半段像素」，而是与 Pair 0 交错的 sub-pixel。测量时把两条并排看才是完整数据。

5Frame 结构

控件

控件类型范围／默认说明
BAC 前 BK 数量滑块＋数值滑块 0–20，数值框可到 50；默认 2每一段命令前要垫几个 BK。Data line、Setting line、BKPOL 段三处都会各自套用同一个数量。

依设定，波形由上到下最多包含三段：

Data line：BK×n · BAC · POL± · 数据… · EOL · BK×m
↓
Setting line（可选）：BK×n · BAC · SET · REG0…REGn · EOL · BK×m

BKPOL 段没有 EOL 它是接在 EOL 之后的 VBK 命令，本身不再带 EOL。在示波器上看到 BAC 后面直接跟 BKPOL 再回到 BK，是正确的，不是漏掉了。

8波形反推（8-bit）

量到一段看不懂的 9-bit？把它敲进来，工具会同时比对控制码与两张数据表。→ 直接打开工具的这张卡

三种输入方式

方式操作说明
搜索波形名称文本输入输入 BK、BAC、BKPOL+、L0、L255… 从列表选一项，9 个 bit 会自动填好。控制码、DLL 灰阶、PLL 灰阶都在索引里，同名的会分别列出（例如 BK 有 DLL 与 PLL 两笔）。
勾选 b0–b8复选框波形下方九个复选框，勾起来代表该 bit 为 1。
直接点波形可点击在反推波形上点某一个 bit 的位置，即可切换它的 0／1，复选框会同步。

结果怎么读

字段内容说明
9-bit 值例如 0x10F (100001111)括号内是 LSB-first 的显示，与波形由左至右一致；括号外的十六进制则是一般的数值表示。
Command命中的控制码名称同时比对所有控制码与 PLL 版的 BK。命中多个会用 / 并列。没有命中显示 —。
DLL Data例如 L128 (0x80)用 DLL 表反查，得到的是灰阶值。
PLL Data例如 L64 (0x40)用 PLL 表反查。
三行同时有值是正常的 同一组 9-bit 可能既符合某个控制码、又落在某张数据表里。要判断它到底是什么，得看它在波形中的位置：BAC 后面的是命令，POL 之后到 EOL 之间的是数据。工具只负责告诉你「有哪些可能」。
为什么标「8-bit」 反推是以 byte ↔ 9-bit 的映射为基础，而这个映射与 6-bit／8-bit 模式无关（6-bit 的差别只在上游怎么打包成 byte）。所以在 6-bit 模式下这个工具一样能用，只是查出来的 Lx 是打包后的 byte 值而非某个颜色的灰阶。

9常见问题

点问题展开答案。

画出来的波形跟示波器上量到的对不起来？▼

依可能性排查：

  1. Data Zone 编码选错（DLL ↔ PLL）——数据段会整段不同，这是最常见的原因。
  2. Scrambler 状态不符，或初始 Key 与 IC 端不一致。
  3. BK Zone 编码选错——只有 BK 段会不同，其余正确。看到「只有 blanking 对不上」就是这一项。
  4. 位顺序看反了——本工具与示波器都是 LSB-first（b0 在最左），规格书上的十六进制要反过来对。
  5. Source Driver Bits 或 Pair 数与实际不符。
6-bit 模式下段落名称怎么变成 R1+G1 这种？▼

因为 6-bit 的数据不是以颜色为单位打包的。每个 pixel 是 18 bits（R/G/B 各 6），串接之后每 8 bits 切一个 byte 再做 8B9B——切点自然会落在颜色中间。所以一个 byte 可能同时装着 R1 的后半与 G1 的前半，标签就写成 R1+G1。这是正确的封装方式，不是显示错误。

2 pair 模式下，Pair 1 的数据为什么不是后半段？▼

iSP 的 2 pair 是交错而非切半。以 2 个 pixel 为一循环：Pair 0 送 R1、B1、G2，Pair 1 送 G1、R2、B2。两条要并排一起看才是完整画面。详见第 4 章的对照表。

波形太长看不清楚单一 bit？▼

三个做法：把 Pixel 数量调小（2–4 个就够看编码）、用 H-Zoom + 逐步放大（每次 1.4 倍，最大 12×），或按全屏再放大。要回到全貌按 Fit，要跳到特定位置点下方的 Overview。

REG 值填了，但波形上看不到我填的数字？▼

REG 数据一样要经过 8B9B 编码，波形上是编码后的 9-bit，不是原本的 byte。要确认编出来对不对，把该段的 9 个 bit 敲进「波形反推」，看 DLL／PLL Data 是不是你填的值。

怎么切换 POL 的正负？▼

不用去设定卡片找——直接点波形上的 POL 色块就会正负互换，BKPOL 色块同理，两者各自独立。切换后 Frame 信息列与整段位序列会立刻更新。
